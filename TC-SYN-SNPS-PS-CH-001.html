🧠 Knowledge Assessment

1. Why must PSRAM macro .db files be added to set_link_library but NOT to set_target_library?

  • DC cannot read PSRAM .db files directly; they must be specified separately from standard cell databases.
  • PSRAM macros are automatically included when the search_path directories are configured.
  • set_target_library contains only cells DC can map logic onto. PSRAM macros are fixed hard macros — DC uses their timing models for port timing analysis but cannot synthesise logic inside them.
  • PSRAM macros are only needed for place-and-route, not synthesis timing analysis.
Correct! set_target_library is the list of cells DC selects during technology mapping. PSRAM macros are hard IP blocks whose internal logic is fixed — DC only needs their timing models (in set_link_library) to analyse setup and hold timing at their ports.

2. The iguana_soc analyze command requires a different format flag than tile. What is it and why?

  • -format vhdl, because iguana_soc uses mixed Verilog/VHDL sources.
  • -format sverilog, because iguana_soc is written in SystemVerilog which has constructs (interfaces, packages, logic, always_ff) that the standard Verilog parser does not support.
  • -format db, because iguana_soc RTL is pre-compiled into a binary format.
  • -format verilog works for SystemVerilog too; no change is needed.
Correct! iguana_soc uses SystemVerilog. Passing -format sverilog to analyze enables the SystemVerilog parser so constructs like interface, package, logic, and always_ff are correctly recognised.

3. iguana_soc uses set_clock_groups -asynchronous in its SDC. What does this tell DC?

  • It disables all timing analysis for the design.
  • It sets clock uncertainty to zero for paths crossing clock domains.
  • It tells DC not to analyse timing paths that cross between the listed clock groups, since those paths are handled by CDC synchronisers in RTL and cannot meet normal setup/hold requirements.
  • It marks all six clocks as generated clocks derived from a single master clock.
Correct! Paths crossing asynchronous clock boundaries are intentionally not timed — they are handled by dedicated CDC synchronisers in RTL. Without set_clock_groups -asynchronous, DC would try to meet impossible inter-domain timing and report misleading violations.

4. In physical synthesis, what is the advantage of running check_timing after extract_physical_constraints but before compile_ultra -spg?

  • It forces DC to reload the TLU+ files after the DEF is loaded.
  • It writes the floorplan constraints to a report file for documentation.
  • It confirms that all clock domains are correctly constrained after the SDC is applied and before the hours-long SPG compilation begins, allowing you to catch missing constraints before wasting time on a bad run.
  • It is required by DC to validate that the DEF file matches the elaborated netlist.
Correct! SPG compilation takes several hours for a large design like iguana_soc. Running check_timing before starting lets you verify that all paths are constrained and all clock domains recognised. Catching a missing create_clock or set_clock_groups at this stage saves you from a wasted multi-hour run.
