📖 Theory and Background

What is Signoff STA and Why It Matters

Static timing analysis (STA) is performed at multiple stages of the physical design flow, but signoff STA is the final, most accurate timing verification step before a design is sent for fabrication. Unlike the timing analysis performed inside synthesis or place-and-route tools, signoff STA uses a dedicated, purpose-built timing engine that operates on the post-route netlist with extracted parasitics. The goal is to confirm that the design meets all timing constraints under every specified operating condition.

In-tool timing engines trade accuracy for speed so that designers can iterate quickly during optimization. Signoff STA tools like Tempus, on the other hand, prioritize accuracy. They use more detailed delay models, full-chip parasitic annotation, signal integrity analysis, and advanced variation modeling. A design that appears clean inside the PnR tool may still have violations when analyzed at signoff, making this step essential before tapeout.

The MMMC Framework

Modern designs must operate correctly across a wide range of conditions: different voltages, temperatures, process corners, and functional modes. The Multi-Mode Multi-Corner (MMMC) framework provides a structured way to define and analyze all of these scenarios simultaneously.

  • Library Sets: A collection of timing libraries (.lib files) that represent a specific process corner and operating condition (e.g., slow-slow at 0.81V/125C or fast-fast at 0.99V/-40C). Each library set groups the standard cell, IO, and macro libraries for one corner.
  • Timing Conditions: A pairing of a library set with specific operating parameters. Timing conditions define the electrical environment under which delays are calculated.
  • RC Corners: Extracted parasitic models representing different interconnect conditions (e.g., RC-worst for maximum wire delay, RC-best for minimum wire delay, C-worst for maximum coupling capacitance). Each RC corner corresponds to a different SPEF file or set of extraction parameters.
  • Delay Corners: A combination of a timing condition (library set) with an RC corner. The delay corner fully specifies the cell delay model and the interconnect delay model used for a given analysis.
  • Analysis Views: The top-level construct that combines a delay corner with a constraint mode (the SDC file defining clocks, exceptions, and constraints). Each analysis view represents one complete timing scenario. For signoff, you typically define views for worst-case setup (slow corner, RC-worst) and worst-case hold (fast corner, RC-best), along with additional views for different functional modes.

SPEF Annotation and Accurate Delay Calculation

After place and route, a parasitic extraction tool generates SPEF files that capture the resistance and capacitance of every net in the design. During signoff STA, these SPEF files are annotated (back-annotated) onto the design netlist so that the timing engine can compute accurate interconnect delays instead of relying on estimates.

Each RC corner typically has its own SPEF file, extracted under different assumptions about metal thickness, dielectric constant, and wire width variation. Annotating the correct SPEF file for each delay corner is critical: using RC-worst parasitics with a slow library set produces the most pessimistic setup analysis, while using RC-best parasitics with a fast library set produces the most pessimistic hold analysis. Incorrect SPEF-to-corner mapping is one of the most common signoff STA setup errors and can lead to missed violations or false failures.

Signal Integrity: Crosstalk Delay, Glitch, and Double Clocking

As process geometries shrink, the coupling capacitance between adjacent wires becomes a significant fraction of the total net capacitance. Signal integrity (SI) analysis models the effects of this coupling on timing and functionality.

  • Crosstalk Delay: When an aggressor net switches while a victim net is also transitioning, the coupling can either speed up or slow down the victim transition. SI-aware STA adds these crosstalk-induced delay changes to the path delays, which can push previously clean paths into violation.
  • Glitch Analysis: When a victim net is stable (not switching) and an aggressor net transitions, the coupling can induce a voltage glitch on the victim. If the glitch amplitude is large enough relative to the noise margin, it can cause a logic error. Glitch reports identify nets at risk and classify them by severity.
  • Double Clocking: A specific type of glitch that occurs on clock nets, where a noise-induced glitch creates a false clock edge. This can cause a flip-flop to capture data at the wrong time, leading to functional failures that are extremely difficult to debug in silicon.
SI Timing Impact: Crosstalk can add or subtract delay from a signal path. In the worst case, an aggressor switching in the opposite direction to the victim adds delay (pessimistic for setup analysis), while an aggressor switching in the same direction subtracts delay (pessimistic for hold analysis). Signoff STA must account for both scenarios.
Glitch Severity Levels: Glitch reports typically classify violations by the ratio of glitch height to noise margin. A glitch that exceeds the noise margin threshold may propagate through downstream logic and cause functional errors, making it a signoff-blocking issue that must be fixed before tapeout.

OCV, AOCV, and CPPR at Signoff

On-chip variation (OCV) accounts for the fact that identically designed transistors and wires do not behave identically across the die. Process, voltage, and temperature gradients cause cells in one region to be faster or slower than cells in another region. At signoff, OCV derating is applied to model this variation: the launch path and capture path of a timing check are derated differently to represent the worst-case mismatch.

Advanced OCV (AOCV) improves on flat OCV derating by making the derate factors depend on path depth and physical distance. Longer paths with more stages see less variation (statistical averaging), so AOCV applies smaller derates to deep paths and larger derates to shallow paths, producing more realistic results.

Clock Path Pessimism Removal (CPPR) corrects an artifact of OCV analysis. When OCV derates are applied, the common portion of the clock tree shared by both the launch and capture flip-flops gets derated in opposite directions, creating artificial pessimism. CPPR identifies this common clock path and removes the conflicting derates, recovering timing margin that would otherwise be wasted.

Clock Propagation vs. Ideal Clocks at Signoff

During early design stages, clocks are often modeled as ideal: every flip-flop receives the clock edge at exactly the same time (zero skew, zero latency). This simplification speeds up analysis but does not reflect reality. At signoff, clocks must be propagated through the actual clock tree so that the real insertion delay, skew, and clock tree parasitics are included in the timing analysis.

Propagated clocks reveal issues that ideal clocks hide: clock skew between related flip-flops can cause hold violations, long clock tree insertion delays reduce the effective time available for data paths, and clock reconvergence pessimism can mask true timing margins. Signoff STA with ideal clocks is meaningless because it does not reflect the actual silicon behavior. The constraint files (SDC) used at signoff must define clocks as propagated, and the clock tree must be fully built and extracted before signoff analysis can begin.

📝 Knowledge Assessment Quiz

Question 1: Why is signoff STA performed separately from the timing analysis inside PnR tools?

  • A. PnR tools cannot read SDC constraint files
  • B. Signoff STA uses a different netlist format that PnR tools cannot generate
  • C. Signoff STA tools prioritize accuracy over speed, using more detailed delay models and full parasitic annotation
  • D. PnR tools do not support multi-corner analysis

Correct! In-tool timing engines trade accuracy for speed to enable fast design iterations, while signoff STA tools like Tempus use more detailed models, full parasitic annotation, and SI analysis to provide the most accurate timing picture before tapeout.

Question 2: In the MMMC framework, what does a delay corner combine?

  • A. A constraint mode and an analysis view
  • B. A timing condition (library set) and an RC corner
  • C. Two different SPEF files for min and max analysis
  • D. A clock definition and a set of timing exceptions

Correct! A delay corner pairs a timing condition (which specifies the cell delay model via a library set) with an RC corner (which specifies the interconnect delay model via extracted parasitics), fully defining how delays are calculated for a given scenario.

Question 3: What is the purpose of Clock Path Pessimism Removal (CPPR)?

  • A. To remove clock skew from the timing analysis
  • B. To convert ideal clocks into propagated clocks
  • C. To reduce the number of analysis views required for signoff
  • D. To remove artificial pessimism caused by conflicting OCV derates on the shared clock path

Correct! When OCV derates are applied, the common portion of the clock tree shared by launch and capture flip-flops gets derated in opposite directions, creating artificial pessimism. CPPR identifies this shared path and removes the conflicting derates to recover real timing margin.

Question 4: In signal integrity analysis, what is "double clocking"?

  • A. Using two clock domains in the same design
  • B. Applying both setup and hold checks to the same path
  • C. A crosstalk-induced glitch on a clock net that creates a false clock edge
  • D. Running the clock at twice the intended frequency due to duty cycle distortion

Correct! Double clocking occurs when crosstalk from an aggressor net induces a glitch on a clock net, creating a false clock edge that can cause flip-flops to capture data at the wrong time, leading to functional failures in silicon.
