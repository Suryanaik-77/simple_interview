📖 Theory and Background

What is Static Timing Analysis?

Static Timing Analysis (STA) is the process of verifying that a digital design meets all its timing requirements without running a simulation. Unlike dynamic simulation which requires input vectors, STA exhaustively checks every possible timing path in the design by computing signal arrival times and comparing them against required times.

STA is performed after place-and-route because only at that stage do we have the actual physical layout — real wire lengths, real cell placements, and extracted parasitic data (resistance and capacitance). PrimeTime uses this real parasitic data (provided as SPEF files) along with timing libraries to compute accurate path delays.

PVT Corners and Multi-Corner STA

Transistor and interconnect behavior varies with Process, Voltage, and Temperature (PVT). A design that meets timing at one PVT condition may fail at another. To ensure the chip works across all operating conditions, STA must be run at multiple PVT corners:

Why 4 corners? Setup violations occur when paths are too slow (slow process, low voltage, worst parasitics). Hold violations occur when paths are too fast (fast process, high voltage, best parasitics). Both must be checked at extreme temperatures (−40°C and 125°C). Each corner requires a matching pair: the correct timing library (.db) for that PVT condition AND the correct SPEF extracted at that RC condition. Using mismatched libraries and SPEFs gives inaccurate results.

SPEF and Parasitic Annotation

After place-and-route, a parasitic extraction tool (such as Cadence QRC or Synopsys StarRC) analyzes the physical layout — every routed metal wire, every via, every coupling between adjacent nets — and computes the resistance (R), grounded capacitance (C), and coupling capacitance (Cc) for each net segment. This data is written out in SPEF (Standard Parasitic Exchange Format).

When PrimeTime reads a SPEF file, it annotates these extracted parasitics onto the design netlist. This means every net in the gate-level netlist gets its real R and C values from the physical layout, replacing any wire-load model estimates. The annotated parasitics are then used by the timing engine to compute accurate net delays, transition times, and crosstalk effects.

Each PVT corner requires its own SPEF file because metal resistance and capacitance change with temperature and process variation. The extraction tool runs at different conditions (cworst, rcworst, cbest, rcbest) to produce corner-specific parasitic data. It is critical to use the SPEF that matches the PVT corner being analyzed — a cworst SPEF with slow libraries for setup, a cbest SPEF with fast libraries for hold.

On-Chip Variation (OCV)

Within a single chip, transistors and wires do not behave identically everywhere. The center of the die may be at a different temperature than the edges. Process variations cause some transistors to be faster or slower than others on the same die.

OCV analysis models this by applying different derating factors to the launch and capture paths of a timing check. This makes the analysis more pessimistic but more realistic, catching timing failures that would be missed with a single uniform timing model.

🧠 Knowledge Assessment Quiz

Question 1: Why is STA performed after place-and-route rather than after synthesis?

  • A. STA requires RTL source files which are only available after P&R.
  • B. Only after P&R do we have the actual physical layout with real wire lengths and extracted parasitics for accurate timing.
  • C. PrimeTime cannot read gate-level netlists from synthesis.
  • D. STA is only needed for FPGA designs, not ASICs.

Correct! After P&R, the design has real cell placements and routed wires. Parasitic extraction produces SPEF files with actual R and C values, enabling PrimeTime to compute accurate path delays.

Question 2: Which PVT corner is primarily used for setup timing analysis?

  • A. Fast-Fast, high voltage, best parasitics
  • B. Slow-Slow, low voltage, worst parasitics
  • C. Typical-Typical, nominal voltage
  • D. The corner does not matter for setup analysis.

Correct! Setup violations occur when data arrives too late. The slow-slow corner with low voltage and worst parasitics gives the longest path delays, making it the hardest corner for setup timing.

Question 3: What does a SPEF file contain?

  • A. The RTL source code of the design.
  • B. The timing library data for standard cells.
  • C. The extracted parasitic resistance and capacitance of every wire in the routed design.
  • D. The floorplan and macro placement data.

Correct! SPEF (Standard Parasitic Exchange Format) contains the R and C values extracted from the routed layout. PrimeTime uses this to compute accurate wire delays.

Question 4: What does OCV (On-Chip Variation) analysis account for?

  • A. Voltage variations between different chips in a wafer.
  • B. Temperature changes over time as the chip heats up.
  • C. Process and environmental variations within a single die, where different regions may have slightly different transistor and wire characteristics.
  • D. Variations between different technology libraries.

Correct! OCV models the fact that transistors and wires on the same die do not behave identically everywhere. It applies different derating factors to launch and capture paths for more realistic analysis.
