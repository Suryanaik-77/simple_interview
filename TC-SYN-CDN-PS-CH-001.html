🧠 Knowledge Assessment

1. Why is an MMMC configuration needed for physical-aware synthesis?

  • MMMC is only needed for designs with more than one clock domain.
  • The placement engine needs to evaluate timing under multiple PVT and RC corners simultaneously to make robust placement decisions.
  • Standard synthesis does not support timing analysis at all.
  • MMMC is required because iSpatial cannot read .lib files directly.
Correct! Different PVT/RC corners can produce different critical paths. MMMC ensures the placer optimizes for all corners simultaneously.

2. What additional inputs does physical-aware synthesis require compared to standard synthesis?

  • Only a different set of timing library files.
  • A routed DEF file from a completed place-and-route run.
  • LEF files (cell physical abstracts) and a floorplan DEF file with die area, rows, and macro placements.
  • A Verilog testbench for functional verification.
Correct! LEF files provide cell dimensions and pin locations. The floorplan DEF provides die boundaries and macro positions. Together they enable placement-based wire delay estimation.

3. Why is congestion analysis important in physical-aware synthesis?

  • It determines how many clock domains the design has.
  • It is required to generate the gate-level netlist.
  • High congestion areas can cause routing failures and DRC violations during P&R. The placer redistributes cells to avoid hotspots.
  • Congestion analysis is only needed for designs smaller than 100K gates.
Correct! Physical-aware synthesis detects congestion during placement and redistributes cells to improve routability.

4. What is the benefit of write_design -innovus -handoff?

  • It creates a smaller output file that loads faster.
  • It packages netlist, placed DEF, timing constraints, and LEF references into a single Innovus-compatible database for seamless P&R handoff.
  • It automatically runs place-and-route inside Genus.
  • It only works with iguana_soc, not with other designs.
Correct! Innovus can start from the placed netlist instead of scratch, saving significant P&R runtime.
