📖 Theory and Background

What is Synthesis?

In VLSI, synthesis is the process of translating a Register-Transfer Level (RTL) design written in Verilog or VHDL into an optimized gate-level netlist. The synthesis tool maps RTL constructs to standard cells from a technology library, optimizing for Power, Performance, and Area (PPA) during this conversion.

Cadence Genus is an industry-standard synthesis tool that performs this transformation. Unlike Synopsys Design Compiler, Genus uses set_db database commands to configure its environment, and breaks the synthesis into three explicit phases: syn_generic, syn_map, and syn_opt.

Understanding the Elaboration Phase in Genus

After reading RTL files with read_hdl, Genus performs elaboration via the elaborate command. This is Genus's equivalent of Design Compiler's separate analyze + elaborate + link sequence — in Genus, all three happen together during elaborate.

During elaboration, Genus performs three essential checks:

  • Resolves module references: Connects instantiated submodules to their Verilog definitions
  • Checks hierarchy: Ensures all submodule definitions have been read in via read_hdl
  • Validates library cells: Confirms that standard cells exist in the technology library specified by set_db link_library

After elaboration, running check_design generates a report showing the number of unresolved references. A clean design shows:

Unresolved References          0

Genus TUI-273: The Unresolved Reference Warning

TUI-273 Warning: 
[TUI-273] Unresolved reference to module 'module_name' in 'top_design'.

This warning indicates that Genus encountered an instantiation of module_name inside top_design, but it cannot find the Verilog definition for that module among the files read with read_hdl or in the loaded libraries.

Root Causes of TUI-273:

  • Missing RTL file: The .v file containing the module definition was not included in the read_hdl file list
  • Typo in module name: The instantiation name in the parent module doesn't exactly match the module's module declaration
  • Missing library file: A standard cell (e.g., an LVT cell) is not found in any library listed in set_db link_library
  • Incorrect search path: The library file path in set_db init_lib_search_path does not include the directory containing the required .lib file

🧪 Lab Focus: The Two Main Culprits

Throughout these testcases, you will solve the two most frequent unresolved reference scenarios:

  • Missing Source Files: Adding missing Verilog files to the read_hdl file list so Genus can find module definitions.
  • Library Configuration Issues: Ensuring all required .lib files (standard cell HVT/SVT/LVT and SRAM macro libraries) are listed in set_db link_library.

📝 Knowledge Assessment Quiz

Question 1: In Cadence Genus, which command is used to read RTL source files into the tool?

  • A. read_verilog
  • B. analyze -format verilog
  • C. read_hdl
  • D. import_hdl

Correct! Cadence Genus uses read_hdl to parse and load Verilog/VHDL source files. This is different from Design Compiler which uses analyze -format verilog. After reading all files, elaborate builds the design hierarchy.

Question 2: Which Genus message ID indicates that a module instantiation cannot be resolved to a definition?

  • A. LINK-5
  • B. UID-341
  • C. TUI-273
  • D. ELAB-100

Correct! TUI-273 is the Cadence Genus message code for an unresolved module reference. It is the Genus equivalent of Design Compiler's LINK-5 warning. You will see it in the genus_synthesis.log file when modules cannot be resolved during elaboration.

Question 3: In Genus, which set_db variable must include all standard cell and macro library .lib files to prevent unresolved cell references?

  • A. init_hdl_search_path
  • B. link_library and target_library
  • C. synthetic_library
  • D. rtl_source_files

Correct! set_db link_library lists all .lib files Genus uses to resolve library cell references during elaboration. set_db target_library specifies the cells available for technology mapping during syn_map. Both must be updated when adding new cell variants (e.g., LVT) or macro libraries (e.g., SRAMs).

Question 4: After adding a missing Verilog file to the read_hdl file list, what must you do for the change to take effect?

  • A. Reload only the modified file using read_hdl in the running Genus session
  • B. Run check_design again after elaborating
  • C. Re-run the complete synthesis flow (make run) so Genus re-elaborates with the old file
  • D. No action needed — Genus detects file changes automatically

Correct! Elaboration happens early in the flow and builds the complete design hierarchy from all files that were read. After modifying the file list, you must restart Genus and re-run the full flow so it re-reads all files and rebuilds the hierarchy with the newly included module.
