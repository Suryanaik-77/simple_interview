📖 Theory and Background

What is Floorplanning?

Floorplanning is the stage of physical design where you define the physical framework on which the chip will be built. It establishes the die size, core area, I/O port positions, macro placement, and the power distribution network — before any standard cell placement has occurred.

A well-designed floorplan is the single biggest factor in achieving timing closure and minimizing routing congestion. A poor floorplan that misplaces macros or under-resources power delivery will cause problems that cannot be fixed at placement or routing time.

Die Area vs Core Area

The die is the full silicon area that gets cut from the wafer — it includes the I/O ring, pads, and the core region. The core is the inner rectangular area where standard cells and macros are placed. The boundary between the core and die edge is controlled by the core offsets (left, right, top, bottom), which reserve space for I/O buffers, power rings, and routing channels. At block level, core offsets are typically 0.5–2.0 µm; at chip level (with pad rings), offsets are 200–500 µm.

Core utilization = (Standard cell area + Macro area) ÷ Core area × 100%. TSMC 28nm designs typically target 60–70% core utilization. At utilization above 75%, the placer cannot find timing-optimal positions for critical cells, and routing congestion increases sharply. At very low utilization (<50%), the die area is oversized, increasing manufacturing cost per wafer.

Die Sizing Calculation — Utilization and Aspect Ratio

Given total cell area and a target utilization, the core dimensions are derived as follows:

  1. Core Area = Total Cell Area ÷ Target Utilization
  2. Core Width = √(Core Area ÷ Aspect Ratio)   where Aspect Ratio = Height ÷ Width
  3. Core Height = Aspect Ratio × Core Width
  4. Die Width = Core Width + Left Offset + Right Offset
  5. Die Height = Core Height + Top Offset + Bottom Offset

Example: Cell area = 0.35 mm², target utilization = 70%, aspect ratio = 1.2 (slightly taller than wide):
Core Area = 0.35 ÷ 0.70 = 0.50 mm²
Core Width = √(0.50 ÷ 1.2) = 0.645 mm  |  Core Height = 1.2 × 0.645 = 0.775 mm

In this lab, the die area and core offsets are pre-defined in floorplan_without_pg_Phy_cells.def. Understanding the sizing calculation is essential for verifying whether the given DEF dimensions are consistent with the target utilization and for troubleshooting IMPFP-110 errors (invalid utilization ratio) that occur when the core area is too small for the placed cell area.

🏉 Floorplan Goals and Aims

The floorplan stage has four primary engineering objectives. Every decision made during floorplanning should be evaluated against all four simultaneously — they interact with and constrain each other.

⏰ Timing Closure

  • Keep the critical timing path cells physically close — long wires add capacitance and increase propagation delay
  • Place macros so that the cells that feed into them and receive data from them are adjacent in the standard cell core
  • Avoid placing a macro that forces a critical path to route around it — adding even 100µm of detour on a 1 GHz design can cost >100 ps
  • Target core utilization of 60–70% — above 75% the placer cannot find optimal positions for timing-critical cells

⚡ Power Delivery (IR Drop)

  • IR drop must stay below 5% of VDD across all operating conditions — excessive drop shifts device threshold voltages and slows combinational logic
  • The power grid must be dense enough to deliver current from the C4 bumps to every standard cell row with low resistance
  • High-activity blocks (multipliers, datapath) need denser power stripes directly above them
  • Macro blocks have their own internal power connections — ensure the floorplan provides stripe coverage over macro power pins

🔄 Routability

  • The router needs horizontal and vertical routing channels between macros and between the core and the die boundary
  • A minimum channel width of 10–20µm between adjacent macros is required for signal routing — narrower channels cause 100% routing congestion
  • Uniform standard cell density avoids creating routing hotspots — congested regions cause the router to use longer detour paths, degrading timing
  • I/O ports placed at the die edge should be spaced so that the routing tracks to them do not overlap at the core boundary

□ Area Efficiency

  • Every µm² of unused core area is cost — it translates directly to die area, which drives wafer cost
  • Macros should be placed to leave as little fragmented unusable area between them as possible
  • Standard cell rows must fill the space between and around macros without creating unroutable isolated islands
  • Halo (keepout) regions around macros consume area — use the minimum halo that the process design rules require

💿 Macro Placement Guidelines

SRAM macros, register files, and hard IP blocks are significantly larger than standard cells and are placed as fixed rectangular objects before standard cell placement begins. Their position dominates the quality of the entire physical design — the placer cannot move them. Systematic macro placement follows nine key guidelines.

Rule 1 — Avoid placing macros in the core center

Macros placed in the center of the core fragment the standard cell area into isolated sectors, forcing every net that connects to the macro to route around its boundary. Edge or corner placement leaves a contiguous standard cell region in the core interior where the placer can optimize freely. The macro's data pins face inward toward the core; its power pins face the die boundary where the power grid provides direct connection.

Rule 2 — Orient macro pins to face the standard cell region

SRAM and register file macros expose their data, address, and control pins on specific sides depending on orientation (R0, R90, MX, MY, etc.). Choose the orientation so that the data port pins face the logic that drives them. Wrong orientation forces every connected net to route around the macro body, adding 200–500 ps of wire delay on critical paths.

Rotation restrictions in 28nm: At 28nm and below, macros have a fixed poly-gate orientation constraint — 90° and 270° rotations are prohibited by DRC rules because they change the direction of the poly lines relative to the diffusion active regions, violating gate printing rules. Only R0 (0°), MX (horizontal mirror), MY (vertical mirror), and MXR90/MYR90 flipped variants are typically legal. At 40nm and above, rotation is generally more flexible. Always verify the legal orientation set from the PDK LEF symmetry statement before applying any rotation in the floorplan DEF.

Rule 3 — Place macros communicating with I/O close to the relevant port side

If an SRAM macro's data bus connects directly to a block-level port (e.g., a memory-mapped interface), place the macro on the same die edge as those ports. This minimizes the wire length between the macro and the boundary, reducing both routing congestion near the boundary and the delay on those interface paths.

Rule 4 — Maintain routing channels between macros (calculate required channel width)

A minimum gap of 10–20µm must be maintained between adjacent macros. Calculate the required channel width as: Number of routing tracks needed × track pitch. For a 28nm design with M5 pitch of 0.14µm and 50 signal wires crossing the channel, the minimum channel = 50 × 0.14 × 2 = 14µm. Narrower channels cause 100% routing congestion and produce unresolvable DRC violations at route-detail time.

Rule 5 — Apply halos (keepout regions)

A halo is a rectangular keepout region around each macro where no standard cells may be placed. TSMC 28nm typically requires 5–10µm halos to prevent cell placement from blocking the macro's pin access routes and to avoid DRC violations between cell diffusion and macro boundary geometry. The halo also reserves space for the macro's power-ground via connections.

Rule 6 — Group macros based on hierarchical connectivity

Macros that exchange data with each other (e.g., a tag SRAM and a data SRAM in the same cache bank) should be placed adjacent to each other. Co-located macros share short routing channels and allow the bus wires between them to be routed without traversing the standard cell region. Spreading connected macros across opposite sides of the die forces the bus to cross the full die width, consuming routing resources and adding latency.

Rule 7 — Avoid crisscross routing patterns

A crisscross routing pattern occurs when two macros are placed such that the nets from macro A must cross over macro B to reach their destinations, and vice versa. This creates a routing deadlock — neither set of nets can be routed without blocking the other. Always verify the data flow direction across your floorplan: nets should flow in consistent directions (left-to-right, top-to-bottom) without crossing over each other's macro boundaries.

Rule 8 — Place larger macros near the core boundary

Large SRAM arrays (e.g., L2 cache, 2048-row register files) placed near the core boundary allow their power pins to connect directly to the die-level power grid with minimum via stacking. Placing them in the core interior forces the power grid to span long distances in upper metal layers before reaching the macro supply pins, increasing IR drop across the macro's internal logic.

Rule 9 — Avoid standard cell trap pockets

A trap pocket is a closed region of standard cell rows fully surrounded by macros and/or the die boundary, with no routing escape path. Cells placed in a trap pocket can receive power and clock but cannot connect their signal pins to the rest of the design — the global router reports 100% overflow in that region. Before finalizing macro positions, verify in the Innovus floorplan view that every standard cell region has at least two independent routing escape corridors to the global routing grid.

📌 Port and Pin Placement Guidelines

I/O ports (the external interface pins of the block) are placed on the die boundary during floorplanning using edit_pin in Cadence Innovus. Their positions determine both the routability of connections from the top-level integration and the wire lengths from the boundary to the internal logic.

Guideline 1 — Select the port side based on connectivity

The most effective principle in port placement is to place each port on the side of the block that is closest to the logic it connects to. Analyze the netlist: if an input bus feeds a macro in the left half of the core, place those input ports on the left edge. If an output bus comes from logic in the top-right corner, place those outputs on the right or top edge. This side-selection minimizes the routing distance between the port and its first connected cell, reducing both wire length and congestion near the boundary.

Guideline 2 — Group ports by functional bus

Related signals — all bits of a data bus, all bits of an address bus, or a set of control/handshake signals — must be placed contiguously on the same edge. Grouping allows the router to create compact, parallel routing bundles. Scattering bus bits across different edges forces the router to interleave connections across the die, consuming routing tracks from multiple layers and increasing congestion everywhere.

Guideline 3 — Assign ports to the correct metal layer

Ports are assigned to specific metal layers using edit_pin -layer. In TSMC 28nm block-level flows:

  • M4 / M6 — standard signal I/O ports on vertical/horizontal preferred layers respectively. These layers extend across the full die height/width and are reachable at the boundary by the top-level router.
  • M8 / M9 — used for high-current power/ground ports or bump-connected pads that must carry supply current.
  • M1 / M2 — must never be used for I/O ports. These are local routing layers that exist only within and directly above standard cell rows; they do not reach the die boundary. A port placed on M1 or M2 creates a floating metal geometry with no external connection.
Guideline 4 — Calculate port spread distance and use multi-layer interleaving

The spread distance defines how far along the die edge the ports are distributed. The formula is:

Total Spread = Nports × Metal Pitch × (1 + Empty Tracks)

For a TSMC 28nm block with 240 ports on the top edge, M4 pitch = 0.14 µm, and 1 empty track between each port:
Spread = 240 × 0.14 × (1 + 1) = 67.2 µm per layer

If the available edge length cannot accommodate all ports on a single layer at the required pitch, use multi-layer interleaving: alternate ports between M4 and M6 along the same edge. This distributes 120 ports to M4 and 120 to M6, each with a pitch of 0.28 µm — halving the required span while satisfying each layer's independent DRC spacing rules. Multi-layer interleaving can reduce the required spread distance by 30–66% depending on the number of layers used.

Guideline 5 — Avoid die corners and maintain minimum spacing

Port geometries placed within 5–10µm of die corners risk corner DRC violations. Adjacent ports must maintain the minimum metal spacing for their assigned layer. The -fix_overlap 1 flag in edit_pin automatically resolves minor spacing violations, but it is better to set an appropriate -spacing value from the start. Run check_pin_assignment after edit_pin to confirm there are no illegal placements.

🔎 Port placement in this lab (iguana_soc design):

All ports are placed uniformly along the Top edge on metal layers M4 and M6 using a fill-layer spread pattern with clockwise direction. A 2-track pitch between adjacent ports satisfies the minimum metal spacing rules while giving the top-level router adequate access to each pin from above the die boundary. The start and end coordinates define the placement window — ports are distributed within this span in order, interleaved across M4 and M6 to halve the required pitch per layer. After placement, a pin assignment check verifies that no ports are outside the window, overlapping, or on illegal layers.

📈 Physical Cell Types Used in Floorplanning

Endcap Cells — Well Proximity Effect (WPE) and Row Termination

At the end of each standard cell row, the N-well and P-well regions must be properly terminated. Without endcap cells, the abrupt well boundary causes the Well Proximity Effect (WPE): boron and phosphorus implant ions scatter laterally from the well edge into adjacent transistors, shifting their threshold voltages by up to 20–30 mV. This shift degrades drive strength, changes propagation delay, and causes timing violations that are impossible to detect until the design reaches silicon.

Endcap cells solve WPE by extending the well geometry cleanly to the row boundary. TSMC 28nm uses two different endcap cell types: BOUNDARY_RIGHTBWP40P140 is placed at the left edge of each row (its geometry faces right into the row), and BOUNDARY_LEFTBWP40P140 is placed at the right edge (its geometry faces left). This mirrored placement ensures both well edges are terminated correctly regardless of row direction.

Well-Tap Cells — Latch-Up Prevention through Parasitic SCR Suppression

In CMOS technology, the n-well/p-substrate structure inherently forms a parasitic p-n-p-n Silicon Controlled Rectifier (SCR). Under normal conditions, this SCR is off. However, when triggered — by an I/O voltage overshoot, a power-supply glitch, or an ESD event — the SCR turns on and creates a low-resistance short between VDD and VSS. This latch-up condition draws destructive current that permanently burns out the chip if power is not immediately removed.

The SCR is prevented from triggering by ensuring the N-well and P-substrate have sufficiently low resistance to VDD and VSS respectively. Well-tap cells provide direct ohmic contacts from the N-well to VDD and from the P-substrate to VSS. Because the well and substrate are resistive materials, their resistance to VDD/VSS increases with distance from the nearest contact. TSMC 28nm specifies a maximum well-tap distance of 30µm — beyond this distance, the well resistance is high enough that a transient trigger can initiate latch-up.

Well-tap cells are inserted in a checkerboard pattern across alternating rows. In a checkerboard arrangement, a tap in row N at position X is paired with a tap in row N+1 at position X + half-pitch. This staggered placement ensures that every point in the row grid is within 30µm of a tap in at least one direction — both horizontally and diagonally — providing complete 2D coverage against latch-up triggering.

⚡ Power Planning — IR Drop, Electromigration, and the Multi-Layer Grid

Why Power Planning Matters: IR Drop and Electromigration

IR drop is the voltage loss across the resistive power network from the supply pin to each standard cell row: Vdrop = I × Rgrid. If VDD = 0.9 V and the IR drop budget is 5%, the allowable drop is 45 mV. A cell receiving 0.855 V instead of 0.9 V has higher transistor threshold relative to its supply — it switches slower, degrading setup timing. There are two types: static IR drop (DC current from always-on logic) and dynamic IR drop (instantaneous current surge when a clock edge triggers simultaneous switching of many flops). Dynamic IR drop is typically 2–3× the static value and is the harder constraint to meet.

Electromigration (EM) occurs when the time-averaged current density in a metal wire exceeds the foundry's EM limit (typically 1–2 mA/µm² for M9 at 28nm). Above the EM limit, momentum transfer from electrons physically displaces metal atoms, forming voids (opens) and hillocks (shorts) over time. Power grid wires carry continuous high current and are particularly susceptible — sizing stripes to stay below the EM limit is a mandatory design constraint, not a guideline.

Routing Blockages Over Macros

Before creating M4/M5 power stripes, the power plan script creates routing blockages over all macro instances on M4 and M5. This is necessary because SRAM macros expose their horizontal power pins on M4 — if M5 horizontal power stripes were created without blockages, they would overlap these pins and create VDD-to-VSS shorts. The blockages force the stripes to route around the macro pin regions. After stripes are placed, the blockages are removed and update_power_vias inserts stacked vias directly over the macro pins to connect the macro supply up through the global grid. Keeping the blockages permanently would prevent these supply vias from being inserted.

Electromigration Current Density Limit

Electromigration (EM) is the gradual displacement of metal atoms caused by momentum transfer from electrons in a high-current wire. The current density formula is:

J = I ÷ (W × T)   where W = wire width, T = metal thickness

Exceeding the EM limit causes voids (metal depleted → open circuit) and hillocks (metal accumulated → short circuit) over months or years of operation. For TSMC 28nm power grid wires, the practical EM limit is 1.5–2.0 mA/µm². Industry practice is to design at 50% of the limit to provide guard margin for temperature variation and aging. Upper metal layers (M7–M9) are preferred for the high-current trunk stripes because they are thicker (lower resistance, higher EM limit) and have wider manufacturing tolerance.

The power plan creates a hierarchical multi-layer grid of VDD/VSS stripes from M4 through M9. Upper layers carry bulk current at minimum IR drop; lower layers distribute it to the standard cell rows. Stacked vias connect stripe layers at every intersection to minimize inter-layer resistance. After stripes are created, the M1 VDD/VSS rails inside standard cell rows are connected upward to the lowest stripe layer to complete the supply path to every cell.

📝 Knowledge Assessment Quiz

Test your understanding of floorplanning concepts before starting the testcases.

1. The checkerboard pattern in add_well_taps -checker_board staggers tap positions in alternating rows. Why is staggering necessary rather than placing all taps in the same column position?

  • Staggering reduces the number of tap cells required, saving area compared to columnar placement
  • Innovus requires staggered placement to avoid DRC violations between adjacent-row tap cell geometries
  • A columnar pattern covers only the horizontal direction — every point is within 30µm horizontally, but the diagonal distance to the nearest tap in an adjacent row could exceed 30µm. The checkerboard ensures that every point in the 2D row grid is within 30µm of a tap cell in at least one diagonal direction, providing complete coverage against latch-up triggering
  • Staggered placement distributes the VDD/VSS current from tap cells more evenly across the routing grid
Correct! The TSMC 28nm maximum well-tap distance of 30µm applies in all directions, not just horizontally. A columnar pattern (all taps aligned in the same column) leaves diagonal distances between rows that can exceed 30µm. The checkerboard offsets every alternate row by half the column pitch, ensuring that the diagonal distance to the nearest tap never exceeds the maximum — providing complete 2D latch-up protection.

2. The power plan script creates routing blockages over macros on M4/M5 before calling add_stripes, then removes them before update_power_vias. Why must the blockages be removed before update_power_vias?

  • Routing blockages prevent update_power_vias from reading the macro pin coordinates from the LEF
  • Permanent blockages would cause DRC violations in the power grid connectivity check
  • update_power_vias must insert stacked vias directly over the macro's M4 power pins to connect the macro's internal supply to the global grid — routing blockages on M4/M5 over the macros would prevent these vias from being placed, leaving the macro supply disconnected
  • Blockage objects consume memory and must be deleted before write_db to reduce database size
Correct! The blockages serve only one purpose: prevent the M5 horizontal stripes from accidentally shorting to the macro's horizontal M4 power pins during stripe creation. Once the stripes are placed (routing around the macro areas), the blockages must be removed so that update_power_vias can insert supply vias directly over the macro pin locations — connecting the macro's internal power grid up through M4-M6 to the global power distribution network.

3. What does check_connectivity -nets {VDD VSS} -ignore_dangling_wires verify after the power plan?

  • That all signal nets are routed without open connections
  • That the power net widths meet the minimum metal width DRC rules on every layer
  • That the VDD and VSS power networks each form a single connected component — every cell row power strap and macro supply pin is reachable from the top-level power stripe, with no isolated floating VDD or VSS segment that would leave cells without supply
  • That the via stacking layers configured in the power plan script match the layers used in add_stripes
Correct! check_connectivity on VDD and VSS verifies that the entire power grid is a single connected graph — no isolated islands that would have no current path from the supply. Dangling wires (stubs at row terminations) are excluded with -ignore_dangling_wires since those are expected and harmless. Isolated segments indicate missing via connections between stripe layers — typically caused by incorrect stacked_via_bottom_layer / stacked_via_top_layer settings.

4. Two SRAM macros are placed with their data ports facing each other in the middle of the core. Their address buses connect to logic on the left side of the core. What macro placement rule is violated and what is the consequence?

  • Rule 5 (standard cell islands) — the macros enclose a region of cells that cannot be routed
  • Rule 3 (halos) — opposing halos overlap, violating minimum distance rules
  • Rule 7 (crisscross routing) and Rule 2 (pin orientation) — the address bus from the left must route over or around the first macro to reach the second macro's address port on the far side, while the data bus between the macros crosses the address routing, creating a crisscross deadlock. The router cannot resolve both simultaneously without 100% congestion in the channel between the macros
  • Rule 8 (larger macros near boundary) — both macros should be moved to the die edge
Correct! Placing the macros facing each other creates crisscross routing: the address bus from the left must bypass the near macro to reach the far macro's address pins, while the data bus between the macros passes through the same routing channel in the opposite direction. This deadlock causes 100% routing congestion in the inter-macro channel. The correct placement: both macros on the left edge with their address ports facing the address logic directly, and their data ports arranged so the data bus runs parallel (not crossing) to the address routing.
