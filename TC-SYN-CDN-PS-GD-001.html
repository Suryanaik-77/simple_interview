    • read_def — loads the floorplan with die area, placement rows, and macro positions.

    • check_timing_intent — saved before optimization (bf_opt) for comparison.

Understanding the 14 Warnings

Timing exceptions with no effect (7):

Seven SDC timing exceptions (false paths or multicycle path constraints in groups like grp_1, grp_2, grp_4, etc.) do not match any actual timing path in the current design. This can happen when:

  • The SDC was written for a broader design or a previous netlist revision, and some paths no longer exist after optimization removes or restructures logic.
  • A higher-priority exception already covers the same paths, making the lower-priority one redundant.
  • The exception uses overly broad wildcards that don’t resolve to real endpoints after elaboration.

These warnings are non-critical — they do not affect timing results — but cleaning them up improves runtime and memory usage.

Exceptions with invalid timing start-/endpoints (7):

Seven exception groups reference -from pins that are not valid timing startpoints. The majority are clock pins (CP) of ICG (Integrated Clock Gating) cells inserted by lp_insert_clock_gating: 

exception:tile/func_ssm40c_cw/grp_10
    invalid from points:
        pin:tile/RC_CG_HIER_INST0/RC_CGIC_INST/CP
        pin:tile/RC_CG_HIER_INST1/RC_CGIC_INST/CP
        ...  (hundreds of ICG clock pins)

exception:tile/func_ssm40c_cw/grp_6
    invalid from points:
        hpin:tile/g_sparc_core.core_sparc0/ifu_ifu_icd_icache_way_10/CLK
        hpin:tile/g_sparc_core.core_sparc0/lsu_lsu_dcache_dcache_way_01/CLK
        ...  (SRAM macro clock hierarchical pins)
  • The SDC uses -from on clock pins (CP, CLK), but clock pins are not valid timing startpoints. If the intent was to constrain paths passing through these pins, -through should be used instead.
  • The ICG instances (RC_CG_HIER_INST*) were inserted by Genus during clock gating. The original SDC was written before these cells existed, so its exceptions reference pins that were not anticipated.
  • The SRAM macro clock pins (icache_way, dcache_way) are hierarchical pins that cannot serve as path startpoints.

These warnings mean the invalid -from points are silently ignored by the tool — they do not corrupt timing analysis. However, the exceptions may not be constraining what the designer intended. A proper fix would update the SDC to use -through or remove the stale references.

💡 Key Takeaway: All 14 warnings are SDC hygiene issues, not functional timing problems. Zero warnings appear for unconstrained clocks, missing delays, missing drivers, or missing loads — the timing intent is complete. The design is safe to proceed to PnR.

🧠 Knowledge Assessment

1. The af_opt report shows 7 “Exceptions with invalid timing start-/endpoints” pointing to ICG clock pins. Why do these warnings appear?

  • The SDC file was modified between bf_opt and af_opt.
  • The SDC uses -from on clock pins of ICG cells inserted during clock gating, but clock pins are not valid timing startpoints — -through should be used instead.
  • The ICG cells were incorrectly synthesized and need to be removed.
  • The tool cannot analyze timing through clock gating cells.
Correct! Clock pins (CP) on ICG cells are not valid timing startpoints. The SDC exceptions were written before clock gating insertion created these cells, so they reference pins with -from that should use -through instead. The invalid points are silently ignored by the tool.

2. Why is an r2r WNS of -112 ps acceptable at synthesis stage?

  • Any negative slack means the design will fail.
  • Clock uncertainty provides margin, and LVT cells (blocked during synthesis) will be enabled in PnR to close remaining violations on critical paths.
  • The tool automatically fixes all violations during output writing.
  • Negative slack is ignored in physical synthesis mode.
Correct! At synthesis, LVT cells are blocked to control leakage power. PnR will selectively enable faster LVT cells only on critical paths, and the clock uncertainty margin absorbs small remaining violations.

3. What does syn_opt -spatial do differently from syn_opt?

  • It skips timing optimization entirely.
  • It only optimizes area, not timing.
  • It performs full placement-driven optimization, placing cells and using real wire delays to guide cell sizing, buffer insertion, and logic restructuring.
  • It runs the same optimization but writes output in a different format.
Correct! The -spatial flag triggers the iSpatial engine which iteratively places cells and optimizes timing using real wire delays from placement, not statistical estimates.

4. Why is MMMC used instead of a single timing library in iSpatial?

  • MMMC is required by the Genus license.
  • The placer needs to evaluate timing under multiple PVT and RC corners simultaneously to make placement decisions that are robust across all operating conditions.
  • MMMC makes the tool run faster.
  • Single libraries are not supported in Genus.
Correct! Different PVT corners can produce different critical paths. MMMC ensures the placer optimizes for all corners simultaneously.
