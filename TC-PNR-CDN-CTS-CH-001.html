📚 Knowledge Assessment Quiz

1. NDR (Non-Default Routing) rules are applied to clock nets during CTS. What do these rules specify, and why are they needed?

  • NDR rules specify that clock nets must use only the top metal layer (M9) to avoid interference with data signals on lower layers
  • NDR rules restrict clock nets to a minimum width to reduce capacitance and improve transition time
  • NDR rules specify wider wire width (e.g., 2× default) and larger spacing (e.g., 2× default) for clock nets. Wider wires reduce resistance and improve transition time; wider spacing reduces capacitive coupling from neighboring signal nets that could cause noise-induced skew or glitches on the clock
  • NDR rules replace the standard routing algorithm with a custom clock-specific router that guarantees zero skew between all branches
Correct! Clock nets are the most timing-sensitive nets in the design. NDR rules apply two key constraints: (1) Width increase (typically 2× default) — a wider wire has lower resistance per unit length, reducing RC delay on the wire segment and improving clock transition time; (2) Spacing increase (typically 2× default) — larger spacing to neighboring signal wires reduces capacitive coupling. If a switching signal net is routed adjacent to the clock, coupling capacitance can inject noise onto the clock, causing edge jitter and skew variation. The combination of lower resistance and lower coupling noise makes NDR-constrained clock routing significantly more robust than default signal routing rules.

2. In CTS pin type classification, a flip-flop clock input is assigned as a "sink pin." What is the correct definition of a sink pin in CTS?

  • A sink pin is a clock output — it is where the clock signal exits a buffer and enters the next stage of the tree
  • A sink pin is a clock input at the top level of the hierarchy — the entry point into the chip from the external clock source
  • A sink pin is an endpoint of the clock tree — a clock input on a sequential element (flip-flop, latch, or register) where the clock is consumed. The CTS engine must balance delays from the clock source to all sink pins to minimize skew
  • A sink pin is a clock input on a macro block — it is treated differently from flip-flop clock inputs because macros have internal clock networks
Correct! CTS classifies each clock pin into one of four types to guide tree construction: Sink pins — sequential element clock inputs (flip-flop, latch, register) that are the endpoints the tree must reach and balance; Through pins — hierarchical module clock inputs that pass the clock through to lower-level sinks without being a sink themselves; Ignore pins — clock pins the CTS tool should not consider or buffer (e.g., test-mode paths or intentionally unconstrained inputs); Float pins — pins the tool may optionally balance but is not required to. The sink pin classification is most critical because all tree balancing optimization is measured relative to achieving equal arrival time at all sinks.

3. What is a "through pin" in CTS and how does it differ from a sink pin?

  • A through pin is a clock pin that is driven by two sources simultaneously — used in clock muxing designs
  • A through pin is a clock input on a special high-drive-strength buffer that spans between two physical regions of the die
  • A through pin is a hierarchical module clock input that the CTS engine passes the clock signal through to reach the actual sinks inside the hierarchy. Unlike a sink pin, it does not consume the clock — it is a pass-through point in the design hierarchy that the CTS tool traverses to find deeper sinks
  • A through pin is a clock input that is marked as don't-touch so the CTS engine routes around it without inserting any buffers on that path
Correct! In hierarchical physical design, a module boundary creates a hierarchy pin — a clock input on the module's boundary. If the module contains flip-flops inside, the clock must pass through this boundary pin to reach the sinks. This boundary pin is classified as a "through pin" in CTS: the tool crosses it to find the actual sinks and builds buffering/balancing for the full path from the clock root to the innermost sinks. The through pin itself is not a timing endpoint — it is a transit point. Misclassifying a through pin as a sink would cause the CTS engine to stop tree construction at the module boundary, leaving all sinks inside the module with no clock tree buffering.

4. CTS target skew is typically specified as a fraction of the clock period. What is the commonly recommended guideline?

  • Target skew should be less than 1% of the clock period — tighter than this is impossible to achieve in silicon
  • Target skew should equal the clock period divided by the number of flip-flops — larger designs can tolerate more skew
  • Target skew is typically ~5% of the clock period. For a 1 GHz clock (1 ns period), this gives a 50 ps target. This value accounts for the fact that clock uncertainty in timing analysis already includes ~5% of period as the skew margin, and zero skew causes simultaneous switching that can spike IR drop
  • Target skew should be set to zero — modern CTS tools can achieve true zero skew, which eliminates all skew-related timing violations
Correct! The ~5% of clock period guideline for CTS target skew balances competing requirements. Zero skew is impractical (all flip-flops switching simultaneously causes large IR drop spikes and is impossible to maintain under process variation). Very tight skew targets (1–2%) require enormous buffering effort and aggressive NDR rules that consume routing resources. The 5% guideline is well within what modern CTS engines can reliably achieve, is accommodated by the 5% clock uncertainty allocation used in timing analysis, and leaves margin for process variation. For a 1 GHz design, 50 ps target skew is a reasonable goal; for a 500 MHz design, 100 ps is typical.
