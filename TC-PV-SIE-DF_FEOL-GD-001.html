Problem Statement

GUIDED

You have received a post-route GDS for the aes_cipher_top block taped out on TSMC 28nm HP technology. Before the block can be used in full-chip integration, FEOL dummy fill (OD and PO layers) must be inserted to satisfy CMP density requirements.

When you run the flow without any fixes, Calibre exits cleanly and produces a fill GDS. In this testcase you will read the runset, understand each statement, execute the run, and verify the output.

Your task: Run the provided FEOL fill runset and confirm the output fill GDS is created.

📝 Analysis

Open scripts/feol_runset.rule and review each statement:

  • LAYOUT PATH / PRIMARY: Points to the correct input GDS and top cell aes_cipher_top.
  • DRC RESULTS DATABASE: Writes the fill shapes to outputs/aes_cipher_top_FEOL.gds in a layer named _FEOL_fill.
  • #DEFINE UserprBoundary: Activates the boundary recognition feature in the TSMC rule deck so fill stays within the chip boundary.
  • INCLUDE: Loads the TSMC 28nm HP FEOL fill rule deck (Dummy_OD_PO_Calibre_28nm_HP.13a).

All parameters are correct. Run the flow and inspect the output.

📝 Step-by-Step Solution

  • Navigate and Start the Testcase

    The lab environment is already set up by setup_lab.sh. Navigate to the testcase directory and run the flow:

    cd ~/pd/labs/PV-SIE-DF_FEOL/TC-PV-SIE-DF_FEOL-GD-001
make all

  • Review the Runset

    Inspect the runset to understand what Calibre will do:

    cat scripts/feol_runset.rule

    Confirm that LAYOUT PRIMARY matches the top cell in the input GDS and that the INCLUDE path points to the OD/PO rule deck (not the metal fill deck).

  • Check the Calibre Log

    After make run, examine the log for any warnings or errors:

    grep -E "ERROR|FATAL|WARNING|complete" logs/feol_fill.log

    You should see Calibre reporting fill completion without any fatal errors.

  • Confirm the Output GDS

    Verify that the fill output file was created:

    ls -lh outputs/aes_cipher_top_FEOL.gds

    The file size should be several MB, indicating that fill shapes were inserted.

  • Re-run and Verify

    Apply your fix and re-run the flow to confirm the issue is resolved:

    make verify

✅ Success Criteria

  • outputs/aes_cipher_top_FEOL.gds exists and is non-empty
  • No ** ERROR or ** FATAL lines in logs/feol_fill.log

🧠 Knowledge Assessment

1. Which Calibre flag enables hierarchical fill processing?

  • -turbo
  • -hier
  • -drc
  • -fill
Correct! -hier enables hierarchical DRC/fill so Calibre processes cell instances rather than flattening the entire GDS.

2. The runset uses DRC RESULTS DATABASE ... GDSII _FEOL_fill. What does the trailing _FEOL_fill specify?

  • The output file format
  • The top-cell name in the output GDS
  • The cell name prefix used for fill shapes in the output database
  • A Calibre license feature flag
Correct! This string becomes the cell name for the fill results cell inside the output GDS file.

3. If LAYOUT PRIMARY names a cell that does not exist in the GDS, what happens?

  • Calibre aborts with a "can't find cell" or similar fatal error
  • Calibre picks the largest cell automatically
  • Calibre uses the first cell alphabetically
  • Fill runs on all cells in the GDS
Correct! Calibre requires an exact match; a missing primary cell causes an immediate fatal exit.

4. What is the purpose of DRC SUMMARY REPORT in the runset?

  • Names the output GDS containing fill shapes
  • Writes a text summary of fill statistics (shapes added per layer, density achieved)
  • Controls maximum CPU threads
  • Specifies the Calibre license server address
Correct! The summary report is a human-readable text file listing fill counts and density metrics per layer.
