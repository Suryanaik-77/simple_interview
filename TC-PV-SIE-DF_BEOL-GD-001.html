Problem Statement

GUIDED

After FEOL fill has been inserted, the next step in the physical verification flow is to add BEOL dummy fill — metal and via shapes — to satisfy CMP density requirements for all metal layers.

In this guided exercise you will run a correct BEOL fill runset and verify that outputs/aes_cipher_top_BEOL.gds is created.

Your task: Run the provided BEOL fill runset and confirm the output fill GDS is created without errors.

📝 Analysis

Open scripts/beol_runset.rule and review each statement. Key items to check:

  • LAYOUT PRIMARY is aes_cipher_top — correct top cell name.
  • DRC RESULTS DATABASE writes to outputs/aes_cipher_top_BEOL.gds.
  • #DEFINE UserprBoundary is present — constrains fill to the chip boundary.
  • INCLUDE loads the Metal/Via fill deck (Dummy_Metal_Via_Calibre_28nm.13a).

📝 Step-by-Step Solution

  • Navigate and Start the Testcase

    Navigate to the testcase directory and run the flow:

    cd ~/pd/labs/PV-SIE-DF_BEOL/TC-PV-SIE-DF_BEOL-GD-001
make all

  • Review the Runset

    Confirm the INCLUDE path points to the Metal/Via rule deck:

    grep INCLUDE scripts/beol_runset.rule

  • Check the Log

    grep -E "ERROR|FATAL|complete" logs/beol_fill.log

  • Confirm Output GDS

    ls -lh outputs/aes_cipher_top_BEOL.gds

  • Re-run and Verify

    make verify

✅ Success Criteria

  • outputs/aes_cipher_top_BEOL.gds exists and is non-empty
  • No ** ERROR or ** FATAL lines in the log

🧪 Validation & Verification

make verify

🧠 Knowledge Assessment

1. What does the GDSII _BEOL_fill suffix in DRC RESULTS DATABASE control?

  • Output file compression level
  • The cell name for fill results inside the output GDS
  • The Calibre license type required
  • The output file format version
Correct! This string becomes the results cell name inside the output GDS database.

2. Which layers does BEOL fill insert shapes on?

  • OD and PO
  • N-well and P-well
  • Metal routing layers (M1–M9) and via cuts
  • STI and gate oxide
Correct! BEOL fill targets all metal and via layers to satisfy CMP density requirements.

3. Why are FEOL and BEOL fill outputs separate GDS files?

  • They are merged later; keeping them separate allows individual re-runs if one rule deck changes
  • Calibre cannot write both to the same file
  • The foundry requires them to be delivered separately for sign-off
  • BEOL fill shapes would overwrite FEOL fill shapes in the same file
Correct! Separation allows targeted reruns and flexible merge ordering in the flow.

4. What command verifies that a GDS file is valid and readable?

  • calibre -verify output.gds
  • calibredrv with a Tcl script reading the file header and listing cells
  • file output.gds
  • gds_check -lint output.gds
Correct! calibredrv provides the standard way to inspect GDS files in the Calibre flow.
