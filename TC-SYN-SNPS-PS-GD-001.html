  • Read RTL, Elaborate, Link, and Check Design

    source ../inputs/Filelist.tcl

    • source ../inputs/Filelist.tcl — loads the filelist which sets $RTL_SOURCE_FILES to all Verilog source paths.
    • analyze — parses every Verilog file. Syntax errors are caught here.
    • elaborate $design_name — builds the complete design hierarchy starting from the top module tile. DC connects all sub-modules together and resolves parameters. If any instantiated module is missing, you will see an unresolved reference error here. Once elaborate succeeds, the full design is ready for constraints and compilation.
    • current_design + link — sets the active design context to tile and binds all cell references in the netlist to their timing models in the loaded libraries. Any unlinked cell will cause incorrect timing analysis.
    • check_design — runs structural sanity checks (unconnected ports, multi-driven nets, combinational loops) before constraints are applied. The report is saved for comparison with the post-compile check.

  • Restrict Cell Usage

    • The glob pattern blocks LVT cells (high leakage), strength-0 drive cells, clock buffer/inverter cells, and oversized drive-strength cells.
    • set_attribute ... dont_use false — selectively re-enables the CKLNQD8BWP40P140LVT integrated clock gate cell so it can be used for ICG insertion during compilation.

  • Configure Clock Gating (ICG Insertion)

    In a digital design, the clock network is the biggest source of dynamic power — it toggles every cycle even when registers are not changing value. An Integrated Clock Gate (ICG) cell sits between the clock source and a group of registers. When those registers are idle, the ICG shuts off their clock, eliminating wasted switching power. This typically saves 20–40% of total clock power. 

    set_app_var compile_clock_gating_through_hierarchy true
set timing_separate_clock_gating_group TRUE

set_clock_gating_style \
    -sequential_cell latch \
    -max_fanout 64 \
    -minimum_bitwidth 4 \
    -positive_edge_logic integrated:CKLNQD8BWP40P140LVT \
    -control_point before \
    -control_signal scan_enable \
    -num_stages 3

identify_clock_gating

set_app_var compile_delete_unloaded_sequential_cells true
    • Clock gating is allowed across hierarchical boundaries so sub-module registers can also be gated.
    • The ICG cell used is CKLNQD8BWP40P140LVT (the LVT cell we re-enabled in the previous step). Each ICG can gate up to 64 registers, and a register bank must be at least 4 bits wide to qualify.
    • identify_clock_gating scans the elaborated design and marks all eligible register groups for ICG insertion during compilation.
    • Unloaded flip-flops (outputs driving nothing) are automatically removed to save power.

  • Apply Timing Constraints (SDC)

    source ../inputs/tile.sdc

    This loads the complete timing constraints — clock definitions, input/output delays, false paths, and multi-cycle paths. The SDC is the backbone of timing closure: without correct constraints, every report from this point on is meaningless.

That lab teaches you how to debug every warning that appears when you run check_timing right after sourcing the SDC — missing clocks, unconstrained endpoints, missing input/output delays. Engineers who master check_timing can confidently write SDCs from scratch and catch constraint bugs before they waste hours on a bad synthesis run. Complete it and come back here — you will understand this step at a much deeper level.

  • Set Routing Layers and Extract Floorplan

    set_preferred_routing_direction -layers {M1 M3 M5 M7 M9} -direction horizontal
set_preferred_routing_direction -layers {M2 M4 M6 M8} -direction vertical
set_ignored_layers -min_routing_layer M1 -max_routing_layer M7
report_ignored_layers

extract_physical_constraints ../inputs/new_fp.def.gz
    • set_preferred_routing_direction — odd metals horizontal, even metals vertical. Guides wire-length estimation during SPG.
    • set_ignored_layers — restricts signal routing to M1–M7. Upper metals (M8–M9) are reserved for power distribution.
    • extract_physical_constraints ../inputs/new_fp.def.gz — the key step that makes synthesis physically aware. DC reads the compressed floorplan DEF and loads die boundary, core area, placement blockages, and pre-placed macro positions. After this, DC can estimate real wire lengths based on the physical layout.

  • Pre-Compile Timing Check and Path Grouping

    check_timing > ../reports/check_timing_bf_compile.rpt

group_path -from [all_registers -clock_pins] -to [all_registers -data_pins] -name r2r
group_path -from [all_registers -clock_pins] -to [all_outputs]              -name r2o
group_path -from [all_inputs]                -to [all_outputs]              -name i2o
group_path -from [all_inputs]                -to [all_registers -data_pins] -name i2r
group_path -from [get_pins -hierarchical *CLK*] -to [all_registers -data_pins] -name m2r
group_path -from [all_registers -clock_pins] -to [get_pins -of [all_macro_cells]] -name r2m
    • check_timing — verifies all clock domains are constrained and no endpoints are missing timing intent. Always run this before compilation to catch SDC issues early.
    • group_path — partitions all timing paths into named groups so DC optimizes and reports each category separately:
      • r2r — register to register (most common and usually most critical)
      • r2o — register to output port
      • i2o — input to output (pure combinational)
      • i2r — input to register
      • m2r — SRAM macro clock pin to register (memory read paths)
      • r2m — register to SRAM macro (memory write paths)

  • SPG Compilation

    compile_ultra -gate_clock -spg
    • -gate_clock — inserts ICG cells as configured earlier.
    • -spg (Synthesis with Physical Guidance) — activates placement-aware optimization. DC uses the loaded floorplan and TLU+ parasitic models to estimate real wire delays during cell mapping and logic restructuring.
    Runtime note: SPG compilation of the tile design takes several hours. Monitor progress in the log.

The tool also detects timing loops from the thread scheduler feedback logic and breaks them automatically.

check_timing After Compile

After compilation, most of the unconstrained endpoints disappear. DC optimizes away dead logic, merges registers, and resolves the control paths. The post-compile report is dramatically cleaner:

Only 2 endpoints remain unconstrained. These are the esl_rtsm_fcl_nextthr_bf latches — they belong to the round-trip scheduling state machine (RTSM) inside the OpenPiton thread scheduler. These latches are used as control storage for thread scheduling decisions and intentionally operate outside the main clock timing domain. They are not data-path registers and do not need setup/hold constraints. This is expected and can be safely waived.

🧠 Knowledge Assessment

1. What does extract_physical_constraints do?

  • It writes the netlist into a DEF file for PnR.
  • It loads the early floorplan DEF into DC so the tool can estimate real wire lengths based on placement geometry during SPG compilation.
  • It defines the clock constraints from the floorplan file.
  • It verifies that the DEF matches the netlist.
Correct! The floorplan DEF gives DC die boundary, macro positions, and placement context. After this, SPG can estimate actual wire distances instead of using statistical models.

2. Why is TLU+ loaded for physical synthesis but not for logic synthesis?

  • TLU+ contains standard cell timing arcs.
  • TLU+ provides RC extraction tables from the foundry process, giving DC accurate wire delay estimates based on routing distance instead of inaccurate wire-load models.
  • TLU+ is needed to generate the SVF file.
  • TLU+ defines clock constraints.
Correct! Wire-load models are statistical guesses. TLU+ tables model the actual parasitic R and C of each metal layer, enabling DC to compute realistic wire delays during SPG.

3. What does the -spg flag add to compilation?

  • Scan path generation for DFT.
  • It disables clock gating.
  • It activates Synthesis with Physical Guidance — DC uses the loaded floorplan and TLU+ data to estimate wire delays during cell mapping and optimization.
  • It writes a placed DEF as output.
Correct! SPG makes DC placement-aware. Without it, DC uses wire-load models even if a floorplan was loaded.

4. Why should the post-synthesis SDC be used for PnR instead of the input SDC?

  • The input SDC is deleted by DC after synthesis.
  • Synthesis inserts ICG cells that create new derived clocks not present in the original SDC. The post-synthesis SDC captures these additions.
  • The post-synthesis SDC is in a compressed format.
  • DC requires it for the SVF file.
Correct! ICG insertion creates new clock signals. The post-synthesis SDC includes these derived clocks so PnR has the complete timing picture.
