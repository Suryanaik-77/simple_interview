📖 Theory and Background

1. Global Routing, Track Assignment, and Detail Routing

Routing is the physical design stage that connects every signal net in the placed design with actual metal wires on the available routing layers. ICC2 separates the routing problem into three hierarchical passes that progressively increase in precision:

Routing Stage What It Does Resolution
Global Routing Divides the die into rectangular tiles (GCells) and determines which GCells each net must traverse — produces a coarse routing topology without assigning specific tracks GCell level (~10 tracks wide)
Track Assignment Assigns wires to specific routing tracks within each GCell, resolving conflicts between competing nets on the same layer Single track level
Detail Routing Performs exact wire and via placement, ensuring all DRC rules (spacing, width, via enclosure) are satisfied while honoring the track assignments from the previous stage Exact wire geometry

The command route_auto runs all three stages in a single call — global routing, track assignment, and detail routing — without requiring you to invoke each step separately. This is the standard production flow in ICC2.

route_auto vs. manual stages: Earlier ICC2 versions required separate calls to route_global, route_track, and route_detail. The route_auto command executes the same sequence internally but with better inter-stage coordination, improved timing-driven decisions, and automatic congestion-aware rerouting between passes. Always prefer route_auto for production flows.

2. Signal Integrity — Crosstalk-Driven Routing

Signal integrity (SI) refers to the impact of coupling capacitance between adjacent wires on the timing and logic correctness of a design. In deep sub-micron processes (28nm and below), long parallel wires can run within a few tens of nanometers of each other, creating significant coupling capacitance. Two classes of SI problems arise:

  • Crosstalk Delta Delay: A switching aggressor net injects current into an adjacent quiet victim net via coupling capacitance. If aggressor and victim switch in the same direction, the victim transitions faster (negative delta delay — a hold risk). If they switch in opposite directions, the victim slows down (positive delta delay — a setup risk).
  • Glitch Noise: A switching aggressor can induce a spurious voltage spike on a quiet victim. If the spike exceeds the logic threshold voltage, the victim may erroneously switch, causing functional failure independent of timing margins.

The app option time.si_enable_analysis true activates ICC2's SI engine, which computes coupling-aware delays using the extracted parasitic RC of the routed wires. The crosstalk-driven routing options (route.global.crosstalk_driven, route.track.crosstalk_driven) instruct the router to separate aggressor-victim pairs onto different layers or increase wire spacing where coupling is detected.

⚠️ SI analysis must be enabled before route_auto. If you enable SI analysis only after routing completes, ICC2 cannot use it during wire placement decisions. The router must know about SI constraints at global routing time so it can separate critical nets onto isolated layers and avoid parallel running wires on the most sensitive paths.

3. Antenna Violations — Plasma-Induced Gate Oxide Damage

Antenna violations arise during the semiconductor fabrication process, not during normal chip operation. During plasma etching of metal layers, long metal wire segments accumulate electric charge. If the accumulated charge has no discharge path to ground, it flows through the first completed connection it finds — typically the thin gate oxide of a connected MOSFET transistor. This can permanently damage or destroy the gate oxide, causing the transistor (and any flip-flop or logic gate it drives) to fail.

The antenna ratio is the metric: it is the ratio of the exposed metal wire area to the gate oxide area it connects to. Foundry design rules specify a maximum antenna ratio (typically 200:1 to 400:1). ICC2 checks this during routing and offers two fix strategies:

Fix Strategy Mechanism ICC2 Option
Diode Insertion A reverse-biased diode cell is inserted at the gate input. The diode shunts accumulated charge safely to the substrate during etching without affecting normal operation. route.detail.insert_diodes_during_routing true
Layer Hopping The wire is routed up to a higher metal layer earlier in its path, reducing the effective antenna area on the lower (longer-etched) layer. route.detail.hop_layers_to_fix_antenna true
Diode cell name matters: The route.detail.diode_libcell_names option must specify the exact library cell name of the antenna diode in your PDK. For the BWP35P140 standard cell library used in this lab, the correct cell is ANTENNABWP35P140. Using the wrong cell name causes the router to skip diode insertion silently, leaving antenna violations unresolved.

4. Redundant Vias — Yield and Electromigration Improvement

A standard single-cut via connects two metal layers through a single contact hole. If that contact hole is slightly misaligned or has an etching defect, the connection is open — the net fails. A redundant (multi-cut) via places two or more contact cuts in parallel for the same metal-to-metal connection. The wire still carries the same current, but now has two discharge paths: losing one cut still leaves the net connected.

The command add_redundant_vias post-processes the routed design and replaces eligible single-cut vias with multi-cut versions wherever the routing tracks allow the extra geometry. Benefits include:

  • Yield improvement: Single-cut via open defects are one of the leading causes of early-life chip failures. Multi-cut vias reduce this failure mode significantly.
  • Electromigration improvement: Multiple parallel cuts reduce current density through each individual contact, extending the electromigration lifetime of high-current power and clock nets.
  • No timing impact: Multi-cut vias have slightly lower resistance than single-cut vias, which typically improves (or at worst does not worsen) timing.

5. Post-Route Optimization — route_opt and Tightened Uncertainty

After route_auto completes, the design has real routed parasitics available for the first time. At this point, the timing numbers are more accurate than any estimate made during placement or CTS. The route_opt command exploits this accuracy to perform ECO (Engineering Change Order) style optimization: it can insert, resize, or move cells, reroute local congestion, and fix remaining DRC violations — all while keeping the routing largely intact.

A critical step before running route_opt is to tighten the clock uncertainty. During CTS, the uncertainty is set conservatively (0.255 ns) to account for post-CTS clock skew that has not been fully resolved yet. After routing, the clock tree is stable and the extracted skew is known. Reducing uncertainty to 0.204 ns gives route_opt a larger timing window to work within — setup violations that appeared under the conservative uncertainty may now be resolved without any cell changes, and the optimizer has more freedom to fix remaining violations.

Hold uncertainty post-route: Hold uncertainty is reduced to 0.050 ns post-route (from a larger value at CTS). Hold violations are fixed using LVT delay buffers (DEL*, BUFFD1BWP*, BUFFD2BWP*) which have fast transitions but add just enough delay to correct hold margin. LVT cells are also re-enabled for optimization post-route — the leakage penalty is accepted in exchange for timing closure capability.

1. What does the ICC2 command route_auto actually execute internally?

  • A. Only global routing — you must run route_track and route_detail separately afterward.
  • B. Detail routing only — global routing is done automatically during placement.
  • C. Global routing, track assignment, and detail routing in a single coordinated call.
  • D. Global routing and track assignment only — detail routing requires a separate route_detail call.
Correct! route_auto runs all three routing stages — global routing, track assignment, and detail routing — in a single command with inter-stage coordination and congestion-aware feedback between passes. This is the standard production command in ICC2 and replaces the older manual stage-by-stage flow.

2. What is the root cause of antenna violations in a physical design, and when do they occur?

  • A. Excessive coupling capacitance between adjacent wires that causes glitch noise during normal circuit operation.
  • B. Electromigration damage to a single-cut via caused by high current density in production use.
  • C. A timing violation caused by long wire delays on high-fanout clock nets after routing.
  • D. Accumulation of plasma charge on long metal wires during the semiconductor etching process, which discharges through and damages the gate oxide of a connected transistor.
Correct! Antenna violations are a fabrication-time phenomenon. During plasma etching, long metal wire segments act as antennas and accumulate charge. If this charge has no path to ground before the gate oxide connection is completed, it discharges destructively through the thin gate oxide, permanently damaging the transistor. This is why foundry design rule files specify maximum antenna ratios.

3. Why is the setup clock uncertainty tightened from 0.255 ns (CTS) to 0.204 ns before running route_opt?

  • A. The 0.255 ns uncertainty is a hold guard-band; it must be removed before setup optimization can run.
  • B. After routing, real parasitic extraction gives an accurate picture of clock skew, so the conservative CTS uncertainty can be reduced — giving route_opt more timing margin to recover setup violations.
  • C. ICC2 requires uncertainty below 0.210 ns before route_opt will run; it is a hard tool requirement.
  • D. Tightening uncertainty increases hold slack, which prevents hold-fix buffers from being unnecessarily inserted.
Correct! During CTS, the clock uncertainty includes a guard-band for post-CTS routing effects that are not yet quantified. After routing, the actual wire parasitics of the clock tree are extracted and the real clock skew is known. The 0.255 ns uncertainty was conservative; reducing it to 0.204 ns reflects the more accurate picture. A smaller uncertainty means less slack is wasted on the guard-band, giving route_opt more room to fix remaining setup violations.

4. What is a redundant (multi-cut) via and why is it inserted after route_auto?

  • A. A via that connects three or more metal layers simultaneously to reduce routing detours on congested designs.
  • B. A duplicate via placed on a different routing layer to provide an alternate signal path if a wire is severed by a DRC violation.
  • C. A via with two or more parallel contact cuts between the same two metal layers, reducing the risk of an open-circuit defect from a single misaligned or etching-defective contact and lowering current density to improve electromigration lifetime.
  • D. A special via type placed only on clock nets that provides lower resistance to minimize clock insertion delay.
Correct! A redundant (multi-cut) via places two or more parallel contact cuts for a single metal-layer-to-metal-layer connection. If one cut has a fabrication defect, the other cut maintains connectivity. The command add_redundant_vias post-processes the routed design to upgrade eligible single-cut vias to multi-cut versions, improving manufacturing yield and electromigration reliability with no degradation to timing.
