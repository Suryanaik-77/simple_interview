🧭 What this lab is

Dynamic_Array_in_SV.sv defines a dynamic_array_pkg package with dynamic-array typedefs and a transaction_t struct, plus a DynamicArrayDemo class that wraps int, byte, string, and transaction dynamic arrays with methods to create and resize them. tb_Dynamic_Array_in_SV.sv drives a dynamic_array_wrapper DUT while also declaring and exercising plain SystemVerilog dynamic arrays directly in the testbench.

💡 The concept

A dynamic array is declared with empty brackets (e.g. int int_array[];) and stays unsized until new[N] is called, which allocates N elements (default-initialized). Calling new[N] again on an already-sized array throws away the old contents and allocates a fresh block unless the old array is explicitly passed in as new[N](old_array), which copies over as many elements as fit. .size() reports the current element count and .delete() empties the array back to zero size. This create/resize/preserve/delete lifecycle is the core skill the lab builds.

⚙️ How it works

DynamicArrayDemo declares int_array, byte_array, string_array, and txn_array (of transaction_t, imported from dynamic_array_pkg) all as unsized dynamic arrays. Its new(initial_size = 0) constructor conditionally allocates int_array and byte_array via new[initial_size] when a nonzero size is passed. create_array(size) simply does int_array = new[size] and prints a message - this is a plain resize that does *not* preserve prior contents. resize_preserve(new_size) first records int_array.size(), then reallocates with int_array = new[new_size](int_array), which copies the existing elements into the new, differently-sized array - this is the pattern that safely grows or shrinks without data loss. On the testbench side, tb_Dynamic_Array_in_SV.sv instantiates a dynamic_array_wrapper DUT (parameter MAX_SIZE(256)) with push/pop/data_out/count/empty/full ports, and separately declares its own dyn_int[], dyn_byte[], dyn_string[], and dyn_2d[][] (an array of dynamic arrays) to manipulate directly in simulation.

🎯 What you'll learn
  • Declaring and sizing dynamic arrays with new[]
  • Preserving existing contents across a resize with new[new_size](old_array) versus a bare new[new_size]
  • Using .size() and .delete() to inspect and clear dynamic arrays
  • Building dynamic arrays of structs (transaction_t) and arrays-of-arrays (int dyn_2d[][])
⚠️ Common mistakes
  • Calling new[size] alone during what was meant to be a resize, and silently losing all previously stored elements (compare create_array vs resize_preserve in this same file)
  • Indexing into a dynamic array before it has ever been sized with new[], which is a runtime out-of-bounds access since the array still has zero elements
