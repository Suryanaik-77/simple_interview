🧭 What this lab is

A counter for which formal proves the target scenario count==10 is reachable, producing a witness trace. It shows how cover properties validate that the environment still exercises the behaviour you meant to verify.

💡 The concept

A cover property asks the tool to find at least one trace reaching a target condition. A hit yields a witness; a miss means the scenario is unreachable - often a sign of dead code or an over-strong assumption that accidentally forbids it.

🔧 The property under proof

The cover property asks formal to prove the scenario count==10 is reachable; a hit produces a witness trace, a miss (unreachable) means dead logic or an over-constrained environment.

cover property (count == 10);   // must be reachable - JasperGold finds a witness trace
⚙️ The formal flow

run.sh calls JasperGold on prove.tcl: analyze, elaborate, clock, reset, prove -all. The cover is reported covered with a witness trace.

jg -batch -tcl prove.tcl
  analyze -sv fpv_cover.sv fpv_cover_props.sv
  elaborate -top fpv_cover
  clock clk ; reset rst ; prove -all
🎯 What you'll learn
  • Explain what a cover witness trace proves
  • Recognize an unreachable cover as a red flag for dead code or over-constraint
  • Separate cover properties from functional-coverage percentages
🧰 Tool & files

Engine: JasperGold (Synopsys VC Formal via ./run.sh vcf). Files: fpv_cover.sv (design), fpv_cover_props.sv (SVA, bound), prove.tcl, run.sh.
