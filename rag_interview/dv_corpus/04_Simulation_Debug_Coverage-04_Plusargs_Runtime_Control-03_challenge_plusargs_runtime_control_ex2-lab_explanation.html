🧭 What this challenge is

The same self-checking DUT with an off-by-a-constant bug independent of any plusarg.

💡 The concept being tested

Whether the design advances by the correct step; a runtime knob cannot correct a wrong RTL constant.

🛠️ Debugging Guide
🔴 Symptom - what you see when you run it

The testbench prints FAIL: lines on enabled cycles with got equal to twice expected, at any NUM_CYCLES.

🔎 How to investigate
  1. Note the doubling pattern is unaffected by the plusarg value.
  2. Open the design file and read the enabled-update branch.
  3. Check the increment constant against the header spec, which calls for a step of one.
🧭 Fix direction

Change the increment from + 4'd2 to + 4'd1.

✅ How to confirm your fix

Re-run ./run.sh vcs; RESULT: TEST PASSED.
