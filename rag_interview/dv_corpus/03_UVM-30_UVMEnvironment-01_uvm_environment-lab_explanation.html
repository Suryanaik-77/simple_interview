🧭 What this lab is

env_pkg.sv implements my_env, which builds a my_agent (agt) and a my_scoreboard (scb) in build_phase, then connects agt.mon.ap to scb.imp in connect_phase so every transaction the monitor observes is streamed to the scoreboard for checking against the add_dut adder in tb_top.sv.

💡 The concept

The environment pattern exists to decouple stimulus generation and observation (inside the agent) from result checking (inside the scoreboard). build_phase is where components are constructed top-down via the factory (::type_id::create), while connect_phase runs afterward specifically so that TLM connections — like an analysis port to an analysis imp — can be made once every component in the hierarchy is guaranteed to exist. This ordering is fundamental to UVM's phasing: you cannot connect a port to a component that hasn't been built yet.

⚙️ How it works

The add_item transaction (env_pkg.sv) carries randomized a/b operands plus an res field that the monitor fills in from observed DUT output. add_sequence generates 8 add_items through start_item/finish_item on the agent's sequencer. my_env creates agt (a my_agent, containing the sequencer/driver/monitor) and scb (a my_scoreboard) in build_phase, then performs the critical integration step agt.mon.ap.connect(scb.imp) in connect_phase — routing every transaction the monitor publishes on its analysis port into the scoreboard's analysis imp. In tb_top.sv, the add_if interface and add_dut (a registered 8-bit adder driving sum/valid_out) are elaborated, the virtual interface is registered via uvm_config_db#(virtual add_if)::set(...), and run_test("env_test") kicks off the UVM phases.

🎯 What you'll learn
  • Why connect_phase, not build_phase, is the correct place to wire TLM ports between sibling sub-components
  • How an agent exposes only its sequencer and monitor analysis port to the env, hiding its internal driver/sequencer handshake
  • How to trace a transaction's path from sequence → sequencer → driver → DUT → monitor → scoreboard through the env's structure
⚠️ Common mistakes
  • Building sub-components in build_phase but forgetting to connect their analysis ports in connect_phase, so the scoreboard silently receives nothing
  • Trying to make TLM connections inside build_phase, before the target component instances are guaranteed to exist
