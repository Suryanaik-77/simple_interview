🧭 What this lab is

The reference lab implements my_agent, a single uvm_agent that, in build_phase, checks get_is_active() and either creates a driver + sequencer + monitor (active) or just a monitor (passive), then wires the driver to the sequencer in connect_phase only when active.

💡 The concept

UVM's built-in is_active field (of type uvm_active_passive_enum) lets one agent class serve two roles. get_is_active() reads that field, and the convention is to gate creation of driving components (driver, sequencer) on UVM_ACTIVE, while the monitor is always created since observation is needed in both modes. This keeps agent code DRY and lets a test flip a component between active and passive purely through configuration.

⚙️ How it works

In agent.sv, my_agent extends uvm_agent declares handles driver drv, sequencer seqr, and monitor mon. Its build_phase calls super.build_phase(phase) then branches on get_is_active() == UVM_ACTIVE: if true it calls driver::type_id::create, sequencer::type_id::create, and monitor::type_id::create, logging "Configured as ACTIVE agent"; otherwise it only creates mon and logs "Configured as PASSIVE agent". connect_phase calls super.connect_phase(phase) and, again gated on UVM_ACTIVE, connects drv.seq_item_port.connect(seqr.seq_item_export) — this connection is skipped entirely in passive mode since drv/seqr were never built. Separately, driver extends uvm_driver #(seq_item); its run_phase loops seq_item_port.get_next_item(req) → drive_item(req) → seq_item_port.item_done(), and drive_item prints the item's addr/data/write fields via uvm_info before a #10 delay models drive time. agent_pkg.sv collects everything with \include, in dependency order: seq_item.sv, sequencer.sv, driver.sv, monitor.sv, agent.sv, sequence.sv, env.sv, test.sv`.

🎯 What you'll learn
  • Writing one uvm_agent class that supports both active and passive configuration via get_is_active()
  • Gating component creation (build_phase) and TLM connection (connect_phase) on UVM_ACTIVE so passive mode never touches unbuilt handles
  • Connecting a driver's seq_item_port to a sequencer's seq_item_export correctly
  • Structuring a package file (agent_pkg.sv) with correct \include` ordering so base classes precede their users
⚠️ Common mistakes
  • Forgetting to guard the connect_phase driver-sequencer connection with the same is_active check as build_phase, causing a null-handle error in passive mode where drv/seqr were never created
  • Omitting super.build_phase(phase) / super.connect_phase(phase) calls, which can silently break inherited agent setup
