🧭 What this challenge is

A my_env whose build_phase sets agt.is_active = UVM_PASSIVE right after creating the agent, so the agent silently builds only a monitor — no sequencer, no driver.

💡 The concept being tested

This tests the learner's understanding of the is_active configuration knob on uvm_agent: an agent configured UVM_PASSIVE only instantiates its monitor in its own build_phase, omitting the sequencer and driver entirely, which means it can observe but never drive stimulus.

🛠️ Debugging Guide
🔴 Symptom — what you see when you run it

The test guards against a null-handle fatal by checking env.agt.sqr for null before calling seq.start(), so the simulation terminates cleanly and quickly — but the scoreboard checks 0 transactions instead of the expected 8, because no stimulus was ever generated or driven to the DUT.

🔎 How to investigate
  1. Find where my_env::build_phase sets agt.is_active immediately after agt = my_agent::type_id::create(...).
  2. Recall what UVM_PASSIVE means inside an agent's own build_phase — which sub-components get skipped?
  3. Check the test: notice it explicitly null-checks env.agt.sqr before starting the sequence — why would that handle be null in this configuration?
  4. Confirm the scoreboard connection itself (connect_phase) is intact — the bug is upstream of connection, in agent configuration.
🧭 Fix direction

In my_env::build_phase, change agt.is_active = UVM_PASSIVE; to agt.is_active = UVM_ACTIVE; so the agent builds its sequencer and driver and can actually drive the add_sequence stimulus.

✅ How to confirm your fix

Re-run the simulation: env.agt.sqr should no longer be null, the sequence should start and complete, and the scoreboard should report all 8 transactions checked.
