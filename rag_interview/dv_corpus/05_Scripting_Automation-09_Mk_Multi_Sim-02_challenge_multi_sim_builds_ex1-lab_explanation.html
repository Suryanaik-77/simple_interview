🧭 What this challenge is

The scaffold DUT with one planted functional bug that a clean compile cannot catch - only the simulate-stage self-check exposes it.

💡 The concept being tested

Whether the design correctly gates its state update on the enable input.

🛠️ Debugging Guide
🔴 Symptom - what you see when you run it

The testbench prints FAIL: lines on the cycles where enable is low, because the design advances when it should hold.

🔎 How to investigate
  1. Notice the FAIL cycles are exactly the enable-low cycles.
  2. Open the design file and read the clocked always block.
  3. Compare the non-reset branch against the header spec: update only while enabled.
🧭 Fix direction

Change the plain else that updates the count into else if (en) so the design holds when en is low.

✅ How to confirm your fix

Re-run ./run.sh vcs; the FAIL lines disappear and the run ends with RESULT: TEST PASSED.
