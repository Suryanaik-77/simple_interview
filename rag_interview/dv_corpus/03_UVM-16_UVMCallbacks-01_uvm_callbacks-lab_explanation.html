🧭 What this lab is

The reference lab (callback_pkg.sv, callbacks.sv, my_agent.sv, and related files) builds a driver/sequencer pair whose behavior can be modified at runtime through driver callbacks (driver_cb and derived classes like error_inject_cb, crc_error_cb) and sequence callbacks (seq_cb and derived classes like seq_error_cb, seq_delay_cb).

💡 The concept

The callback pattern has six steps: define a base callback class extending uvm_callback with empty virtual hook methods; write derived classes that override only the hooks they need; register the callback type with the component using ` uvm_register_cb `; insert the hook call inside the component with uvm_do_callbacks `; and finally attach callback instances to a specific component instance at runtime with uvm_callbacks#(COMP,CB)::add(). This separates 'what the component always does' from 'what a given test wants to change', so the same my_driver/my_sequencer code is reused across base_test, driver_cb_test`, and other tests with different callback sets attached.

⚙️ How it works

callback_pkg.sv imports uvm_pkg::* and includes the other files in dependency order so base classes exist before derived ones. callbacks.sv defines the driver-callback base class driver_cb (with empty hook methods taking a transaction by ref so it can be modified) plus derived classes such as error_inject_cb and crc_error_cb, and, in Part 2, the sequence-callback base seq_cb with derived seq_error_cb/seq_delay_cb. my_driver and my_sequencer call their hooks via ` uvm_do_callbacks ` at the appropriate points in their run-time code, and each is registered with its callback base type via uvm_register_cb `. my_agent instantiates seqr (a my_sequencer) and drv (a my_driver) as child components; it does not use callbacks itself, but the callback comment block shows how a test attaches them afterward: uvm_callbacks#(my_driver, driver_cb)::add(agt.drv, cb) for driver callbacks and uvm_callbacks#(my_sequencer, seq_cb)::add(agt.seqr, cb) for sequence callbacks, where agt is the my_agent instance and cb` is the concrete derived callback object created by the test.

🎯 What you'll learn
  • How to define a uvm_callback base class with virtual hook methods that do nothing by default
  • How ` uvm_register_cb `` links a component type to a callback base type so the pool can be looked up
  • How ` uvm_do_callbacks `` invokes every registered callback instance at a specific point in component code
  • How uvm_callbacks#(COMP,CB)::add() attaches a concrete callback object to one component instance from the test/environment
⚠️ Common mistakes
  • Forgetting ` uvm_register_cb(COMP, CB_BASE) ` on the component, so uvm_do_callbacks `` silently finds nothing in the pool even though callback objects were added
  • Calling uvm_callbacks#()::add() with a callback base type that doesn't match the one used in ` uvm_register_cb `/ uvm_do_callbacks ``, so the added instance is never triggered
