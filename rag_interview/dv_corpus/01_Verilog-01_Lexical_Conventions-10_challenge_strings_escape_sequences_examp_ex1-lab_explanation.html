Per-Leaf Exercise

This debugging exercise contains string literals in Verilog and an incomplete conditional statement in the ascii_processor module. The message_formatter stores 16-character strings in registers, while ascii_processor is supposed to convert ASCII characters to uppercase/lowercase and identify alpha and digit characters, but the implementation is truncated mid-statement.

🐛 Challenge Exercise

🔍 Debug Strategy

  1. The ascii_processor module's conditional statement starting with 'if (ascii_in >= 8'd97...' is incomplete and missing the closing condition and logic body.
  2. Check the original design intent: what ASCII range represents lowercase letters (a-z), and what should happen when that condition is true?
  3. Compilation will fail with a syntax error about the incomplete if statement; review the closing parenthesis and the conditional logic that should follow.

💡 Why It Matters

Incomplete conditional statements are common syntax errors that prevent code compilation. Understanding proper if-else syntax and ASCII character ranges (97-122 for lowercase, 65-90 for uppercase) is fundamental for character processing in hardware designs.

🧠 Knowledge Check

Q1: Which identifier is legal in Verilog/SystemVerilog?

  • 2bit_reg
  • _carry_out
  • end
  • data-valid

_carry_out is valid — identifiers may start with underscore. 2bit_reg starts with a digit, end is a keyword, and data-valid contains a hyphen.

Q2: What does <code>8'b1010_1010</code> evaluate to in hexadecimal?

  • 8'hAB
  • 8'hAA
  • 8'h55
  • 8'hA0

1010_1010 in binary is 0xAA. The underscore is purely cosmetic and ignored by the compiler.

Q3: A multi-line comment <code>/* ... */</code> is nested inside another. What happens?

  • Both comments close at the inner */
  • Compile error — nesting is illegal
  • The outer comment swallows the inner
  • Simulator-dependent behaviour

Verilog/SV does not support nested block comments. The first */ closes the comment, leaving the rest of the text as code — often causing a syntax error.

Q4: Which number literal is NOT valid in SystemVerilog?

  • 16'hDEAD
  • 8'o377
  • 4'b1x0z
  • 10'd1024

10'd1024 requires 11 bits to represent 1024 but only 10 bits are allocated; the MSB is silently truncated. The others are syntactically valid (x/z are legal in 4-state literals).

Q5: What is the difference between <code>`define</code> and <code>parameter</code>?

  • `define is scoped to a module; parameter is global
  • `define is a text macro (preprocessor); parameter is a typed elaboration-time constant
  • They are interchangeable
  • `define supports expressions; parameter supports only integers

`define is handled by the preprocessor before parsing — it performs literal text substitution with no type or scope. parameter is a typed, elaboration-time constant scoped to its module.
