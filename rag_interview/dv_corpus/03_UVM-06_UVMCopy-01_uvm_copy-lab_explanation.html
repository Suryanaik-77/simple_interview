🧭 What this lab is

copy_pkg.sv bundles copy_item.sv (transaction classes) and copy_test.sv (copy_demo_test), which runs through five demonstrations of UVM copy semantics: field-macro copy, deep-copy verification of nested objects, the do_copy() callback approach, do_copy() with nested objects, and a shallow-copy pitfall.

💡 The concept

UVM objects support copying in two complementary ways. With field automation macros (uvm_field_int, uvm_field_array_int, uvm_field_object, etc.), uvm_object_utils_begin/end auto-generates a do_copy() that copies each registered field, including recursing into nested objects registered with uvm_field_object (deep copy by default). Alternatively, a class can hand-write its own do_copy(uvm_object rhs) for performance or custom logic — but it MUST call super.do_copy(rhs) first so any inherited/base-class field copying still happens, then add its own field assignments on top. Getting this wrong is one of the most common UVM copy bugs.

⚙️ How it works

payload_obj (extends uvm_object) holds payload_data[] and checksum, registered via uvm_field_array_int and uvm_field_int so both fields are deep-copied automatically. network_packet (extends uvm_sequence_item) holds src_addr, dst_addr, pkt_type, priority_level, description, and a nested payload_h handle of type payload_obj, registered with uvm_field_object so the nested object is copied by value, not by reference. In copy_test.sv, copy_demo_test::run_phase raises an objection and calls, in order, demo_field_macro_copy(), demo_deep_copy_verification(), demo_do_copy_callback(), demo_do_copy_nested(), and demo_shallow_copy_problem(). demo_field_macro_copy() creates original_pkt and copied_pkt via the factory (network_packet::type_id::create), randomizes original_pkt, sets its description, and prints it before performing the copy, illustrating the baseline destination.copy(source) usage.

🎯 What you'll learn
  • The correct call direction for copy: destination.copy(source), not the reverse
  • Why an overridden do_copy() must call super.do_copy(rhs) before adding custom logic
  • How uvm_field_object gives automatic deep copy of nested objects, and when UVM_SHALLOW breaks that guarantee
⚠️ Common mistakes
  • Overriding do_copy() and forgetting super.do_copy(rhs), so inherited/macro-registered fields never get copied (or get clobbered afterward)
  • Calling copy() in the wrong direction (a.copy(b) instead of b.copy(a)), silently copying the wrong object into the wrong one
