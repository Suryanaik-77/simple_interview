🧭 What this lab is

compare_demo_test (in compare_test.sv, built from classes in compare_item.sv) runs a sequence of self-contained demo tasks that each isolate one aspect of UVM comparison — field-macro compare, the UVM_NOCOMPARE flag, do_compare() overrides, nested objects, dynamic arrays, and a custom uvm_comparer.

💡 The concept

Field automation macros (uvm_field_int, uvm_field_enum) register fields with the factory so compare() can iterate them automatically; any field tagged with UVM_NOCOMPARE is registered for other automation (printing, copying) but skipped during comparison. When automatic field-by-field comparison isn't expressive enough — e.g. you want custom tolerance, or to skip a field only sometimes — you override do_compare(), which is invoked by the base compare() machinery and must call super.do_compare() first if you still want the macro-driven fields checked, then add custom logic on top.

⚙️ How it works

MemoryTransaction extends uvm_sequence_item registers address, data, byte_enable, operation (an operation_t enum), and burst_len through uvm_field_int/uvm_field_enum inside uvm_object_utils_begin/end; the response_ok field is registered with the UVM_NOCOMPARE flag so DUT-driven response status never causes a mismatch. BurstConfig (nested object, definition continues past the shown excerpt) demonstrates comparing a sub-object held inside a parent transaction. compare_demo_test::run_phase raises an objection and calls demo_field_macro_compare(), demo_nocompare_flag(), demo_do_compare_callback(), demo_nested_object_compare(), demo_dynamic_array_compare(), demo_custom_comparer(), and demo_common_pitfalls() in sequence. demo_field_macro_compare() creates txn_a, txn_b, txn_c via MemoryTransaction::type_id::create, randomizes txn_a/txn_b with randomize() (fataling via uvm_fatal on failure), then exercises compare()'s return value under 'Test 1a: Compare Different Transactions'.

🎯 What you'll learn
  • How field automation macros wire fields into compare(), print(), copy(), and pack() simultaneously
  • When to use UVM_NOCOMPARE to exclude DUT-response or don't-care fields from comparison
  • How to override do_compare() safely by chaining super.do_compare() before adding custom checks
  • How compare() handles nested uvm_object fields and dynamic arrays
⚠️ Common mistakes
  • Forgetting that compare() returns 1 for a match and 0 for a mismatch, and writing the if-check backwards
  • Applying UVM_NOCOMPARE to a field that should actually be checked, silently masking real mismatches
  • Overriding do_compare() without calling super.do_compare(), which drops all the macro-registered field checks
