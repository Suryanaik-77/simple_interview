Special Codes in Digital Design

Gray, BCD, and Hamming Codes

🎯 Learning Objectives

  • Convert between binary, Gray code, and BCD numerical representations.
  • Understand the significance of Gray code in minimizing errors and BCD in preserving decimal digits.
  • Learn codes with basic single-bit error detection and correction capabilities.

Why Do We Need Special Codes?

The Problem with Standard Binary: Regular binary numbers work well for arithmetic, but they have limitations for specific applications like position sensing, decimal representation, and error-prone communication.

Problem 1: Position Ambiguity

When a mechanical encoder moves from position 3 (011) to 4 (100) in binary, all three bits change simultaneously. What if they don't change at exactly the same time?

Solution Needed: A code where only one bit changes at a time → Gray Code

Problem 2: Decimal Inefficiency

Digital systems work in binary, but humans think in decimal. Converting between them for every display is inefficient.

Solution Needed: A code that represents decimal digits directly → BCD (Binary Coded Decimal)

Problem 3: Error Vulnerability

In communication channels or memory, bits can flip due to noise. How do we detect and correct these errors automatically?

Solution Needed: A code that adds redundancy for error detection/correction → Hamming Code

Gray Code: The One-Bit-Change Solution

Consider a 3-bit position encoder (like in a rotary knob):

Binary Counting Problem:

Position Binary Bit Changes Risk
3 → 4 011 → 100 All 3 bits change High error probability
7 → 0 111 → 000 All 3 bits change High error probability
1 → 2 001 → 010 2 bits change Medium error probability

If bits don't switch simultaneously (common in mechanical systems), you might read 011 → 111 → 101 → 100, getting wrong intermediate values!

Gray Code Fundamentals

Gray code is a binary numeral system where two successive values differ in only one bit.

Key Property: Adjacent numbers differ by exactly one bit → No ambiguous intermediate states!

3-bit Gray Code Sequence

Decimal Binary Gray Code Bit Changes
0 000 000 -
1 001 001 1 bit changed
2 010 011 1 bit changed
3 011 010 1 bit changed
4 100 110 1 bit changed
5 101 111 1 bit changed
6 110 101 1 bit changed
7 111 100 1 bit changed

Conversion Between Binary and Gray Code

Binary to Gray Code

Method:

  1. Keep the most significant bit (MSB) as is
  2. For each subsequent bit:
    • Gray[i] = Binary[i] XOR Binary[i-1]

Example: Binary 101 (5) to Gray:

  • MSB: G₂ = B₂ = 1
  • G₁ = B₁ XOR B₂ = 0 XOR 1 = 1
  • G₀ = B₀ XOR B₁ = 1 XOR 0 = 1
  • Result: 111 ✓

Gray Code to Binary

Method:

  1. Keep the most significant bit (MSB) as is
  2. For each subsequent bit:
    • Binary[i] = Gray[i] XOR Binary[i-1]

Example: Gray 111 to Binary:

  • MSB: B₂ = G₂ = 1
  • B₁ = G₁ XOR B₂ = 1 XOR 1 = 0
  • B₀ = G₀ XOR B₁ = 1 XOR 0 = 1
  • Result: 101 (5) ✓

BCD: Binary Coded Decimal

Example: Display the number 249 on a 7-segment display

  • In pure binary: 249 = 11111001 (8 bits)
  • To display it, you need to:
    1. Convert 11111001 to decimal 249
    2. Extract hundreds (2), tens (4), ones (9)
    3. Convert each digit to 7-segment codes
  • This requires complex division/modulo operations in hardware

BCD Fundamentals

BCD represents each decimal digit with 4 binary bits (nibble).

Key Concept: Each decimal digit (0-9) is encoded separately using 4 bits.

Range: 0000 (0) to 1001 (9). Values 1010-1111 (10-15) are invalid in BCD.

BCD Encoding Table

Decimal Digit BCD (4 bits) Notes
0 0000 Same as binary
1 0001 Same as binary
2 0010 Same as binary
3 0011 Same as binary
4 0100 Same as binary
5 0101 Same as binary
6 0110 Same as binary
7 0111 Same as binary
8 1000 Same as binary
9 1001 Same as binary
Invalid 1010-1111 Not used in standard BCD

For single digits 0-9, BCD and binary are identical.
The difference appears for multi-digit numbers.

BCD Addition: The Special Case

Adding BCD numbers requires special handling because BCD digits only go up to 9.

Problem: 8 + 7 in BCD

BCD Addition Problem
   BCD: 1000  (8)
 + BCD: 0111  (7)
 ----------------
Binary: 1111  (15)  ← Invalid BCD! (should be 0001 0101)

1111 is 15 in binary, but in BCD we need:
1 (0001) and 5 (0101) = 0001 0101

Solution: BCD Adjustment Rule

If BCD addition result > 9 or generates carry, add 6 (0110) to correct:

BCD Correction
   1000  (8)
 + 0111  (7)
 --------
   1111  (15, invalid)
 + 0110  (add 6 for correction)
 --------
 (1)0101 = 0001 0101 = 15 ✓

Hamming Code: Error Detection and Correction

Scenario: Sending data 1011 through a channel

  • Sent: 1 0 1 1
  • Received: 1 0 0 1 (3rd bit flipped by noise)
  • How do we know an error occurred?
  • How do we know which bit is wrong?
  • Can we correct it without retransmission?

Simple parity check can detect odd errors but cannot correct them or identify the error location.

Hamming Code Fundamentals

Richard Hamming (1950) invented a family of error-correcting codes that can detect and correct single-bit errors.

Core Idea: Add redundant parity bits at strategic positions to create a code where each single-bit error produces a unique "syndrome" that identifies the error location.

Key Terminology

Data Bits (k)

Original information bits we want to protect (e.g., 4 bits: 1011)

Parity Bits (r)

Redundant bits added for error detection/correction

Code Word (n)

Total bits transmitted: n = k + r

Syndrome

Pattern of parity check results that identifies error location

Hamming(7,4) Code: A Concrete Example

The most famous Hamming code: 4 data bits + 3 parity bits = 7-bit code word.

Step 1: Bit Position Assignment

Hamming Code Structure
Position: 1  2  3  4  5  6  7
Type:     P1 P2 D1 P3 D2 D3 D4

Where:
- P1, P2, P3 are parity bits (redundant)
- D1, D2, D3, D4 are data bits (original information)

Step 2: Parity Bit Coverage

Each parity bit covers specific positions:

  • P1 (position 1): Covers positions 1, 3, 5, 7 (all positions where bit 1 in binary representation = 1)
  • P2 (position 2): Covers positions 2, 3, 6, 7 (all positions where bit 2 in binary representation = 1)
  • P3 (position 4): Covers positions 4, 5, 6, 7 (all positions where bit 3 in binary representation = 1)

Complete Example: Encoding 1011

Given data: 1 0 1 1 (D1=1, D2=0, D3=1, D4=1)

Step 1: Place data bits

Step 1: Place Data Bits
Position: 1  2  3  4  5  6  7
Type:     P1 P2 D1 P3 D2 D3 D4
Initial:  _  _  1  _  0  1  1

Step 2: Calculate P1 (covers positions 1,3,5,7)

Step 2: Calculate P1
Positions covered: 1(P1), 3(D1=1), 5(D2=0), 7(D4=1)
Bits: P1, 1, 0, 1
We want even parity (total 1's even):
Current sum: 1 + 0 + 1 = 2 (even)
So P1 must be 0 to keep parity even
P1 = 0

Step 3: Calculate P2 (covers positions 2,3,6,7)

Step 3: Calculate P2
Positions covered: 2(P2), 3(D1=1), 6(D3=1), 7(D4=1)
Bits: P2, 1, 1, 1
Current sum: 1 + 1 + 1 = 3 (odd)
So P2 must be 1 to make parity even
P2 = 1

Step 4: Calculate P3 (covers positions 4,5,6,7)

Step 4: Calculate P3
Positions covered: 4(P3), 5(D2=0), 6(D3=1), 7(D4=1)
Bits: P3, 0, 1, 1
Current sum: 0 + 1 + 1 = 2 (even)
So P3 must be 0 to keep parity even
P3 = 0

Step 5: Complete code word

Step 5: Complete Code Word
Position: 1  2  3  4  5  6  7
Final:    0  1  1  0  0  1  1

Transmitted code word: 0110011

Error Detection and Correction

Scenario: Bit 5 flips during transmission

Error Scenario
Sent:     0  1  1  0  0  1  1
Received: 0  1  1  0  1  1  1  (bit 5 flipped from 0→1)

Step 1: Recalculate parity checks at receiver

Step 1: Recalculate Parity
P1 check (positions 1,3,5,7): 0,1,1,1 → 0+1+1+1=3 (odd) → Error1=1
P2 check (positions 2,3,6,7): 1,1,1,1 → 1+1+1+1=4 (even) → Error2=0
P3 check (positions 4,5,6,7): 0,1,1,1 → 0+1+1+1=3 (odd) → Error3=1

Step 2: Form syndrome word

Step 2: Form Syndrome
Syndrome = Error3 Error2 Error1 = 1 0 1

Step 3: Interpret syndrome

Step 3: Interpret Syndrome
Syndrome 101 in binary = 5 in decimal
Error is at position 5!

Step 4: Correct the error

Step 4: Correct Error
Flip bit at position 5: 1 → 0
Corrected: 0 1 1 0 0 1 1 ✓ (matches original)

Relationship: For r parity bits, we can have up to 2ʳ - r - 1 data bits. The total code word length is n = 2ʳ - 1.

Example: r=3 → n=7, k=4 (Hamming 7,4)

Example: r=4 → n=15, k=11 (Hamming 15,11)

2.Which of these is a valid BCD representation for the decimal number 47?

  • 0100111 (7 bits)
  • 01000111 (8 bits)
  • 101111 (6 bits)
  • 1000111 (7 bits)

Correct Answer: 01000111 (8 bits: 0100 0111)

Explanation:

  • Decimal 47 has two digits: 4 and 7
  • 4 in BCD = 0100
  • 7 in BCD = 0111
  • Combined: 0100 0111 = 01000111 (8 bits)

Why others are wrong:

  • 0100111 (7 bits): Wrong number of bits. BCD for 2 digits needs 8 bits (4 bits per digit).
  • 101111 (6 bits): Too few bits, and 1011 is invalid BCD (represents 11, but BCD only goes 0-9).
  • 1000111 (7 bits): Wrong number of bits and pattern doesn't match valid BCD digits.

Binary comparison: 47 in pure binary = 00101111 (6 bits needed, but usually shown as 8 bits: 00101111). Note that binary is more compact but loses decimal structure.

5.Perform BCD addition: 47 (0100 0111) + 38 (0011 1000). What is the result after BCD correction?

  • 0111 1111
  • 1000 0101 with carry
  • 1000 0101
  • 0111 1111 with carry

Correct Answer: 1000 0101 with carry

Step-by-step addition:

   0100 0111  (47)
 + 0011 1000  (38)
 ------------
   0111 1111  (7F in hex, 127 in decimal - invalid BCD!)

   Since lower nibble (1111 = 15) > 9, add 6:
   0111 1111
 +      0110
 ------------
   1000 0101  (85 in BCD)

     Result: 1000 0101 = 85 with no further carry needed.

Final BCD result: 1000 0101 = 85 (which is correct: 47 + 38 = 85)

6.In a Hamming(7,4) code, if the received code word is 0110011 and the syndrome calculated is 000, what does this indicate?

  • Error in parity bit P1
  • Double-bit error occurred
  • No error in transmission
  • Error in data bit D3

Correct Answer: No error in transmission

Explanation:

  • Syndrome 000 indicates all parity checks pass
  • In Hamming codes, syndrome 000 means no single-bit error detected
  • The received code word matches what was sent (assuming no errors)

Important Note: Hamming(7,4) can detect but not correct double-bit errors. Syndrome 000 could also mean no error OR an undetectable error pattern (like certain double-bit errors). But for single-bit error detection/correction, syndrome 000 is interpreted as "no error."

8.What is the main disadvantage of BCD compared to pure binary representation?

  • It cannot represent decimal numbers
  • It uses more bits to represent the same number
  • It is harder to implement in hardware
  • It cannot be used for arithmetic operations

Correct Answer: It uses more bits to represent the same number

Explanation:

  • BCD uses 4 bits per decimal digit, while pure binary uses the minimum bits needed
  • Example: Decimal 249 requires 12 bits in BCD (0010 0100 1001) but only 8 bits in binary (11111001)
  • This inefficiency is the trade-off for preserving the decimal digit structure

Note: BCD is actually easier to implement for decimal displays and simpler for decimal arithmetic, but it's less storage-efficient.

10.What is the purpose of adding "6" (0110) in BCD addition when the result exceeds 9?

  • To convert binary to hexadecimal
  • To make valid BCD sum
  • To make the addition faster
  • To reduce the number of bits needed

Correct Answer: To make valid BCD sum

Detailed Explanation:

  • BCD represents each decimal digit (0-9) with 4 bits (0000 to 1001)
  • When adding two BCD digits, the binary sum might produce values from 1010 to 1111 (10 to 15 in decimal)
  • These values are invalid in BCD because BCD only represents digits 0-9
  • Adding 6 (0110) corrects the sum because:
    • In decimal, when a sum exceeds 9, we carry over to the next digit
    • In 4-bit binary, 6 is the difference between a valid BCD digit and the next valid BCD with carry

Example: 7 + 8 in BCD

   BCD: 0111 (7)
 + BCD: 1000 (8)
 ------------
   Binary sum: 1111 (15 in binary)
   
   But 1111 (15) is invalid in BCD!
   
   Add correction factor 6 (0110):
   1111 (15)
 + 0110 (6)
 ------------
 (1)0101 = 0001 0101
   
   Result: 0001 (1) and 0101 (5) = 15 ✓

Why specifically 6?

  • In 4-bit binary, values 10-15 (1010-1111) are 6 invalid codes
  • Adding 6 skips over these invalid codes to reach the next valid BCD representation with carry
  • 6 = 16 (next valid with carry) - 10 (first invalid value)

BCD Adjustment Rule:

  • If binary sum ≤ 9 (0000-1001): No correction needed
  • If binary sum ≥ 10 (1010-1111): Add 6 (0110) to correct

📝 Key Takeaways

Gray Code

Minimizes errors in state transitions by ensuring only one bit changes at a time.

BCD

Preserves decimal digit structure, making display and decimal arithmetic straightforward.

Hamming Code

Adds redundant parity bits to detect and correct single-bit errors automatically.

Conversion Methods

Binary→Gray: G[i] = B[i] XOR B[i-1]. Gray→Binary: B[i] = G[i] XOR B[i-1]. BCD addition requires +6 correction if result > 9.
