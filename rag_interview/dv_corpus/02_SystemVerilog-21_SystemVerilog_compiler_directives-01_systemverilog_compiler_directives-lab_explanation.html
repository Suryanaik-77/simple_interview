🧭 What this lab is

The reference lab 21_SystemVerilog_compiler_directives.sv builds up a library of macros — plain constants, a string macro, an expression macro, a multi-line macro, and several parameterized macros — while its testbench tb_21_SystemVerilog_compiler_directives.sv layers its own conditional testbench-only macros on top and instantiates eight small demo modules, one per directive category.

💡 The concept

define performs pure text substitution and is global from its point of definition to end-of-compile (or undef) — it is not scoped to a module like a variable would be. ifdef/ifndef/elsif/else/endif conditionally include or exclude source text based on whether a macro name has been defined, which is how debug-only or environment-specific code is toggled without editing the RTL. timescale sets the time unit/precision for delay values in a file. __FILE__ and __LINE__ are predefined macros the preprocessor substitutes with the current filename and line number, useful for self-locating debug/assert messages. Parameterized macros take arguments like a function call but are still textual substitution, so every argument must be individually parenthesized to avoid operator-precedence surprises, and ` performs token-pasting to build new identifier names.

⚙️ How it works

The design file defines simple constants DATA_WIDTH, ADDR_WIDTH, MEM_DEPTH, a string macro DESIGN_NAME, and an expression macro MEM_SIZE that combines MEM_DEPTH and DATA_WIDTH. PRINT_HEADER is a multi-line macro using backslash line-continuation to bundle three $display calls, including one that expands DESIGN_NAME. MAX, MIN, and ABS are parameterized ternary macros, each with every argument individually parenthesized. DEBUG_PRINT(msg) and ASSERT(condition, msg) both use the predefined ` __FILE__ ` and __LINE__ ` macros so failure messages self-report their source location. REG_SLICE(sig, width, offset) wraps the +: indexed part-select syntax, and CDC_SYNC(clk, rst_n, in, out, stages) uses token-pasting to synthesize a new signal name out_sync from the out argument. In the testbench, ifdef TB_VERBOSE ` gates whether LOG(msg) expands to a real $display or to nothing, ifdef TB_CHECK_TIMING ` gates a CHECK_SETUP assertion macro, and TEST_PASS(name)/TEST_FAIL(name) both print a result and increment pass_count/fail_count. The testbench instantiates macro_demo, conditional_compilation_demo, timescale_demo, default_nettype_demo, pragma_demo, predefined_macros_demo, undef_demo, and string_macro_demo, all sharing the clk/rst_n/test_data` signals declared at the top.

🎯 What you'll learn
  • Distinguish define text substitution from a real SystemVerilog parameter` (no type, no scoping, pure text replacement)
  • Use ifdef/ifndef guards to build testbench-only or debug-only code paths that compile out cleanly in production runs
  • Use __FILE__/__LINE__ inside DEBUG_PRINT/ASSERT-style macros to get self-locating diagnostic messages
  • Recognize macro token-pasting (`) as the mechanism for generating new signal/identifier names like out_sync`
  • Remember define is global and order-dependent across the whole compile, including anything pulled in via include, not scoped to the file or module it appears in
⚠️ Common mistakes
  • Assuming a define is scoped to the module or file it's written in, when it is actually visible globally from its definition point onward, including into any file compiled or included afterward
  • Dropping the trailing \ line-continuation character on a multi-line macro like PRINT_HEADER or CDC_SYNC, which silently truncates the macro body at that line
  • Leaving a macro argument un-parenthesized in a parameterized macro (e.g. writing a + b instead of (a) + (b)), which causes operator-precedence bugs once the macro is substituted into a larger expression
