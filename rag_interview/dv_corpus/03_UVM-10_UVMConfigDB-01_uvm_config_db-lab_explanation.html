🧭 What this lab is

The reference lab builds a small testbench (config_pkg.sv includes config_types.sv, simple_transaction.sv, simple_sequence.sv, simple_sequencer.sv, simple_driver.sv, simple_monitor.sv, simple_scoreboard.sv, simple_agent.sv, simple_env.sv) and then config_test.sv walks through uvm_config_db usage step by step, starting with retrieving virtual interfaces and moving into configuration-object propagation and hierarchical scoping.

💡 The concept

uvm_config_db#(T) is a typed, static get/set database keyed by a context component handle, a string inst_path, and a string field_name. Because UVM resolves get() by searching from the calling component's full hierarchical name outward, the path string used in set() must match (or wildcard-match) the path the getter is actually instantiated under. The lab separates two config styles: primitive/virtual-interface values (master_vif, slave_vif) set with a null/empty path from the top for global visibility, and structured config objects (agent_config, env_config) that bundle many related fields into one uvm_object so a whole agent's behavior can be configured with a single set() call.

⚙️ How it works

config_base_test::build_phase first calls uvm_config_db #(virtual simple_if)::get(this, "", "master_vif", master_vif) and the equivalent for slave_vif, each wrapped in an if (!...) check that ` uvm_fatal`s with tag VIF_ERR if the interface was never set — these were originally published from tb_top using a null context and a "*" wildcard path so any component in the hierarchy can find them. The test then moves on to constructing agent_config and env_config objects (declared as master_cfg, slave_cfg, env_cfg). agent_config (in config_types.sv) carries is_active (a uvm_active_passive_enum), data_width, addr_width, fifo_depth, timeout_cycles, the enable_coverage/enable_checks/enable_scoreboard flags, and its own vif handle, with convert2string() and do_print() overridden so the whole config prints as one readable block. env_config holds environment-wide knobs such as num_masters, num_slaves, global_timeout, and verbosity_level, letting the top-level test configure multi-agent topology from one object instead of many scalar set()` calls.

🎯 What you'll learn
  • Matching the context/inst_path/field_name used in set() to the exact instance path the getter resolves from
  • Using null context + wildcard path ("*") to publish a virtual interface globally from tb_top
  • Bundling related knobs into a uvm_object-derived config class (agent_config, env_config) instead of many discrete set() calls
  • Guarding required get() calls with uvm_fatal versus letting optional ones fall back to a default
⚠️ Common mistakes
  • Calling set() after the target component's build_phase has already executed its get() (e.g. in connect_phase), so the value never arrives in time
  • Using an inst_path string that doesn't match the actual instance name given to type_id::create(), causing get() to silently return the default/uninitialized value instead of erroring
