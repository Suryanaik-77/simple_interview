🧭 What this lab is

test.sv (compiled into barrier_pkg via barrier_pkg.sv and exercised by tb_top.sv) walks through every uvm_barrier method with a series of standalone tests, starting with base_test, which forks multiple processes that all call wait_for() on a shared barrier and logs when each process arrives and is released.

💡 The concept

A uvm_barrier is created with new(name), its release point configured with set_threshold(n), and each participating process calls wait_for(), which blocks until exactly n processes have called it, at which point all n are released simultaneously in the same delta/time step. Supporting methods let you introspect and manage the group: get_threshold() reads the configured count, get_num_waiters() reports how many processes are currently blocked, reset() clears the waiter count without changing the threshold, cancel() decrements the waiter count by one (removing a single waiting process without releasing the group), and set_auto_reset(v) controls whether the barrier automatically re-arms itself for reuse after each release (enabled by default).

⚙️ How it works

In base_test::run_phase, a local uvm_barrier br is constructed with br = new("br"), its threshold is set with br.set_threshold(3), and the current value is echoed back through br.get_threshold(). The test then opens a fork...join-style block with three named processes (Process A, B, C) that each delay by a different amount (#5ns, #10ns, …), print an uvm_info message that they have reached the barrier, call br.wait_for(), and print a second message once released — demonstrating that even though the processes arrive at different simulation times, none proceeds past wait_for() until all three (the threshold) have checked in. tb_top.sv is a plain initial block that only prints a banner describing the uvm_barrier API (new, set_threshold, get_threshold, wait_for, get_num_waiters, reset, set_auto_reset, cancel) and lists the available test classes (base_test, basic_barrier_test, threshold_test, num_waiters_test, reset_test, cancel_test, auto_reset_on_test, auto_reset_off_test) that a learner selects via +UVM_TESTNAME.

🎯 What you'll learn
  • How to construct and configure a uvm_barrier with new()/set_threshold() and share it across processes or components
  • Reading barrier state with get_threshold() and get_num_waiters() to reason about synchronization progress
  • Using fork...join alongside wait_for() to make independent processes rendezvous at a common point
  • Understanding the difference between reset() (clear waiters) and cancel() (remove one waiter) and when auto-reset via set_auto_reset() is appropriate for reusable barriers
⚠️ Common mistakes
  • Assuming wait_for() releases as soon as any process calls it, rather than waiting until the full set_threshold() count has checked in
  • Forgetting that a barrier must be shared by reference (e.g., via uvm_config_db) across all participating components — a locally constructed barrier in each component will never see the other processes' calls
