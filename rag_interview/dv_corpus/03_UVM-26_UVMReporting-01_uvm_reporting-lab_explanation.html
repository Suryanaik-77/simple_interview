🧭 What this lab is

The reference lab pairs a small data-class hierarchy in my_pkg.sv (colors, format, my_data, derivative) that exercises UVM's field-automation and do_print() mechanisms, with a minimal tb_top.sv that demonstrates uvm_report_* functions/macros, verbosity levels, and different UVM printers, all wired together via reporting_pkg.sv.

💡 The concept

UVM gives two complementary ways to control what gets printed/reported: (1) uvm_field_* macros inside uvm_object_utils_begin/_end auto-generate print(), copy(), and compare() behavior for the fields you register, and (2) overriding do_print(uvm_printer printer) lets you hand-print things the macros don't cover, such as nested sub-objects. Independently, uvm_report_* functions and the ` uvm_info`/uvm_warning/uvm_error/uvm_fatal macros carry a severity and (for info) a verbosity threshold, and are rendered by a uvm_printer` (table, tree, or line format) whose knobs control layout.

⚙️ How it works

colors registers color and enable with ` uvm_field_int(..., UVM_ALL_ON)` inside uvm_object_utils_begin(colors)/uvm_object_utils_end, so printing a colors object is fully automatic. format registers header, footer, enable, and body the same way, but its rand colors m_color member is deliberately left out of the field macros; instead format overrides virtual function void do_print(uvm_printer printer) and calls printer.print_object("m_color", m_color) to manually add the nested colors object to the printed output. my_data shows the alternate, fully-automated approach: it registers data, addr, and its nested format m_format0 object via uvm_field_object(m_format0, UVM_ALL_ON)`, so no do_print() override is needed. derivative extends my_data and uses uvm_object_utils(derivative)` to demonstrate inheritance with print/reporting. On the reporting side, tb_top.sv imports reporting_pkg (which include`s my_pkg.sv and test_pkg.sv), then simply calls run_test(), which reads +UVM_TESTNAME from the command line and builds/runs the test as uvm_test_top, exercising uvm_report_info/uvm_report_warning functions, the uvm_* `` macros, verbosity levels, and printer types as described in its header comments.

🎯 What you'll learn
  • How ` uvm_field_int`/ uvm_field_object` inside uvm_object_utils_begin/_end` auto-generate print/copy/compare for registered fields
  • When and how to override do_print(uvm_printer printer) to manually print nested objects that field macros don't cover
  • How severity (uvm_info/uvm_warning/uvm_error/uvm_fatal) differs from verbosity (UVM_LOW…UVM_DEBUG) and how each is controlled
  • How different uvm_printer types (table, tree, line) and their knobs change how the same object prints
⚠️ Common mistakes
  • Forgetting to add a nested object to either the field macros (` uvm_field_object`) or a do_print() override — as format does for m_color` — so the child object silently never appears in printed/reported output
  • Assuming a class field is printed automatically just because the class has uvm_object_utils_begin/_end, without checking that the specific field was actually listed with a ` uvm_field_* `` macro
