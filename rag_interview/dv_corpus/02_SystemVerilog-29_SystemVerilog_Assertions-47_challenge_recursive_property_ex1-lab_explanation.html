💡 Why It Matters

Off-by-one and incorrect arithmetic in control logic are common in real designs. Decrement-by-N bugs can cause state machines to skip states or fail termination conditions. SVA properties provide executable documentation that catches such violations at simulation time.

🧠 Knowledge Check

Q1: In a concurrent assertion <code>@(posedge clk) a |-> ##1 b</code>, what does <code>|→</code> mean?

  • a and b must be true simultaneously
  • If a is true, b must be true on the very next cycle (implication)
  • a must be true before b ever becomes true
  • b is disabled until a is seen

|→ is the overlapping implication operator. If the antecedent (a) matches, the consequent (##1 b) must match — b must be true one cycle later.

Q2: An SVA property uses <code>##[1:3] b</code>. When can b be true to satisfy the property?

  • Exactly 1 cycle later
  • Exactly 3 cycles later
  • 1, 2, or 3 cycles later
  • At any future cycle

##[1:3] is a bounded delay range. The property is satisfied if b is true at any clock tick from 1 to 3 cycles after the antecedent matches.

Q3: What is the difference between <code>assert</code> and <code>assume</code> in formal verification?

  • No difference — they are synonyms
  • assert specifies properties to be proven; assume constrains the input space
  • assume is for simulation only; assert is for formal only
  • assert fires on failure; assume fires on success

In formal tools: assume restricts the set of legal inputs (the environment model), while assert specifies the properties the design must satisfy within that constrained space.

Q4: A <code>$rose(sig)</code> expression in an SVA is true when:

  • sig transitions from 0 to 1 at the current clock edge
  • sig has been 1 for at least one full cycle
  • sig is 1 at any point in simulation
  • sig transitions from x to 1

$rose detects a 0→1 (or x/z→1) transition at the current sampled clock edge. It is false if sig was already 1 in the previous cycle.

Q5: If an SVA assertion fails at time T, what does the simulator report by default?

  • A warning that can be ignored
  • An error that halts simulation immediately
  • A failure message; simulation continues unless $fatal is used
  • Nothing — assertion failures are silent unless explicitly enabled

SVA assertion failures emit an error message but simulation continues. To stop on failure use $fatal in the action block: assert (...) else $fatal;
