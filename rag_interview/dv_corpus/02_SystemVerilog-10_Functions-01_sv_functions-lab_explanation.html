🧭 What this lab is

Functions.sv defines functions_pkg, a package containing a spread of function styles—explicit return, implicit return, void, default arguments, ref/inout/output passing, and recursion. tb_Functions.sv exercises these both through a FunctionDemo class and through a function_rtl DUT.

💡 The concept

A SystemVerilog function must return exactly one value (unless declared void), executes in zero time, and can either return a value explicitly or assign to its own name for an implicit return. Arguments can be passed as ref (aliases the caller's variable), output/inout (copied back at function exit), or plain input (copy-in only). Recursive functions must be declared automatic so each call gets its own stack frame instead of sharing static storage, which would corrupt results across nested calls.

⚙️ How it works

add(a,b) uses an explicit return a + b;. multiply(a,b) instead assigns multiply = a * b;, relying on implicit return via the function's own name. display_value(val) is declared function void and only calls $display, returning nothing. power(base, exp = 2) shows a default argument so power(x) implicitly squares x. swap(ref int a, ref int b) is automatic and swaps the caller's variables directly through ref. compute(input int x, output int doubled, inout int accumulated) demonstrates all three non-ref argument directions in one function. factorial(n) and fibonacci(n) are both automatic and call themselves recursively. In tb_Functions.sv, import functions_pkg::*; brings these into scope; a FunctionDemo demo = new(100); object then drives demo.demo_basic(), demo.demo_default_args(), demo.demo_ref_args(), demo.demo_recursive(), demo.demo_array_return(), demo.demo_static_var(), and demo.demo_class_methods() to exercise the package functions from class methods, while a separate function_rtl dut (.*) is driven with a, b, sel over an 8-iteration loop to show functions used inside synthesizable RTL.

🎯 What you'll learn
  • Distinguish implicit return (assigning to the function name) from explicit return
  • Choose the correct argument direction (ref vs input/output/inout) for a given use case
  • Know when automatic is mandatory — specifically for recursive functions like factorial/fibonacci
  • Use default argument values (as in power) to simplify common call sites
⚠️ Common mistakes
  • Forgetting automatic on a recursive function, causing shared static storage to corrupt results across nested calls
  • Confusing ref (a live alias to the caller's variable) with output/inout (values copied back only at function exit)
