🧭 What this lab is

The reference lab centers on the QueueDemo class in SystemVerilog_Queues.sv, which methodically exercises SystemVerilog queue operations, and pairs it with a queue_fifo hardware DUT driven from tb_SystemVerilog_Queues.sv to show queues used both as a software data structure and as the model for a real FIFO.

💡 The concept

A queue is declared with the [$] unbounded dimension (or [$:N] for a bounded queue, as seen with bounded_queue[$:10]), and can hold scalars, strings, or user-defined structs such as the packet_t type from queue_pkg (fields id, data, prio). Queues support literal initialization with '{...} assignment patterns, indexed access including the special $ index for the last element, and a rich method set for adding/removing at either end (push_back/push_front/pop_back/pop_front), inserting or removing at an arbitrary index (insert/delete), and reporting size (size()). Calling delete() with no argument empties the entire queue, which is different from delete(index) removing a single element.

⚙️ How it works

The QueueDemo class declares int_queue[$], str_queue[$], pkt_queue[$] (of type packet_t from queue_pkg), and a bounded bounded_queue[$:10]. Its constructor new() seeds int_queue via '{1, 2, 3, 4, 5}. demo_basic_ops() reassigns int_queue = '{10, 20, 30}, then calls push_back(40), push_front(5), pop_back(), and pop_front() in sequence, printing the queue with %p after each step and reading int_queue[0] and int_queue[$] to show first/last-element access. demo_insert_delete() rebuilds int_queue = '{10, 20, 30, 40, 50}, calls insert(2, 25) to splice a value in the middle, delete(4) to remove a single index, and then copies into a local temp_q[$] to demonstrate that temp_q.delete() (no index) clears the whole queue. On the testbench side, tb_SystemVerilog_Queues instantiates queue_fifo #(.WIDTH(8), .DEPTH(4)) as dut, connected via .* to clk, rst_n, din, dout, wr_en, rd_en, empty, full. After demo runs through demo_basic_ops, demo_insert_delete, demo_slicing, demo_concatenation, demo_bounded, demo_struct_queue, and demo_fifo_lifo, the test_dut_fifo() task drives 5 writes on din/wr_en while printing full, then performs 5 reads via rd_en while printing dout/empty, tying the software queue concepts to an actual hardware FIFO's fill/drain behavior.

🎯 What you'll learn
  • Declaring unbounded ([$]) and bounded ([$:N]) queues, including queues of structs
  • Using push_back/push_front/pop_back/pop_front to treat a queue as a FIFO or LIFO
  • Indexing with [0] and the special [$] for first/last element access
  • Using insert(index, value) and delete(index) for mid-queue edits, versus delete() to clear everything
  • Correlating a software queue model with a real synthesizable FIFO's empty/full handshake signals
⚠️ Common mistakes
  • Assuming push_front/pop_back behave like push_back/pop_front — mixing up which end is being added to or removed from silently reorders data
  • Calling delete(index) when the intent was to clear the whole queue (or vice versa), since delete() with no argument wipes everything
  • Reading/writing queue[$] on an empty queue, which is out-of-bounds and returns the default value instead of erroring loudly
