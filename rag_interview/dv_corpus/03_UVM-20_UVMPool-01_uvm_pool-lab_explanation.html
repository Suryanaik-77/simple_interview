🧭 What this lab is

The reference lab (pool_pkg.sv, tb_top.sv, test.sv) prints an overview of uvm_pool methods and specialized pools, then demonstrates two sharing patterns: synchronizing components via a global uvm_event_pool, and sharing a uvm_pool#(string,int) handle through uvm_config_db.

💡 The concept

uvm_pool mimics an associative array but its real power is the global pool: get_global_pool() (or the shorthand get_global(key) on specialized pools) returns the *same* singleton instance no matter which component calls it, keyed by a string name. This lets unrelated components rendezvous on shared data or events without one holding a reference to the other. Specialized pools like uvm_event_pool, uvm_object_string_pool, and uvm_barrier_pool are pre-typed convenience wrappers around this same mechanism.

⚙️ How it works

event_trigger_comp and event_waiter_comp both call uvm_event_pool::get_global("shared_event") in their run_phase — because both use the identical key "shared_event", they retrieve the same uvm_event handle ev. The trigger component waits trigger_delay (5 time units) then calls ev.trigger(), while the waiter blocks on ev.wait_trigger() until that fires. Separately, data_producer_comp declares uvm_pool#(string, int) data_pool and in build_phase retrieves it via uvm_config_db#(uvm_pool#(string, int))::get(this, "", "data_pool", data_pool), issuing a uvm_fatal if it's missing; in run_phase it calls data_pool.add("sensor_A", 100) to populate the shared pool for a consumer to read.

🎯 What you'll learn
  • How get_global/get_global_pool provide singleton shared storage across components without passing handles explicitly
  • The difference between event-based synchronization (trigger/wait_trigger on a pooled uvm_event) and data sharing via a uvm_config_db-distributed uvm_pool instance
  • The build_phase retrieval pattern with a uvm_fatal guard when a required pool/object isn't found in config_db
⚠️ Common mistakes
  • Calling new() on a pool type instead of get_global_pool(), which silently creates an isolated, empty pool disconnected from the shared one
  • Key typos or case mismatches (e.g. adding under one string and looking up under a slightly different one) causing exists()/get() to silently miss data
