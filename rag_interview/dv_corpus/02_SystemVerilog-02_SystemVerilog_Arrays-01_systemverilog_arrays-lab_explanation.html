🧭 What this lab is

The reference lab (SystemVerilog_Arrays.sv with tb_SystemVerilog_Arrays.sv) defines an arrays_pkg package of array-related types and constants, then a fixed_arrays_demo module that declares a range of fixed-size packed and unpacked arrays — 1D, 2D, and 3D — to illustrate SystemVerilog array declaration styles side by side.

💡 The concept

Packed arrays (declared before the variable name, e.g. logic [3:0][7:0]) are stored as one contiguous bit vector and can be treated as a single word or sliced into sub-fields, which is why packed_word_t is defined as a 32-bit word viewed as 4 bytes. Unpacked arrays (declared after the variable name, e.g. logic [7:0] memory [0:DEPTH-1]) are collections of separately-addressable elements, which is the natural shape for memories, register files, and matrices. Multi-dimensional unpacked arrays simply nest this addressing (matrix[0:3][0:3] for 2D, cube[2][4][4] for 3D), and SystemVerilog offers equivalent declaration syntaxes ([0:DEPTH-1] vs [DEPTH]) for the same range.

⚙️ How it works

arrays_pkg defines byte_t, word_t, and the packed type packed_word_t = logic [3:0][7:0], plus localparams MEM_DEPTH, DATA_WIDTH, and ADDR_WIDTH that size the demo. fixed_arrays_demo imports arrays_pkg::* and declares memory [0:DEPTH-1] as a 1D unpacked register-file-style array, with memory_alt [DEPTH] shown as an equivalent declaration of the same shape. matrix [0:3][0:3] is a 2D unpacked array of bytes, and cube [2][4][4] extends this to 3D. short_array [8] shows a differently-sized element ([15:0]) living alongside the byte-wide arrays. In tb_SystemVerilog_Arrays, the testbench drives dut (an instance of fixed_arrays_demo with DEPTH(16) and WIDTH(8)) and separately exercises array literal initialization via test_array_init [8] = '{8'h10, 8'h20, ..., 8'h80}, along with its own test_matrix [4][4], test_cube [2][3][4], and packed examples packed_word [3:0][7:0] aliased against word_alias [31:0].

🎯 What you'll learn
  • Distinguish packed ([3:0][7:0] before the name) from unpacked ([N] after the name) array declarations and know when each is the right choice
  • Declare and index 1D, 2D, and 3D fixed-size unpacked arrays such as memory, matrix, and cube
  • Use SystemVerilog array literal syntax ('{...}) to initialize an array like test_array_init
  • Recognize equivalent range syntaxes for the same array shape, e.g. [0:DEPTH-1] vs [DEPTH] as seen in memory vs memory_alt
⚠️ Common mistakes
  • Confusing packed and unpacked declaration order (putting the dimension after the name when a contiguous packed vector like packed_word_t was intended, or vice versa)
  • Assuming [0:DEPTH-1] and [DEPTH] declarations differ in indexing behavior when they describe the same range, as shown by memory vs memory_alt
