🧠 Knowledge Check

Q1: A constraint block says <code>x inside {[10:20]}</code>. What values can x take?

  • Only 10 and 20
  • 10, 15, and 20 only
  • Any integer from 10 to 20 inclusive
  • Any real number between 10 and 20

inside with a range selects any integer value within the closed interval [10, 20].

Q2: What does <code>rand_mode(0)</code> do to a rand variable?

  • Forces it to randomize to 0
  • Disables randomization — the variable keeps its current value
  • Sets its distribution weight to 0
  • Removes the constraint on that variable

rand_mode(0) disables randomization for the variable. It retains its current value on subsequent randomize() calls until re-enabled.

Q3: Which is NOT a valid way to add an inline constraint in SystemVerilog?

  • obj.randomize() with { x > 5; }
  • obj.randomize(x) with { x > 5; }
  • constraint c { x > 5; } declared inside the randomize() call
  • All of the above are valid

You cannot declare a named constraint block inside a randomize() call. Inline constraints use the with { ... } syntax only.

Q4: A <code>randc</code> variable cycles through all values before repeating. What is its distribution within one full cycle?

  • Uniform random with replacement
  • Cyclic — each value appears exactly once per cycle
  • Weighted by constraint density
  • Gaussian around the midpoint

randc (random-cyclic) permutes all possible values in a random order, guaranteeing each value appears exactly once per cycle. This eliminates repeats within a cycle.

Q5: Constraints A and B are both active. A says <code>x < 10</code>; B says <code>x > 15</code>. What does randomize() return?

  • randomize() returns 1 and picks x = 12
  • randomize() returns 0 — constraint conflict
  • randomize() throws a fatal error
  • Behaviour is simulator-dependent

When constraints are contradictory (no solution exists) randomize() returns 0 (failure) and the variables retain their pre-call values. Always check the return value.
