🧭 What this lab is

A request/grant handshake whose correctness is checked by bound SystemVerilog Assertions, run dynamically under VCS -assert svaext. It shows how a failing assertion is read and traced back to the RTL.

💡 What this is

An implication assertion passes vacuously whenever its antecedent never holds, so a green assertion may have tested nothing. This group pairs a req|=>gnt assertion with a cover of the antecedent to prove the pass is meaningful, then breaks the design so the assertion genuinely fails.

🔧 The properties
a_ack:    req |=> gnt          // grant follows request
a_nospur: gnt |-> $past(req)    // no grant without a request
+ one concept-specific property for this group
🎯 What you'll learn
  • Read a VCS SVA failure and map it to the offending property
  • Trace an assertion failure back to the RTL cause
  • Run assertions dynamically with -assert svaext
🔧 Key constructs
assert property|=>cover propertyvacuityVCS -assert
🧰 Tool & files

Engine: VCS -assert svaext (dynamic SVA). Files: adbg_vacuity.sv (design), adbg_vacuity_props.sv (bound SVA), tb_adbg_vacuity.sv, run.sh. A cover property (c_reqgrant) proves the request-then-grant scenario is really exercised, so a_ack is a meaningful (non-vacuous) pass.
