🧭 What this lab is

24_Named_Blocks_Statement_Labels.sv is a multi-module reference file where each module isolates one aspect of named blocks: basic naming/local variables, disable-based early termination, labeled statements, disabling tasks, fork-join with named blocks, hierarchical access, and scope/lifetime rules. tb_24_Named_Blocks_Statement_Labels.sv instantiates all of them and adds its own nested-disable and loop-control tests.

💡 The concept

A named block such as begin : main_block acts like a mini scope: variables declared inside it (e.g. int local_var;) live only for that block's execution and are not visible outside it, while the block itself can be referenced by name from a disable statement or a hierarchical path. disable <name> terminates that block immediately, including any statements or nested named blocks still executing inside it — this is what makes named blocks useful for early-exit search patterns and cancellable sequences, as opposed to plain unnamed begin-end groups which cannot be targeted this way.

⚙️ How it works

In basic_named_block_demo, the initial begin : main_block process declares local_var, sets it to 42, then opens begin : nested_block which declares its own nested_var and can still read the outer main_block's local_var — but nested_var goes out of scope once nested_block ends. In disable_statement_demo, initial begin : search_block runs a loop over index i against data and is expected to call disable search_block once found is set, terminating the search early rather than scanning to completion. The testbench tb_24_Named_Blocks_Statement_Labels instantiates u_basic, u_disable, u_labels (labeled_statements_demo), u_disable_task (disable_task_demo), u_fork (fork_join_named_demo), u_hier (hierarchical_access_demo), and u_scope (scope_and_lifetime_demo), then in initial begin : tb_main forks its own test_nested_disable() and test_loop_controls() tasks. test_nested_disable nests begin : level_1 → begin : level_2 → begin : level_3, and after level_3 runs for 10 time units it calls disable level_2, which tears down both level_2 and the still-running level_3 inside it, demonstrating that disabling an outer named block also kills everything nested within it.

🎯 What you'll learn
  • Declare block-local variables inside begin : name ... end : name so they don't pollute the enclosing scope
  • Use disable <block_name> to implement early-exit search/scan patterns instead of flags plus break
  • Understand that disabling an outer named block also terminates any named blocks nested inside it
  • Recognize that a variable is only reachable via a hierarchical path (e.g. dut.block.subblock.var) if it is actually declared inside that named block
⚠️ Common mistakes
  • Assuming a variable declared at module or task scope can be hierarchically referenced through a named block it merely executes inside, rather than one it is actually declared in
  • Disabling the wrong named block in a nested hierarchy (e.g. disabling an inner block when the intent was to unwind several levels, or vice versa as seen in test_nested_disable's disable level_2)
