🧭 What this lab is

The reference lab's base_test (in test.sv, packaged via clp_pkg.sv and run from tb_top.sv) is an orientation exercise: it fetches the CLP singleton and prints a guided tour of the available methods and UVM's built-in plusargs rather than parsing a specific custom argument.

💡 The concept

uvm_cmdline_processor follows the singleton pattern — there is exactly one instance for the whole simulation, obtained via the static get_inst() method, so any component can query the same command-line state. Once you have the handle, methods like get_args(), get_plusargs(), and get_uvmargs() return whole argument lists, while get_arg_value()/get_arg_values() and get_arg_matches() let you search for and extract specific arguments or families of arguments (e.g. everything matching a wildcard/regex). This complements, rather than replaces, native SystemVerilog $test$plusargs/$value$plusargs.

⚙️ How it works

tb_top.sv first prints a reference banner describing the CLP API and UVM's built-in arguments (+UVM_TESTNAME, +UVM_VERBOSITY, +UVM_TIMEOUT, +UVM_CONFIG_DB_TRACE) before run_test() executes. clp_pkg.sv pulls in uvm_pkg, the UVM macros, and test.sv. In test.sv, base_test extends uvm_test and declares a uvm_cmdline_processor clp handle. Its build_phase calls clp = uvm_cmdline_processor::get_inst() to grab the singleton. run_phase then raises an objection and uses ` uvm_info ` calls to walk through each CLP method (get_inst(), get_args(), get_plusargs(), get_uvm_args(), get_arg_value(), get_arg_values()`) as a printed reference rather than exercising them against real arguments.

🎯 What you'll learn
  • Retrieve the CLP singleton correctly with uvm_cmdline_processor::get_inst()
  • Distinguish between get_args(), get_plusargs(), and get_uvmargs() for different argument scopes
  • Understand that get_arg_value()/get_arg_values() write the parsed string into an output argument rather than returning it directly as the value
⚠️ Common mistakes
  • Treating the integer/bit returned by get_arg_value() as the parsed value itself instead of using the out string argument it fills in
  • Forgetting the required + prefix on plusarg-style names passed to CLP query methods
