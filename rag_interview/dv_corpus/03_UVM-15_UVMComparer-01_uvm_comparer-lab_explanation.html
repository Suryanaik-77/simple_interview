🧭 What this lab is

The reference lab is a documentation-style walkthrough (test.sv, tb_top.sv) that doesn't drive an active comparison scenario but instead prints out, phase by phase, every key uvm_comparer variable and method so a learner can see the full API surface before touching buggy code.

💡 The concept

uvm_comparer centralizes the policy for how uvm_object::compare() behaves: policy selects UVM_DEEP (recurse into nested objects), UVM_SHALLOW (compare top-level fields, nested objects by reference), or UVM_REFERENCE (handles only); show_max bounds how many miscompares get printed; verbosity and sev control how those miscompare messages are reported; abstract/physical filter which UVM_ABSTRACT/UVM_PHYSICAL-tagged fields participate; and check_type verifies the two objects share the same get_type_name(). After a compare, miscompares holds a human-readable diff string and result holds the running miscompare count (which must be reset before reuse).

⚙️ How it works

comparer_pkg pulls in transaction.sv and test.sv under one package. tb_top (in tb_top.sv) just imports comparer_pkg and prints a structured reference of the uvm_comparer variables (policy, show_max, verbosity, sev, abstract, physical, miscompares, check_type, result) and methods (compare_field, compare_field_int, compare_field_real, compare_string, compare_object, print_msg). base_test in test.sv extends uvm_test, registers with uvm_component_utils, and in end_of_elaboration_phase calls uvm_top.print_topology(). Its report_phase emits a matching summary of the same uvm_comparer variables/methods via uvm_info calls at UVM_NONE, reinforcing the API before the learner moves to the buggy exercises that actually exercise compare().

🎯 What you'll learn
  • Reading and configuring the core uvm_comparer knobs (policy, show_max, sev, verbosity) before calling compare()
  • Understanding that compare()'s return value only tells you match/no-match, while cmp.result gives the actual miscompare count
  • Recognizing how uvm_field_int/uvm_object_utils_begin-generated automation drives what compare() actually checks
⚠️ Common mistakes
  • Assuming a uvm_comparer object doesn't need explicit configuration — the UVM defaults (e.g. show_max) can silently truncate reported miscompares
  • Confusing compare()'s boolean return with the detailed mismatch count in cmp.result, and not resetting cmp.result between reuses
