🧭 What this lab is

The reference lab builds a small phase_agent (driver + monitor + sequencer) inside phase_env, with every phase method overridden to log $time and get_full_name() so the learner can watch the actual build-then-connect order happen live in the transcript.

💡 The concept

UVM phases fall into two groups: the function phases that execute instantaneously at time 0 in a strict order (build_phase top-down, connect_phase bottom-up, end_of_elaboration_phase bottom-up, start_of_simulation_phase bottom-up), and the task phase run_phase which runs in zero time relative to phase order but consumes simulation time and executes in parallel across all components, kept alive only as long as at least one component has an outstanding objection via phase.raise_objection/drop_objection. Top-down construction guarantees a parent exists before it builds its children; bottom-up connection guarantees a child's ports/exports are fully built before its parent tries to wire them together.

⚙️ How it works

In phase_agent::build_phase, driver, monitor, and sqr (a uvm_sequencer#(phase_item)) are all created with type_id::create(...) — this runs top-down, so phase_agent's own build_phase fires before phase_driver's and phase_monitor's. In phase_agent::connect_phase, driver.seq_item_port.connect(sqr.seq_item_export) wires the driver to the sequencer, and the driver's analysis port is connected into the monitor's internal FIFO — this only works because connect_phase runs bottom-up, so by the time the agent connects things, driver and monitor have already finished their own connect_phase. At the env level, phase_env::build_phase creates agent and scoreboard, and phase_env::connect_phase wires agent.monitor.mon_ap to scoreboard.analysis_imp, completing the driver → monitor → scoreboard analysis chain. phase_env also overrides end_of_elaboration_phase and start_of_simulation_phase purely to log entry, reinforcing that these are bottom-up function phases distinct from connect_phase.

🎯 What you'll learn
  • Trace the actual top-down vs bottom-up firing order using $time/get_full_name() logging rather than just memorizing it
  • Know that TLM connections (seq_item_port.connect, analysis port connects) belong in connect_phase, never build_phase, because children must exist first
  • Recognize that uvm_sequencer#(phase_item) and driver/monitor are all created via type_id::create inside build_phase, not new()
⚠️ Common mistakes
  • Trying to connect driver.seq_item_port to sqr.seq_item_export inside build_phase, before sqr is guaranteed to exist
  • Omitting super.build_phase(phase) / super.connect_phase(phase) calls, which silently breaks base-class bookkeeping (e.g. config propagation) even though nothing crashes immediately
