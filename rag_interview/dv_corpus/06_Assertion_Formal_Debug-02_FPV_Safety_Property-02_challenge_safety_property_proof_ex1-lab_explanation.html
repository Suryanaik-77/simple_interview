🧭 What this challenge is

The same safety invariant, but the counter saturates at 15 instead of 12, so the invariant count <= 12 is violated.

💡 The property being violated

The safety property asserts an invariant: on every reachable state the count never exceeds 12. Formal proves this with no reachable counterexample.

assert property (count <= 12);   // safety invariant - must hold on every reachable state
🛠️ Debugging Guide
🔴 Symptom - what JasperGold reports

JasperGold returns a counterexample for a_bound: a reachable trace drives count to 13, 14, or 15.

🔎 How to investigate
  1. Read the CEX value of count.
  2. Open fpv_safety.sv and read the saturation guard.
  3. Compare the guard limit to the asserted invariant (count <= 12).
🧭 Fix direction

Change the guard from count < 4'd15 to count < 4'd12 so the counter saturates at the invariant bound.

✅ How to confirm your fix

Re-run ./run.sh; JasperGold should report the property proven (or the cover covered) with no counterexample, and the lab ends with RESULT: TEST PASSED.
