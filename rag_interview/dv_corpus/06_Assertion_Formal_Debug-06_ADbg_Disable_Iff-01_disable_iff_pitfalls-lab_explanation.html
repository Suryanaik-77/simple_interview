🧭 What this lab is

A request/grant handshake whose correctness is checked by bound SystemVerilog Assertions, run dynamically under VCS -assert svaext. It shows how a failing assertion is read and traced back to the RTL.

💡 What this is

disable iff (rst) aborts an assertion while reset holds, so the checker does not fire spuriously during reset. This group shows the interplay: a_ack/a_nospur are guarded by disable iff, while a_reset verifies the reset behaviour they depend on.

🔧 The properties
a_ack:    req |=> gnt          // grant follows request
a_nospur: gnt |-> $past(req)    // no grant without a request
+ one concept-specific property for this group
🎯 What you'll learn
  • Read a VCS SVA failure and map it to the offending property
  • Trace an assertion failure back to the RTL cause
  • Run assertions dynamically with -assert svaext
🔧 Key constructs

🧰 Tool & files

Engine: VCS -assert svaext (dynamic SVA). Files: adbg_disable.sv (design), adbg_disable_props.sv (bound SVA), tb_adbg_disable.sv, run.sh. An extra assertion a_reset (no disable iff) checks the reset behaviour the disable iff clause on the other assertions relies on.
