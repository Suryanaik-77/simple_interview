🧭 What this lab is

The reference lab (queue_pkg.sv, tb_top.sv, test.sv) prints a summary of uvm_queue methods from tb_top and then defines a family of tests (base_test, basic_queue_test, push_pop_test, insert_delete_test, get_size_test, global_queue_test) plus a producer_comp/consumer_comp pair that demonstrate creating, filling, and sharing an uvm_queue.

💡 The concept

uvm_queue#(T) behaves like a dynamic array that also exposes queue semantics: push_back/push_front add at either end, pop_back/pop_front remove and return from either end, and insert/delete operate at an arbitrary index. Because it is a uvm_object handle, passing it around means passing a reference, not a copy. On top of instance methods, uvm_queue exposes static class methods, get_global_queue() (returns a single shared queue instance for that type T) and get_global(index) (reads directly from that shared instance), letting unrelated components exchange data without an explicit handle or port connection.

⚙️ How it works

In test.sv, producer_comp::run_phase obtains the shared queue with q = uvm_queue#(string)::get_global_queue(), then builds it up with q.push_front("Rock"), q.push_back("Scissor"), and q.insert(1, "Paper"), logging the resulting q.size(). consumer_comp::run_phase first reads an item directly via the static accessor uvm_queue#(string)::get_global(1) (no queue handle needed), then also fetches the queue handle via get_global_queue() and calls q.pop_front(), q.delete(1), and q.pop_back() in sequence, logging the queue's size() before/after the delete. queue_pkg.sv simply ` include`s test.sv into the package, and tb_top.sv prints the full list of uvm_queue methods (new, size, get, insert, delete, push_back, push_front, pop_back, pop_front, get_global, get_global_queue`) as a reference before test selection.

🎯 What you'll learn
  • Distinguishing instance methods (push_back, pop_front, insert, delete) from the static global-queue accessors (get_global, get_global_queue)
  • How components can share state through a global uvm_queue instance without explicit TLM connections
  • How push/pop ordering (front vs back) determines FIFO vs LIFO retrieval, and how insert/delete shift indices
⚠️ Common mistakes
  • Calling pop_back() when FIFO (first-in-first-out) order is intended, retrieving the most recently pushed item instead of the oldest
  • Assuming get_global_queue() returns a fresh queue per call/component instead of the single shared instance, which breaks the intended producer/consumer sharing
