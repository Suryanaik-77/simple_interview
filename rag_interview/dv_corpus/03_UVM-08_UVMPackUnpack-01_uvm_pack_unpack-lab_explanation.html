🧭 What this lab is

The reference lab's pack_demo_test (in pack_test.sv, run via pack_pkg) walks through six demo functions in its run_phase — demo_field_macro_pack(), demo_pack_variants(), demo_do_pack_callback(), demo_nested_object_pack(), demo_dynamic_array_pack(), and demo_common_pitfalls() — each showing a different facet of UVM pack/unpack using the transaction classes defined in pack_item.sv.

💡 The concept

Field automation macros like uvm_field_int and uvm_field_enum register each field with the UVM factory so that pack()/unpack(), copy(), compare(), and print() all work for free without hand-written code — this is Method 1. Method 2, the recommended approach for performance and precision, overrides do_pack(uvm_packer packer)/do_unpack(uvm_packer packer) directly and calls packer methods (e.g. pack_field_int, unpack_field_int) in an explicit, matching order with explicit bit widths. Both approaches must call super.do_pack(packer)/super.do_unpack(packer) first so inherited fields are handled, and the pack order in do_pack must exactly mirror the unpack order in do_unpack with identical bit widths, or the deserialized object silently ends up with wrong field values instead of an error.

⚙️ How it works

demo_field_macro_pack() creates a SimpleTransaction (txn_orig), randomizes it — constrained by valid_burst_c (burst_len inside {[1:16]}) and valid_be_c (byte_enable != 0) — then calls txn_orig.pack(packed_bits) to serialize it into a dynamic bit array and reports packed_bits.size()/num_bits. SimpleTransaction registers its fields (address, data, byte_enable, operation typed as the mem_op_t enum, burst_len) with uvm_field_int/uvm_field_enum inside uvm_object_utils_begin/_end, so pack()/unpack() work automatically without any custom code. The file comments indicate later classes use the do_pack()/do_unpack() hook approach (Method 2) for a more complex transaction, plus demonstrate pack_object()/unpack_object() for nested objects and the rule that dynamic arrays must have their size packed before their contents — these are exercised by demo_do_pack_callback(), demo_nested_object_pack(), and demo_dynamic_array_pack() respectively, with demo_common_pitfalls() intentionally illustrating mistakes such as order/width mismatches.

🎯 What you'll learn
  • Choosing between field-automation macros (Method 1) and explicit do_pack/do_unpack callbacks (Method 2) for serialization
  • Keeping do_pack field order and bit widths exactly mirrored in do_unpack
  • Always calling super.do_pack()/super.do_unpack() first when overriding these callbacks
  • Packing a dynamic array's size before its contents so unpack knows how many elements to read
  • Using pack_object()/unpack_object() to serialize nested uvm_object fields
⚠️ Common mistakes
  • Overriding do_pack() or do_unpack() and forgetting the super.do_pack(packer)/super.do_unpack(packer) call, silently dropping base-class fields
  • Packing fields in one order in do_pack but unpacking them in a different order (or with a mismatched bit width like packing crc as 8 bits but unpacking as 16), which corrupts every field read after the mismatch
