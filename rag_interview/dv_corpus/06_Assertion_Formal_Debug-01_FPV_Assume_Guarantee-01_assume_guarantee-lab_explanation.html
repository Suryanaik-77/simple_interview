🧭 What this lab is

A small accumulator whose output bound (count never exceeds 10) can be proven by formal only because an assumption constrains its input step. It shows how assume and assert split a proof into environment and guarantee.

💡 The concept

In formal, assume properties constrain the environment (legal inputs) while assert properties are the guarantees the tool must prove for all reachable states. Here assume(step<=1) is exactly what makes the guarantee assert(count<=10) provable - drop it and step could be 3, overshooting the bound.

🔧 The property under proof

The guarantee assert (count never exceeds 10) is provable only because the environment assumption constrains step to at most 1.

assume property (step <= 1);
assert property (count <= 10);   // holds only under the assume
⚙️ The formal flow

run.sh calls JasperGold in batch on prove.tcl, which analyzes the design plus the bound property file, elaborates, declares the clock and reset, and proves all properties unbounded.

jg -batch -tcl prove.tcl
  analyze -sv fpv_assume.sv fpv_assume_props.sv
  elaborate -top fpv_assume
  clock clk ; reset rst ; prove -all
🎯 What you'll learn
  • Distinguish an assume (input constraint) from an assert (guarantee)
  • See how an over-strong or missing assume changes what is provable
  • Read a JasperGold proven/cex result and map it to the property
🧰 Tool & files

Engine: JasperGold (Synopsys VC Formal via ./run.sh vcf). Files: fpv_assume.sv (design), fpv_assume_props.sv (SVA, bound), prove.tcl, run.sh.
