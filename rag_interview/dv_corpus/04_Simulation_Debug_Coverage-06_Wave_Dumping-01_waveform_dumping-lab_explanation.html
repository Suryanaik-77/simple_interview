🧭 What this lab is

A self-checking counter that writes a real VCD waveform each run. It shows how to capture and read a waveform - the primary medium for functional debug - and keep the file manageable.

⚙️ How it runs

VCS simulates the design; the testbench calls $dumpfile/$dumpvars to record signal activity into dump.vcd, which you open in GTKWave, Verdi, or DVE. The run also self-checks so guided passes and buggy variants fail.

🎯 What you'll learn
  • Enable a VCD dump at runtime and confirm it was produced
  • Read a waveform to correlate a signal with its driver
  • Trace a functional or X bug in the waveform back to the RTL

🧰 Tool & files

Engine: VCS; waveform via $dumpfile/$dumpvars (VCD, viewable in GTKWave/Verdi/DVE). Files: wave_dump.sv, tb_wave_dump.sv, run.sh. This group dumps the entire hierarchy so any signal can be inspected after the run.
