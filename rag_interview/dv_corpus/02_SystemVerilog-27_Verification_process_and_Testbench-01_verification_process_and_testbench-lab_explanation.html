🧭 What this lab is

The reference lab builds a layered testbench around a simple synchronous FIFO (fifo_dut), using an SV interface (fifo_if) to bundle the push/pop/data signals and a fifo_base_test class to drive the overall test sequence from the top-level module tb_27_Verification_process_and_Testbench.

💡 The concept

A layered testbench separates concerns: the DUT is wrapped by an interface that carries clock-synchronous signals, a driver converts high-level transactions into pin wiggles on that interface, a monitor passively samples the interface to reconstruct transactions, and a scoreboard/checker compares observed behavior against a reference model. This separation lets stimulus generation, protocol-level driving, and checking evolve independently, and is what makes constrained-random and coverage-driven verification practical at scale.

⚙️ How it works

fifo_dut implements a parameterized (DATA_WIDTH, DEPTH) synchronous FIFO with wr_ptr/rd_ptr pointers, full/empty/count status outputs, and push/pop handshake inputs. The fifo_if interface (parameterized the same way, clocked by clk/rst_n) exposes push, pop, data_in, data_out so the testbench never wires DUT ports directly. In tb_27_Verification_process_and_Testbench, a clk generator toggles every CLK_PERIOD/2, a reset process pulses rst_n low for 5 cycles, and vif (an instance of fifo_if) is connected straight into the fifo_dut instance dut — e.g. .push(vif.push), .data_in(vif.data_in). The test itself is kicked off through a fifo_base_test handle (test), keeping the top-level module thin: its job is only clock/reset generation and instantiation, while stimulus and checking logic live in the class hierarchy.

🎯 What you'll learn
  • How an interface decouples testbench code from DUT port wiring
  • How to structure clock/reset generation separately from stimulus classes
  • How a base test class is used to encapsulate the overall verification sequence
  • Why FIFO status signals (full, empty, count) need to be checked alongside data correctness
⚠️ Common mistakes
  • Driving push/pop combinationally instead of synchronizing to posedge clk, causing races with the DUT's always_ff block
  • Forgetting to respect full/empty before issuing push/pop, which silently drops or under-reads data with no error until a scoreboard mismatch appears
