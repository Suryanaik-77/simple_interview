🧭 What this lab is

The reference lab (resource_pkg.sv including resource_types.sv, timing_config.sv, simple_monitor.sv, simple_driver.sv, simple_scoreboard.sv, priority_checker.sv, simple_agent.sv, simple_env.sv, resource_test.sv) builds a small testbench where resource_demo_test walks through the major uvm_resource_db APIs step by step in build_phase, and PriorityChecker demonstrates reading back a value that was set with override/priority semantics.

💡 The concept

uvm_resource_db#(T) stores values in a global pool keyed by (scope, name) within the type-T-specific pool. set() adds/updates a resource at default priority; set_override() (and the by-name/by-type override variants) raises its priority so it wins over a plain set() at the same scope/name. Scope strings support globbing ("*" matches everything), so a resource set at scope "*" is visible to reads from any actual component scope. read_by_name/read_by_type copy the value directly into a variable, whereas get_by_name/get_by_type return a resource *handle* for inspection; write_by_name/write_by_type update an existing resource's value; dump() prints the entire pool contents, which is invaluable for debugging scope/type mismatches.

⚙️ How it works

resource_demo_test::build_phase calls demo_basic_set(), demo_priority_override(), demo_feature_flags(), and demo_scoped_resources() before constructing env (a SimpleEnv) — deliberately setting resources *before* the environment (and its sub-components) are built, since uvm_resource_db lookups happen when the reading component's build_phase runs. demo_basic_set() calls uvm_resource_db#(int)::set("*", "watchdog_timeout", 10000, this), using the wildcard scope "*" so any component can retrieve it later, and passing this as the accessor for audit-trail purposes. PriorityChecker::build_phase then calls uvm_resource_db#(int)::read_by_name(get_full_name(), "priority_value", value, this), using its own get_full_name() as the read scope and logging the outcome through uvm_info with the "PRIO" id, printing either the retrieved value or a not-found message.

🎯 What you'll learn
  • the precedence difference between plain set() and set_override()/set_override_name()/set_override_type()
  • that each uvm_resource_db#(T) parameterization is a separate, type-isolated pool
  • how scope wildcarding ('*' vs get_full_name()) determines which components can see a resource
  • passing an accessor (this) into set()/read_by_name() for audit/debug traceability
  • using dump() to inspect the live resource pool when a lookup doesn't behave as expected
⚠️ Common mistakes
  • setting a resource as one type (e.g. string) and reading it back with a different type parameter (e.g. #(int)), which silently fails to match instead of erroring
  • calling set() when set_override() was intended, then being confused why a later 'higher priority' value doesn't win
  • hardcoding a scope string that doesn't correspond to the actual component's get_full_name(), instead of relying on the hierarchical scope
