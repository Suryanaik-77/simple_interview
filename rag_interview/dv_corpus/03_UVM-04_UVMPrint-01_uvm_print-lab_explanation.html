🧭 What this lab is

The reference lab's print_demo_test runs through a sequence of demo functions that each illustrate one facet of UVM printing, starting with memory_transaction, a transaction built entirely from field automation macros, and contrasting it with incomplete_txn, which registers with the factory but omits field macros.

💡 The concept

UVM's field automation macros (uvm_field_int, uvm_field_enum, uvm_field_string, uvm_field_sarray_int, etc.) placed inside uvm_object_utils_begin/end automatically wire up print(), copy(), compare(), and pack() for each listed field, including per-field radix flags like UVM_HEX or UVM_DEC. Fields left out of the macro block are invisible to these built-in operations even though the class itself is still factory-registered via uvm_object_utils. print() writes directly to the log using the default (or a supplied) uvm_printer policy, while sprint() returns the same formatted output as a string instead of printing it, and a custom convert2string() can be overridden to produce a compact single-line summary.

⚙️ How it works

memory_transaction (in print_item.sv) declares address, data, op_type, burst_len, tag_name, and the payload[8] byte array, each registered inside uvm_object_utils_begin(memory_transaction) ... uvm_object_utils_end with macros such as uvm_field_int(address, UVM_ALL_ON | UVM_HEX) and uvm_field_enum(operation_t, op_type, UVM_ALL_ON). Its valid_burst_c constraint ties op_type == BURST to a legal burst_len range. In print_test.sv, print_demo_test::demo_field_macro_printing() creates a memory_transaction via memory_transaction::type_id::create, randomizes it with an inline with { op_type == WRITE; burst_len == 0; } constraint, and calls txn.print() to show that every macro-registered field appears automatically. By contrast, incomplete_txn only carries ` uvm_object_utils(incomplete_txn)` with no field macros, so its print() output is minimal — this is flagged directly in the source as // PROBLEM: Only registers with factory, no field macros!. The whole file set is stitched together by print_pkg, which include`s print_item.sv before print_test.sv` so base transaction classes are defined before the test that instantiates them.

🎯 What you'll learn
  • How field automation macros (uvm_field_int, uvm_field_enum, uvm_field_string, uvm_field_sarray_int) drive automatic print/copy/compare
  • The difference between factory registration alone (uvm_object_utils) and full field registration (uvm_object_utils_begin/end with field macros)
  • How print(), sprint(), and convert2string() differ in output destination and formatting
  • Using radix/property flags like UVM_HEX, UVM_DEC, and UVM_ALL_ON to control per-field print formatting
⚠️ Common mistakes
  • Registering a class with uvm_object_utils for factory creation but forgetting to list fields with uvm_field_* macros, producing near-empty print() output (as seen in incomplete_txn)
  • Assuming print() and sprint() are interchangeable, when sprint() must be captured/used explicitly since it returns a string rather than emitting to the log
