🧭 What this lab is

The reference lab SystemVerilog_Processes.sv defines a ProcessDemo class whose tasks - demo_fork_join, demo_fork_join_any, demo_fork_join_none, and (driven from tb_SystemVerilog_Processes) demo_wait_fork, demo_disable_fork, demo_labeled_disable, demo_process_class, demo_process_sync - each isolate one process-control idiom, while the testbench also exercises a process_control_demo module's with_timeout and parallel_stimulus tasks.

💡 The concept

A fork...join block spawns each begin...end (or statement) as its own concurrent process and the surrounding code only continues once ALL of them finish. join_any instead continues as soon as the FIRST branch completes, leaving the others still running unless explicitly killed. join_none returns control to the caller immediately, spawning the branches purely in the background. disable fork terminates every descendant process of the process that calls it (not just the ones textually inside the nearest fork block), which is why it is normally paired with join_any to clean up the losing branches of a race. A process class handle (via process::self()) additionally lets code query or kill a specific process rather than an entire fork group.

⚙️ How it works

In demo_fork_join, three begin...end blocks (Process A, B, C) delay #10, #20, #15 respectively; because the task uses join, "All processes complete" only prints after all three finish, at $time = 20. In demo_fork_join_any, a Slow process (#30) and a Fast process (#10) are forked with join_any, so execution resumes right after the Fast process finishes at $time = 10, and the immediately following disable fork kills the still-running Slow process before it can print "Slow process done". In demo_fork_join_none, two background processes (#10 and #20 delays) are spawned with join_none, so the task moves straight to $display("...continuing..."), then does its own #5 delay and prints "Main thread continues working" - well before either background process has completed. Finally, tb_SystemVerilog_Processes also calls dut.with_timeout(100, "TestOp") and dut.parallel_stimulus() on the process_control_demo module instance dut, applying the same fork-join ideas at the module level alongside clk/rst_n.

🎯 What you'll learn
  • choosing join vs. join_any vs. join_none for concurrent stimulus and monitors
  • using disable fork after join_any to clean up the losing branch of a race
  • reading $time-stamped $display output to verify the true interleaving/completion order of forked processes
⚠️ Common mistakes
  • assuming join_none processes finish before the next line executes, when demo_fork_join_none shows 'Main thread continues working' printing before either background process (#10 or #20) has completed
  • calling disable fork after join_any and assuming it only kills the branches in that specific fork block, when it actually terminates every descendant process of the calling process
