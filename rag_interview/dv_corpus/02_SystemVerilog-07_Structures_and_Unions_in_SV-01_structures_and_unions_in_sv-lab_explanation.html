🧭 What this lab is

Structures_and_Unions_in_SV.sv defines struct_union_pkg with unpacked, nested, and packed structs plus a packed union and a tagged union, and tb_Structures_and_Unions_in_SV.sv exercises them through a StructUnionDemo class before driving instruction_t transactions into a struct_processor DUT.

💡 The concept

The package contrasts unpacked structs (axi_txn_t, point_t/circle_t) — convenient record types for testbench bookkeeping but not directly castable to a flat bit vector — with packed structs (instruction_t, cache_line_t) whose fields are laid out MSB-first over a fixed bit width so they can be assigned to and from plain logic buses. word_view_t then shows a packed union: raw, instr, an anonymous halves struct, and a bytes array all overlay the same 32 bits, so writing through one member and reading through another reinterprets the bits instead of copying them. tagged_value_t goes further with a union tagged, where None/Integer/Float/Bits carry a runtime tag so only the active member can be legally read, giving type safety a plain packed union lacks.

⚙️ How it works

In tb_Structures_and_Unions_in_SV, StructUnionDemo demo is constructed and its demo_unpacked_struct, demo_nested_struct, demo_packed_struct, demo_packed_union, demo_tagged_union, demo_comparison, and demo_struct_functions methods are called in sequence to demonstrate each struct/union flavor from struct_union_pkg. The test_processor task then builds an instruction_t instr using the assignment-pattern syntax '{opcode: 8'h00, rs: 4'h0, rt: 4'h0, rd: 4'h0, immediate: 12'h123}, relies on instruction_t being packed so instr can be assigned straight into the 32-bit instr_in port, pulses valid_in for one clock, and prints result two clocks later after driving it into the struct_processor dut.

🎯 What you'll learn
  • differentiate packed struct (bit-vector castable) from unpacked struct (record-only) assignment rules
  • use a packed union like word_view_t to view one bit vector as raw/instr/halves/bytes without copying
  • build struct literals with assignment-pattern syntax '{field: value, ...}' as done for instruction_t
  • reason about tagged unions (tagged_value_t) for type-safe variant data versus plain packed unions
⚠️ Common mistakes
  • assigning a struct literal that doesn't specify every field, or specifies one with the wrong width, and getting unexpected X's after packing
  • forgetting that packed union members (raw/instr/halves/bytes in word_view_t) share the same storage, so writing one member silently changes what every other member reads
  • treating an unpacked struct (axi_txn_t, circle_t) as if it could be directly assigned to/from a flat logic vector the way instruction_t can
