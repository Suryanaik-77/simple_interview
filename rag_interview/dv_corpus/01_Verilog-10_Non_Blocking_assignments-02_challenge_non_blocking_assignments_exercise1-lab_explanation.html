💡 Why It Matters

Mixing blocking (=) and non-blocking (<=) assignments in the same always block breaks simulation determinism and leads to race conditions. Real designs require consistent assignment types in synchronous logic to ensure proper pipeline behavior and predictable data flow.

🧠 Knowledge Check

Q1: Given two concurrent always blocks both triggered at posedge clk: Block A does <code>a <= b</code>; Block B does <code>b <= a</code>. What happens?

  • a and b both get b's old value
  • a gets b's old value and b gets a's old value — a swap
  • Race condition — undefined result
  • Only one assignment executes

Non-blocking assignments read RHS values in the active region (before any NBA updates). Both blocks see the old values of a and b, then both updates are scheduled. This correctly models a register swap.

Q2: A non-blocking assignment <code>q <= d</code> in an always_ff block. When is q actually updated?

  • Immediately when the statement is reached
  • At the end of the current time step in the NBA region
  • At the next posedge clk
  • When the always block exits

The RHS (d) is evaluated immediately but the LHS (q) is not written until the NBA (Non-Blocking Assignment update) region at the end of the current time step.

Q3: Why do non-blocking assignments prevent the classic 'shift-register race'?

  • They are faster and execute before blocking assignments
  • All RHS values are sampled before any LHS is updated, so each stage reads the previous stage's old value
  • They introduce a one-cycle delay automatically
  • They disable delta-cycle propagation

In a shift register chain, each stage reads its input in the active region. Since no LHS is written until the NBA region, every stage sees the old values — exactly modelling D flip-flop behaviour.

Q4: What value does <code>$display</code> print immediately after <code>q <= 5</code> in the same time step?

  • 5
  • The old value of q
  • x
  • 0

$display runs in the active region. The NBA update hasn't happened yet, so q still holds its old value when displayed.

Q5: Non-blocking assignments can appear in which block type without causing warnings in most lint tools?

  • always_comb
  • always_ff
  • initial
  • Both always_comb and initial

always_ff is specifically for clocked sequential logic where non-blocking assignments belong. Using <= in always_comb is a common mistake that lint tools flag.
