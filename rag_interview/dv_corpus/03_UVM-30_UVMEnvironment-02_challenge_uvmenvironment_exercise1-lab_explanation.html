Buggy Exercise
🧭 What this challenge is

A my_env that correctly builds agt and scb in build_phase but never wires them together — the scoreboard is left completely disconnected from the agent's monitor.

💡 The concept being tested

This tests whether the learner understands that a uvm_env's core job is integration: building sub-components is only half the job, connect_phase must stitch their TLM ports together or downstream components never receive any data.

🛠️ Debugging Guide
🔴 Symptom — what you see when you run it

The simulation runs and the DUT computes correct sums (driver/monitor still function), but the scoreboard reports 0 transactions checked instead of the expected 8 — the self-check fails because nothing ever reaches scb.

🔎 How to investigate
  1. Look at my_env's build_phase — confirm both agt and scb are created via ::type_id::create.
  2. Now look at connect_phase — is there any line connecting agt.mon.ap to anything on scb?
  3. Compare against the guided env_pkg.sv, which has exactly one integration line in connect_phase.
  4. Check whether my_scoreboard even has an unconnected imp sitting idle — that's the receiving end waiting for a publisher.
🧭 Fix direction

In my_env::connect_phase, add the missing analysis port connection from the agent's monitor to the scoreboard's imp — mirroring agt.mon.ap.connect(scb.imp) from the guided example.

✅ How to confirm your fix

Re-run the simulation and check that the scoreboard's transaction count reaches 8 (matching the 8 items generated by add_sequence), with no unchecked/missing-transaction errors.
