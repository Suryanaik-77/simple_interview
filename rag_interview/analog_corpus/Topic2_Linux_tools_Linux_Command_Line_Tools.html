📝 Part 1: Gvim Editor - Your Power Tool for Code Editing

Understanding the vi Family: vi, vim, and Gvim

Before diving into Gvim, it's important to understand the evolution and relationship between these editors:

Editor Full Name Description Key Features
vi Visual Editor Original Unix text editor created in 1976 Basic, available on all Unix/Linux systems, lightweight
vim Vi IMproved Enhanced version of vi with additional features Syntax highlighting, multi-level undo, plugins, macros
Gvim Graphical Vim GUI version of vim with mouse support Menus, toolbars, better font rendering, clipboard integration

When to use vi

  • Working on minimal systems
  • Quick edits on remote servers
  • Guaranteed availability on any Unix/Linux system

When to use vim

  • Advanced editing tasks
  • Working in terminal environments
  • Need syntax highlighting and plugins
  • SSH sessions to remote machines

When to use Gvim

  • Local development work
  • Prefer graphical interface
  • Need mouse support for selection
  • Working with multiple files in tabs

For VLSI Engineers: While all three editors share the same core commands, we'll focus on Gvim in this module because:

  • Better visualization of complex Verilog/VHDL code with syntax highlighting
  • Easier navigation through large design files with mouse support
  • Tab interface for working with multiple related files simultaneously
  • All vim commands work in Gvim, making skills transferable to terminal vim

Note: Everything you learn in Gvim applies directly to vim in terminal mode!

What is Gvim?

Gvim (Graphical Vim) is the GUI version of Vim, one of the most powerful text editors for programmers and engineers. It's particularly valuable in VLSI design because:

  • Opens extremely large files (multi-megabyte log files) instantly
  • Provides syntax highlighting for Verilog, VHDL, and other HDLs
  • Supports powerful search and replace with regular expressions
  • Offers modal editing for maximum efficiency
  • Available on all Linux systems used for VLSI design

🔍 Part 2: Advanced grep with Wildcards

Building on Basic grep

In previous modules, we covered basic grep usage for simple pattern matching. Now, we'll explore advanced features that make grep incredibly powerful for VLSI design work.

Quick Recap: Basic grep searches for patterns in files: grep "pattern" filename

Wildcards and Special Characters

Wildcards allow you to match multiple variations of patterns:

Wildcard Meaning Example Matches
. Any single character cl.ck clock, clack, cl0ck
* Zero or more of previous clk* cl, clk, clkk, clkkk
+ One or more of previous clk+ clk, clkk, clkkk
? Zero or one of previous clk? cl, clk
^ Start of line ^module Lines starting with "module"
$ End of line endmodule$ Lines ending with "endmodule"
[abc] Any character in brackets clk[0-3] clk0, clk1, clk2, clk3
[^abc] Any character NOT in brackets clk[^0-9] clk followed by non-digit

Essential grep Options for VLSI Work

Common grep Options
# Case-insensitive search
grep -i "error" synthesis.log

# Search recursively through directories
grep -r "module" ./rtl/

# Show line numbers
grep -n "always @" counter.v

# Show only filenames with matches
grep -l "ERROR" *.log

# Show lines that DON'T match
grep -v "WARNING" synthesis.log

# Count matching lines
grep -c "flip_flop" design.v

# Show context (lines before and after match)
grep -A 3 "Critical Path"  # 3 lines after
grep -B 2 "ERROR"          # 2 lines before
grep -C 2 "WARNING"        # 2 lines before and after

# Use extended regex (ERE)
grep -E "clk|reset" design.v

# Multiple patterns
grep -e "ERROR" -e "FATAL" simulation.log

# Whole word match
grep -w "clk" design.v     # Won't match "clk_div"

Advanced Wildcard Patterns for VLSI

Finding Signal Declarations

Searching for Wire/Reg Declarations
# Find all wire declarations
grep "wire" design.v

# Find wire declarations with wildcards
grep "wire.*clk" design.v              # Any wire with "clk" in name

# Find specific bit-width wires
grep "wire \[.*:.*\]" design.v         # All multi-bit wires
grep "wire \[7:0\]" design.v           # Exactly 8-bit wires
grep "wire \[[0-9]*:0\]" design.v      # Any wire from [N:0]

# Find register declarations
grep "reg \[.*\].*;" design.v

# Find both wire and reg
grep -E "(wire|reg)" design.v

Module and Port Searching

Finding Modules and Instantiations
# Find module definitions
grep "^module" *.v                     # Lines starting with "module"

# Find module instantiations
grep "counter.*(" testbench.v          # Counter instantiations

# Find input/output ports
grep -E "^\s*(input|output)" design.v  # All I/O declarations
grep "input.*clk" *.v                  # All clock inputs

# Find parameterized modules
grep "parameter.*=" *.v

# List all module names in a directory
grep -h "^module" *.v | awk '{print $2}'

Error and Warning Hunting

Analyzing Log Files
# Find all errors (case-insensitive)
grep -i "error" synthesis.log

# Find errors with line numbers and context
grep -n -C 2 -i "error" synthesis.log

# Find specific error types
grep "Error-.*" synthesis.log          # Errors with codes
grep "Error: Unresolved" synthesis.log # Unresolved references

# Exclude common warnings you don't care about
grep "WARNING" synthesis.log | grep -v "lint"

# Find timing violations
grep -E "(slack|violation)" timing.rpt
grep "slack.*-[0-9]" timing.rpt        # Negative slack only

# Count different message types
grep -c "ERROR" synthesis.log
grep -c "WARNING" synthesis.log
grep -c "INFO" synthesis.log

# Find all unique error messages
grep "ERROR" synthesis.log | sort -u

Recursive Directory Searches

Searching Entire Project Hierarchies
# Search all Verilog files in project
grep -r "module" ./rtl/

# Find which files instantiate a specific module
grep -r "counter_module" ./rtl/ -l

# Find all files with a specific pattern and show filenames
grep -rn "parameter WIDTH" ./rtl/

# Search multiple patterns across project
grep -r -E "(error|warning|critical)" ./logs/

⚙️ Part 3: awk - Pattern Scanning and Processing Language

What is awk?

AWK is a powerful text processing language particularly suited for working with structured data. It excels at:

  • Processing column-based data (reports, CSV files, etc.)
  • Extracting specific fields from text
  • Performing calculations on data
  • Generating formatted reports

Why awk for VLSI? VLSI tool reports are often structured with columns (timing data, cell areas, power consumption). AWK makes extracting and analyzing this data trivial.

Basic awk Syntax

AWK Structure and Basic Usage
# Basic syntax
awk 'pattern { action }' filename

# Print entire file
awk '{print}' file.txt

# Print specific column (default delimiter is whitespace)
awk '{print $1}' file.txt              # First column
awk '{print $2}' file.txt              # Second column
awk '{print $NF}' file.txt             # Last column

# Print multiple columns
awk '{print $1, $3}' file.txt          # Columns 1 and 3
awk '{print $1 " " $3}' file.txt       # With custom separator

# Print all columns
awk '{print $0}' file.txt

AWK Built-in Variables

Variable Meaning Example
$0 Entire line print $0
$1, $2, $3... First, second, third field print $1
NF Number of fields in current line print NF
NR Current line number print NR
FS Field separator (default: whitespace) FS=","
OFS Output field separator OFS=" | "
RS Record separator (default: newline) RS=";"
FILENAME Current filename being processed print FILENAME

Pattern Matching in awk

Conditional Processing
# Print lines containing pattern
awk '/ERROR/ {print}' synthesis.log
awk '/ERROR/' synthesis.log            # Short form

# Print lines NOT containing pattern
awk '!/WARNING/' synthesis.log

# Match specific column
awk '$1 == "ERROR" {print}' log.txt    # First column equals "ERROR"
awk '$3 > 100 {print}' data.txt        # Third column > 100

# Multiple conditions
awk '$1 == "ERROR" && $2 > 50 {print}' log.txt
awk '$1 == "ERROR" || $1 == "FATAL" {print}' log.txt

# Regular expression in specific field
awk '$2 ~ /clk/ {print}' signals.txt   # Second field contains "clk"
awk '$2 !~ /test/ {print}' signals.txt # Second field doesn't contain "test"

# Range patterns
awk '/START/,/END/ {print}' file.txt   # Lines between START and END

AWK for VLSI Design Tasks

Parsing Synthesis Reports

Extracting Data from Reports
# Example report format:
# Cell          Count    Area       Power
# NAND2         125      0.56       0.23
# NOR2          89       0.52       0.21
# DFF           256      1.20       0.45

# Extract cell names and counts
awk 'NR > 1 {print $1, $2}' cell_report.txt

# Find cells with count > 100
awk 'NR > 1 && $2 > 100 {print $1, $2}' cell_report.txt

# Calculate total area
awk 'NR > 1 {sum += $3} END {print "Total Area:", sum}' cell_report.txt

# Find cell with maximum area
awk 'NR > 1 {if($3 > max){max=$3; cell=$1}} END {print cell, max}' cell_report.txt

# Calculate average power
awk 'NR > 1 {sum += $4; count++} END {print "Avg Power:", sum/count}' cell_report.txt

Timing Report Analysis

Analyzing Timing Data
# Example timing report:
# Path                          Slack      Required    Actual
# FF1/Q -> FF2/D                0.523      10.000     9.477
# FF2/Q -> FF3/D                -0.234     10.000     10.234
# FF3/Q -> FF4/D                0.112      10.000     9.888

# Find paths with negative slack (timing violations)
awk 'NR > 1 && $2 < 0 {print $1, $2}' timing.rpt

# Count timing violations
awk 'NR > 1 && $2 < 0 {count++} END {print "Violations:", count}' timing.rpt

✏️ Part 4: sed - Stream Editor for Text Transformation

What is sed?

SED (Stream EDitor) is a powerful tool for filtering and transforming text. It's particularly useful for:

  • Find and replace operations across files
  • Deleting specific lines or patterns
  • Inserting or appending text
  • Automating repetitive text modifications

sed vs. awk vs. grep:

  • grep: Finding patterns (read-only)
  • sed: Transforming text (find & replace)
  • awk: Processing structured data (extract & calculate)

Basic sed Syntax

SED Command Structure
# Basic syntax
sed 'command' filename

# Common pattern
sed 's/old/new/' filename             # Substitute (first occurrence)
sed 's/old/new/g' filename            # Substitute (all occurrences)

# Modify file in-place
sed -i 's/old/new/g' filename         # Linux

# Create backup before modifying
sed -i.bak 's/old/new/g' filename     # Creates filename.bak

# Process multiple files
sed -i 's/old/new/g' *.v

# Print only modified lines
sed -n 's/old/new/p' filename

SED Substitution (s command)

Basic Substitution

Find and Replace Patterns
# Replace first occurrence on each line
sed 's/clk/clock/' design.v

# Replace all occurrences (global)
sed 's/clk/clock/g' design.v

# Replace only on specific line
sed '5s/clk/clock/g' design.v         # Line 5 only
sed '10,20s/clk/clock/g' design.v     # Lines 10-20

# Replace only Nth occurrence
sed 's/clk/clock/2' design.v          # 2nd occurrence on each line

# Case-insensitive substitution
sed 's/error/ERROR/gi' log.txt        # g=global, i=case-insensitive

Using Different Delimiters

Alternative Delimiters for Paths
# Standard delimiter (/)
sed 's/old/new/g' file.txt

# When path contains slashes, use different delimiter
sed 's|/home/user/old|/home/user/new|g' paths.txt
sed 's#/usr/local#/opt/local#g' paths.txt
sed 's@old@new@g' file.txt

# Useful for file paths in scripts
sed 's|/old/path/to/files|/new/path/to/files|g' config.txt

Regular Expressions in sed

Pattern Matching with Regex
# Match word boundaries
sed 's/\bclk\b/clock/g' design.v      # Only whole word "clk"

# Match beginning of line
sed 's/^module/MODULE/g' design.v

# Match end of line
sed 's/;$/;;/g' design.v

# Match any character
sed 's/clk./clock_/g' design.v

# Match multiple characters
sed 's/clk[0-9]/clock_&/g' design.v   # & represents matched text

# Match optional characters
sed 's/clk\?/clock/g' design.v

# Match one or more
sed 's/clk\+/clock/g' design.v

SED for VLSI Design Tasks

Renaming Signals

Signal Name Modifications
# Simple rename
sed -i 's/old_signal/new_signal/g' design.v

# Rename with pattern
sed -i 's/clk_\([0-9]\)/clock_\1/g' design.v    # clk_1 -> clock_1

# Change port names in module instantiation
sed -i 's/\.clk(\(.*\))/\.clock(\1)/g' design.v

# Rename multiple signals
sed -i -e 's/rst/reset/g' -e 's/clk/clock/g' design.v

Log File Processing

Filtering and Modifying Logs
# Extract only error lines
sed -n '/ERROR/p' simulation.log

# Remove all warning lines
sed '/WARNING/d' simulation.log

# Remove lines matching pattern
sed '/lint/d' synthesis.log

# Remove lines between patterns
sed '/START_DEBUG/,/END_DEBUG/d' log.txt

# Add timestamp prefix to each line
sed 's/^/[2024-01-15] /' log.txt

# Extract lines 100-200
sed -n '100,200p' large_file.log

# Print every 10th line
sed -n '1~10p' file.txt

Batch File Modifications

Modifying Multiple Files
# Update parameter in all files
sed -i 's/parameter WIDTH = 8/parameter WIDTH = 16/g' *.v

# Change all wire declarations to logic
sed -i 's/\bwire\b/logic/g' *.sv

# Add header to all files
sed -i '1i\// Generated by synthesis tool' *.v

# Update module instances
sed -i 's/old_module/new_module/g' *.v

# Remove specific lines from all files
sed -i '/FIXME/d' *.v

Advanced SED Commands

Line Operations

Deleting, Inserting, Appending
# Delete specific lines
sed '5d' file.txt                     # Delete line 5
sed '5,10d' file.txt                  # Delete lines 5-10
sed '/pattern/d' file.txt             # Delete lines matching pattern
sed '1d' file.txt                     # Delete first line (header)
sed '$d' file.txt                     # Delete last line

# Insert line before
sed '5i\This is inserted text' file.txt
sed '/pattern/i\New line' file.txt

# Append line after
sed '5a\This is appended text' file.txt
sed '/pattern/a\New line' file.txt

# Replace entire line
sed '5c\New line content' file.txt
sed '/pattern/c\Replacement line' file.txt

# Print specific lines
sed -n '5p' file.txt                  # Print line 5
sed -n '5,10p' file.txt               # Print lines 5-10
sed -n '/pattern/p' file.txt          # Print matching lines

❓ Check Your Understanding

1. In Gvim Normal mode, which command deletes from the cursor to the end of the line?

  • a) dd
  • b) d$
  • c) dw
  • d) D

Explanation: d$ deletes from cursor to end of line. dd deletes entire line, dw deletes word, D also deletes to end of line (same as d$).

2. What does this grep command do: grep -rn "^module" ./rtl/ --include="*.v"

  • a) Finds all lines containing "module" anywhere in Verilog files
  • b) Recursively finds lines starting with "module" in .v files with line numbers
  • c) Finds module definitions but excludes line numbers
  • d) Only searches the current directory for modules

Explanation: -r = recursive, -n = show line numbers, ^ = start of line, --include="*.v" = only .v files.

3. What is the output of: awk '{print $NF}' file.txt

  • a) First field of each line
  • b) Last field of each line
  • c) Number of fields in each line
  • d) All fields except the first

Explanation: $NF represents the last field. NF is "Number of Fields", so $NF gets the value of that field.

4. Which sed command replaces all occurrences of "wire" with "logic" in a file?

  • a) sed 's/wire/logic/' file.v
  • b) sed 's/wire/logic/g' file.v
  • c) sed 'wire/logic' file.v
  • d) sed -r 'wire' 'logic' file.v

Explanation: The 'g' flag means "global" - replace all occurrences on each line. Without 'g', only the first occurrence is replaced.

5. What does this awk command calculate: awk '{sum += $2} END {print sum/NR}' data.txt

  • a) Total sum of the second column
  • b) Average of the second column
  • c) Number of records in the file
  • d) Maximum value in the second column

Explanation: It sums column 2, then divides by NR (Number of Records/lines) to get the average.

6. In Gvim, what does the command :%s/clk/clock/gc do?

  • a) Replace "clk" with "clock" globally without confirmation
  • b) Replace only the first occurrence on each line with confirmation
  • c) Replace all occurrences in the entire file with confirmation for each
  • d) Count how many times "clk" appears in the file

Explanation: % = entire file, g = global (all occurrences), c = confirm each replacement.

7. Which grep option shows 3 lines after each match?

  • a) grep -B 3
  • b) grep -A 3
  • c) grep -C 3
  • d) grep -n 3

Explanation: -A = After, -B = Before, -C = Context (both before and after), -n = show line numbers.

8. What does this sed command do: sed -n '10,20p' file.txt

  • a) Deletes lines 10 to 20 from the file
  • b) Prints only lines 10 to 20 from the file
  • c) Replaces lines 10 to 20 with new content
  • d) Prints all lines except 10 to 20

Explanation: -n suppresses automatic printing, and '10,20p' prints only lines 10 through 20. This is useful for viewing specific sections of large files.
