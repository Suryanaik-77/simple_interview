Problem Statement

GUIDED

You are working on synthesizing a digital design using Cadence Genus. The top-level module is top_design, which instantiates several hierarchical submodules.

When you run script, the synthesis script executes elaborate, then runs check_design -unresolved and writes the result to reports/check_design.rpt. This report is your primary debug signal. Open it first after every run:

cat reports/check_design.rpt

The report shows a structured summary. The critical line is Unresolved References:

 Check Design Report (c)
 -------------------

 Summary
 -------

              Name                       Total
----------------------------------------------
Unresolved References                        2
Empty Modules                                0
Unloaded Port(s)                             0
Unloaded Sequential Pin(s)                   0
Unloaded Combinational Pin(s)                0
...
  Done Checking the design.

The check_unresolved proc reads this count, sees it is non-zero, and calls exit 1 — stopping the flow before wasting time on syn_generic, syn_map, and syn_opt.

Your task: Fix both missing references so that reports/check_design.rpt shows Unresolved References 0. One issue is a missing RTL source file; the other is a missing standard cell library. Use the log to identify which specific modules are missing, then fix and re-run.

Note: During elaborate, Genus may also print TUI-273 warnings in the log — one per unresolved module. These are useful for identifying module names, but the structured count in check_design.rpt is the definitive pass/fail signal.

🔌 The Debug Flow: run → check_design.rpt → log → Fix

Every unresolved reference issue in Genus follows the same three-stage debug loop. Internalise this — you will use it in every synthesis run:

①
check_design.rpt — your primary signal

After every run, open reports/check_design.rpt first. The script runs check_design -unresolved automatically after elaborate and writes this report. Find the line Unresolved References N — that number is your scoreboard. If N > 0, the flow exits early. Track this number down to 0 as you fix each issue.

②
Log investigation — identify which modules are missing

Once the report shows a non-zero count, grep the log to find the specific module names: grep -i "unresolved" | logs/genus_synthesis.log. Use the names to determine the fix: a plain Verilog name → add .v to read_hdl; a cell name with a vendor suffix → add .lib to set_db link_library.

③
Fix & Re-run — one issue type at a time

Apply the correct fix, then re-run make run and return to step ① — read check_design.rpt again. Repeat until Unresolved References reaches 0.

🔍 Analysis

The reports/check_design.rpt for this testcase shows Unresolved References 2. Grepping the log reveals two specific missing names — one is a plain Verilog module and one is a standard cell:

  • Missing module: memory_controller
    The name memory_controller does not match any library cell naming pattern — it is a plain Verilog module name. This means its .v source file was never passed to read_hdl. The file exists on disk; it was simply omitted from inputs/file_list.tcl.
    Fix type: add memory_controller.v to the read_hdl list.
  • Missing cell: CKBD8BWP40P140LVT
    The BWP40P140LVT suffix is a TSMC standard cell naming pattern. LVT means Low Threshold Voltage. The current set_db link_library only loads the HVT and SVT library files — the LVT library directory is missing entirely from set_db init_lib_search_path.
    Fix type: add the LVT .lib path to set_db init_lib_search_path, set_db target_library, and set_db link_library.

Both issues must be fixed before check_design.rpt can show Unresolved References 0 and synthesis can proceed to syn_generic.

📝 Step-by-Step Solution

  • Step 1 — Navigate and run the synthesis flow

    Set up the lab and run script to observe the failures first-hand:

    cd ~/pd/labs/SYN-CDN-URR/TC-SYN-CDN-URR-GD-001

    The run will stop early. Internally, script calls genus -files scripts/genus_syn.tcl. The script reads the file list, calls elaborate, then runs check_design -unresolved which writes reports/check_design.rpt. The check_unresolved proc reads the report, sees a non-zero count, and exits with an error. Open the report to find out how many references are unresolved.

  • Step 2 — Open reports/check_design.rpt: read the unresolved reference count

    The script already ran check_design -unresolved and wrote the report. Open it now — this is the first thing to check after every run:

    cat reports/check_design.rpt

    You will see the full summary table. The critical line is Unresolved References:

     Check Design Report (c)

 Summary

----------------------------------------------
Unresolved References                        2
Empty Modules                                0
Unloaded Port(s)                             0

...
  Done Checking the design.

    Unresolved References 2 tells you there are exactly two issues to fix. This number is your progress tracker — you will check it after every fix until it reads 0.

  • Step 3 — Grep the log to identify the specific missing module names

    The report told you how many references are unresolved. Now grep the log to find out which module names are missing:

    grep -i "unresolved" | logs/genus_synthesis.log

    Look at the module names returned to determine the fix type:

    memory_controller        # plain Verilog module name  →  fix: add .v to read_hdl
CKBD8BWP40P140LVT        # TSMC cell with LVT suffix   →  fix: add LVT .lib to link_library

    The log search tells you which modules are missing — the report already told you how many.

  • Step 4 — Debug Issue 1: identify the missing RTL file

    memory_controller is a Verilog module name — Genus looked through all files in the read_hdl list and did not find a module memory_controller declaration. Check the current file list:

    cat inputs/file_list.tcl

    You will see:

    read_hdl {/proj1/pd/users/testcase/Bharath/AI_test/MVP_test/data_processing_unit.v \
/proj1/pd/users/testcase/Bharath/AI_test/MVP_test/interface_controller.v \
/proj1/pd/users/testcase/Bharath/AI_test/MVP_test/top_design.v}

    Problem identified: memory_controller.v is missing from the list. Verify the file exists on disk:

    ls /proj1/pd/users/testcase/Bharath/AI_test/MVP_test/ | grep memory_controller

    If it prints memory_controller.v, the file is present — it was simply omitted from file_list.tcl.

  • Step 5 — Fix Issue 1: add the missing file to file_list.tcl

    Edit inputs/file_list.tcl to include memory_controller.v:

    read_hdl {/proj1/pd/users/testcase/Bharath/AI_test/MVP_test/data_processing_unit.v \
/proj1/pd/users/testcase/Bharath/AI_test/MVP_test/interface_controller.v \
/proj1/pd/users/testcase/Bharath/AI_test/MVP_test/top_design.v \
/proj1/pd/users/testcase/Bharath/AI_test/MVP_test/memory_controller.v}

    Save the file. On the next run, elaborate will find the memory_controller definition — the unresolved reference count in reports/check_design.rpt will drop by one, from 2 to 1.

Next: With the missing RTL file fixed, we now debug Issue 2. CKBD8BWP40P140LVT is a standard cell name — Genus searched all .lib files in set_db link_library and did not find it. We need to add the LVT library to the script's set_db variables.

  • Step 6 — Debug Issue 2: identify the missing library

    CKBD8BWP40P140LVT is a Low Threshold Voltage (LVT) standard cell — identifiable by the LVT suffix in its name. Open the synthesis script and review the current library configuration:

    cat scripts/genus_syn.tcl

    The relevant section:

    # CURRENT CONFIGURATION (Incomplete)
set_db init_lib_search_path [list . ../../pdk/stdcells/9T/hvt/lib/nldm \
                                       ../../pdk/stdcells/9T/svt/lib/nldm]

set_db target_library [list tcbn28hpcplusbwp40p140hvtssg0p81vm40c.lib \
                             tcbn28hpcplusbwp40p140ssg0p81vm40c.lib]

set_db link_library   [list tcbn28hpcplusbwp40p140hvtssg0p81vm40c.lib \
                             tcbn28hpcplusbwp40p140ssg0p81vm40c.lib]

    Problem identified: The LVT library directory (9T/lvt/lib/nldm) is absent from init_lib_search_path, and the LVT .lib file is missing from both target_library and link_library. During elaborate, Genus searched only the HVT and SVT libraries — there was no LVT library loaded at all.

  • Step 7 — Fix Issue 2: add LVT library to the set_db variables

    Edit scripts/genus_syn.tcl to add the LVT library path and .lib file to all three variables:

    # CORRECTED CONFIGURATION
set_db init_lib_search_path [list . ../../pdk/stdcells/9T/hvt/lib/nldm \
                                       ../../pdk/stdcells/9T/svt/lib/nldm \
                                       ../../pdk/stdcells/9T/lvt/lib/nldm]

set_db target_library [list tcbn28hpcplusbwp40p140hvtssg0p81vm40c.lib \
                             tcbn28hpcplusbwp40p140ssg0p81vm40c.lib \
                             tcbn28hpcplusbwp40p140lvtssg0p81vm40c.lib]

set_db link_library   [list tcbn28hpcplusbwp40p140hvtssg0p81vm40c.lib \
                             tcbn28hpcplusbwp40p140ssg0p81vm40c.lib \
                             tcbn28hpcplusbwp40p140lvtssg0p81vm40c.lib]

    Three additions are required:

    • init_lib_search_path — tells Genus where to look for the LVT .lib file on disk
    • target_library — makes LVT cells available for gate mapping during syn_map
    • link_library — makes LVT cell definitions visible to elaborate so it can resolve CKBD8BWP40P140LVT

  • Step 8 — Re-run and confirm the report is clean

    Both issues are now fixed. Re-run the synthesis flow:

    make run

    Open the report immediately after the run — this is your primary confirmation:

    cat reports/check_design.rpt

    The critical line must now show:

    Unresolved References                        0

    With the report clean, confirm the full synthesis completed:

    • The check_unresolved proc prints INFO: No Unresolved References. Proceeding with synthesis...
    • Synthesis proceeds through syn_generic → syn_map → syn_opt
    • Gate-level netlist is written to outputs/

📝 Knowledge Assessment

1. After running the script then it stops early, what is the first file to open to determine how many unresolved references exist?

  • logs/genus_synthesis.log — grep for error messages
  • reports/check_design.rpt — read the Unresolved References count
  • scripts/genus_syn.tcl — review the library configuration
  • inputs/file_list.tcl — count the files in the read_hdl list
Correct! reports/check_design.rpt is the primary debug signal. The script runs check_design -unresolved automatically after elaborate and writes this structured report. The Unresolved References line gives you the exact count — your scoreboard. Go to the log only if you need to identify which specific module names are missing.

2. What does the Unresolved References line in reports/check_design.rpt represent?

  • The number of timing violations in the synthesized netlist.
  • The count of module or cell instantiations that Genus could not match to a definition in read_hdl or set_db link_library during elaborate.
  • The number of empty modules with no logic inside them.
  • The number of ports that are unconnected in the top-level design.
Correct! Each entry in the Unresolved References count represents a module or cell that was instantiated somewhere in the design hierarchy but whose definition was not found — either because the .v file was missing from read_hdl, or because the .lib file was missing from set_db link_library. This count must reach 0 before synthesis can produce a correct netlist.

3. Why must the LVT library be added to both set_db target_library and set_db link_library?

  • They are identical — updating one automatically updates the other in Genus.
  • link_library is used by elaborate to resolve cell references; target_library is used by syn_map to choose cells during mapping. Both must know about LVT cells for the full flow to work.
  • Only link_library is needed; target_library only affects hold-time optimization.
  • Only init_lib_search_path needs updating — Genus auto-populates target_library and link_library from the search path.
Correct! set_db link_library makes the LVT cell definition visible to elaborate, resolving the TUI-273 warning. set_db target_library makes the LVT cell available as a mapping target during syn_map. Without both, either elaboration fails or the mapper cannot use LVT cells even if elaboration succeeds.

4. After fixing inputs/file_list.tcl, why must you re-run the full synthesis flow rather than just re-running check_design in the existing Genus session?

  • Genus requires a server reboot after every file change.
  • elaborate built the design hierarchy from the files that were loaded at that point. The new file was not included, so the hierarchy is incomplete. Re-running check_design in the same session still queries the stale hierarchy — you must restart Genus and re-run read_hdl + elaborate to rebuild it with the new file.
  • Genus automatically reloads all files whenever check_design is invoked.
  • The file list change only takes effect after the Tcl session is saved to disk.
Correct! The design hierarchy is built during elaborate. Any files not present when elaborate ran are not part of that hierarchy — no subsequent command in the same session can add them. The only way to incorporate the fix is to restart Genus and let read_hdl + elaborate re-run from scratch.
