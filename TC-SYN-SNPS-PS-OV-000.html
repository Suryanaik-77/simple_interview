📖 Theory and Background

What is Physical Synthesis?

Traditional logic synthesis takes RTL source files, a technology library, and timing constraints, then maps the design to a gate-level netlist. It optimises for timing, area, and power — but it has no knowledge of where cells will actually be placed on silicon or how far wires will need to travel.

At advanced process nodes (28 nm and below), this is a serious problem. Wire delay and placement-driven parasitics can account for 30–60% of total path delay. A netlist that closes timing in logic synthesis may still fail after place-and-route because the tool estimated wire delays using simplified wire-load models instead of real routing distances.

Physical synthesis solves this by incorporating an early floorplan of the design into the synthesis session. DC loads the floorplan DEF, creates a physical library (NDM) from standard cell LEF data, and uses TLU+ parasitic models to estimate real wire RC delays during compilation. The result is a netlist that is far more placement-friendly and requires far fewer PnR iterations to close timing.

Additional Inputs for Physical Synthesis

Beyond the standard logic synthesis inputs, physical synthesis requires three additional files:

Input What it provides
NDM Physical Library (.ndm) New Data Model library built from standard cell LEF data. Contains physical dimensions, pin locations, and obstruction layers for every cell. Allows the tool to understand cell geometry and estimate placement distance during synthesis.
TLU+ Parasitic Models (.tluplus) Table look-up parasitic models derived from the foundry process. The max file (rcworst corner) gives worst-case wire RC; the min file (rcbest corner) gives best-case conditions. Together they replace simple wire-load models with real interconnect delay estimates.
Floorplan DEF (.def) Design Exchange Format file from an early floorplanning session. Contains die area, core boundary, placement blockages, and pre-placed macros. Gives the tool the spatial context it needs for physically-aware optimisation.

The SPG Flow

The key difference between logic synthesis (Lab 30) and this lab is enabling SPG (Synthesis with Physical Guidance). The flow stages are:

Stage What it does in SPG mode
Load Libraries Same as logic synthesis: standard cell and macro timing libraries are loaded.
Create Physical Library An NDM database is built from the technology file and reference NDM libraries. This is the physical database used internally during SPG compilation.
Load TLU+ Models RC extraction tables are loaded. Without these, SPG compilation falls back to wire-load models and loses its accuracy advantage.
Extract Floorplan The early floorplan DEF is imported. The tool now knows the die boundary, placement blockages, and macro positions.
SPG Compilation Placement-aware cell mapping is performed. The tool estimates wire lengths using the floorplan geometry and TLU+ models, producing a netlist optimised for the expected physical implementation.
Write Outputs Gate-level netlist (.v), design database (.ddc), and post-synthesis SDC (.sdc) for place-and-route hand-off.

Outputs Generated

Output File Type What it contains
Gate-Level Netlist .v Synthesised circuit expressed as interconnected standard cell instances in Verilog
Design Database .ddc Complete DC session checkpoint — netlist, libraries, and constraints for downstream reuse or incremental reporting
Post-Synthesis SDC .sdc Updated SDC that includes any derived clocks added during synthesis (e.g. from clock gating) for use by place-and-route

🧠 Knowledge Assessment

1. What is the primary difference between logic synthesis and physical synthesis?

  • A. Physical synthesis only optimises area; logic synthesis optimises timing.
  • B. Physical synthesis incorporates an early floorplan and TLU+ parasitic data so wire delays are estimated using real routing geometry rather than statistical wire-load models.
  • C. Logic synthesis uses a floorplan DEF; physical synthesis does not.
  • D. Physical synthesis ignores timing constraints and focuses only on placement.
Correct! Physical synthesis incorporates an early floorplan and TLU+ RC models to estimate real interconnect delays during compilation, making the resulting netlist far more placement-friendly than one produced by pure logic synthesis.

2. What does SPG (Synthesis with Physical Guidance) enable?

  • A. The tool uses the loaded floorplan and TLU+ data to estimate wire delays and produce a placement-aware netlist.
  • B. Scan path generation for DFT insertion.
  • C. Clock gating insertion only; no physical data is used.
  • D. Sequential path grouping for multi-cycle path analysis.
Correct! SPG stands for Synthesis with Physical Guidance. It activates physically-aware optimisation by using the floorplan DEF and TLU+ RC models during compilation.

3. Why are TLU+ files required for physical synthesis but not for standard logic synthesis?

  • A. TLU+ files contain the standard cell timing arcs needed for mapping.
  • B. TLU+ files define the clock constraints for each domain.
  • C. TLU+ files provide RC extraction tables for the process metal stack, allowing the tool to estimate real wire delay and capacitance based on routing distance — replacing the inaccurate wire-load models used in logic synthesis.
  • D. TLU+ files are needed to generate the SVF file for Formality LEC.
Correct! Logic synthesis uses statistical wire-load models to estimate interconnect delay. Physical synthesis replaces these with TLU+ RC extraction tables, which model the actual parasitic resistance and capacitance of each metal layer — giving accurate wire delay data during SPG compilation.

4. Which of the following is NOT a required input for physical synthesis in topographical mode?

  • A. Technology library (.db)
  • B. TLU+ parasitic models (.tluplus)
  • C. Floorplan DEF file (.def)
  • D. A routed GDSII file (.gds)
Correct! A routed GDSII file is a final tape-out output — it does not exist at synthesis time. Physical synthesis uses an early (unrouted) floorplan DEF, not a completed GDSII.
