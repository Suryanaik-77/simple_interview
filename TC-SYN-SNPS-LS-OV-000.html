📖 Theory and Background

What is Synthesis?

Synthesis is the process of converting your RTL design (written in Verilog or SystemVerilog) into a gate-level netlist — a circuit built from real standard cells selected from a technology library (e.g., TSMC 28 nm). The synthesis tool simultaneously optimises for Power, Performance, and Area (PPA) while meeting the timing constraints you provide.

Think of it this way: RTL describes what the design should do; synthesis decides how to build it using actual logic gates that can be fabricated on silicon.

The Three Inputs Synthesis Needs

Input File Type What it contains
RTL Files .v / .sv Your design described in Verilog or SystemVerilog
Technology Library .db Compiled binary format describing all available standard cells — their speed, power, and area
Timing Constraints .sdc Specifies clock frequency and required signal arrival times at ports

The DC Shell Synthesis Stages

DC Shell runs synthesis in a well-defined sequence of stages:

Stage What it does
Load Libraries Configures search paths and tells DC Shell which standard cells and macros are available. Without this the tool has nothing to map onto.
Read RTL Analyzes Verilog/SystemVerilog source files and checks for syntax errors before elaboration.
Elaborate Connects all modules together and builds the full design hierarchy in memory.
Apply Constraints Sources the SDC timing constraints and restricts which cells DC Shell can use during mapping.
Compile Maps RTL to standard cells, optimizes for timing and area, and inserts integrated clock gating cells to reduce dynamic power.
Write Outputs Saves the gate-level netlist and design database for use by downstream place-and-route tools.

Outputs Generated by Synthesis

Output File Type What it contains
Gate-Level Netlist .v The synthesized circuit expressed as interconnected standard cell instances in Verilog
Design Database .ddc Complete DC Shell session checkpoint — netlist, libraries, and constraints saved for downstream reuse or incremental reporting
Timing Constraints .sdc Post-synthesis SDC written by write_sdc — includes any derived clocks added during synthesis (e.g. clock gating cell outputs) for use by place-and-route

Standard Cell Threshold Voltages (HVT / SVT / LVT)

TSMC 28 nm provides cells in three threshold-voltage (Vt) flavors. Each has a different speed-versus-leakage trade-off:

FlavorNaming suffixSpeedLeakageTypical use
HVT (High Vt)hvt…SlowerLowDefault cells; good for power budget
SVT (Standard Vt)ssg…MediumMediumGeneral-purpose standard cells
LVT (Low Vt)lvt…FasterHighCritical paths only; excluded by default to control leakage
Lab Focus: In this lab you load all three library flavors but use set_dont_use to block LVT and clock-tree cells during logic synthesis. This keeps static power low. DC Shell will only reach for those cells if a timing path truly cannot close with HVT/SVT cells.

Logic-Aware Synthesis and Clock Gating

“Logic-aware synthesis” refers to DC Shell’s ability to optimise the design not just structurally (gate swapping) but by understanding the logical intent of the RTL. One key feature enabled in this lab is integrated clock gating (ICG) insertion via compile_ultra -gate_clock.

Clock gating stops the clock from toggling flip-flops that are not changing value. This is one of the most effective techniques for reducing dynamic power in a digital design — typically reducing clock power by 20–40%.

The set_clock_gating_style command configures which cell DC Shell uses for ICG insertion, the minimum register bitwidth to gate, and the control point placement. This must be set before compile_ultra so the compiler applies the correct gating strategy from the start.

🧠 Knowledge Assessment

1. What does compile_ultra do that reading and elaborating RTL alone does not?

  • A. It reads and parses the RTL source files into DC Shell memory.
  • B. It inserts clock gating cells to reduce dynamic power before any cell mapping occurs.
  • C. It maps and optimizes the design using actual standard cells from the technology library, meeting timing and area goals.
  • D. It writes the final gate-level netlist to a Verilog file.
Correct! After RTL is read and elaborated, compile_ultra performs technology mapping — replacing the RTL description with real standard cells from the loaded .db files and optimizing for timing and area simultaneously.

2. Why should you save the output .ddc file after synthesis?

  • A. DC Shell cannot write the Verilog netlist without first writing the .ddc file.
  • B. The .ddc captures the complete design state after synthesis — netlist, libraries, and constraints — so it can be reloaded for incremental work or re-reporting without re-running synthesis.
  • C. The .ddc file is the only output recognized by Innovus for place-and-route.
  • D. The .ddc is smaller in size than the Verilog netlist and loads faster.
Correct! The DDC database preserves the entire synthesized state. You can reload it later to run additional reports, perform incremental optimization, or hand off to downstream tools without re-running the full compilation.

3. Why must set_clock_gating_style be defined before compile_ultra -gate_clock?

  • A. It configures the library files that must be loaded before compilation starts.
  • B. compile_ultra reads the clock gating style at the start of compilation to identify candidates and insert ICG cells with the correct configuration.
  • C. Clock gating cells are inserted during analyze, before compile_ultra runs.
  • D. The setting has no effect if applied after elaborate.
Correct! compile_ultra -gate_clock uses the clock gating style configuration at compile time to select the right ICG cell, minimum bitwidth, and control point. Setting it before compilation ensures all ICG insertions follow the intended strategy.

4. Which of the following is NOT a required input for synthesis?

  • A. RTL source files (.v / .sv)
  • B. Technology library (.db)
  • C. Timing constraints (.sdc)
  • D. A placed floorplan (.def)
Correct! A placed floorplan (.def) is an input for place-and-route, not synthesis. Synthesis only needs RTL source files, the technology library, and timing constraints.
