📚 Background: GDS Merge

FEOL and BEOL fill runs each produce a separate GDS containing only the new fill shapes. Before DRC, antenna check, or LVS can be run on the complete design, these fill shapes must be merged back into the original layout GDS to produce a single unified GDS.

calibredrv provides a Tcl scripting interface for GDS manipulation. The layout filemerge command merges GDS files without loading the full GUI module. A typical merge script:

set topcell [ layout peek $design_gds -topcell ]
set tmp_feol DM_feol.[pid]
set tmp_beol DM_beol.[pid]
set tmp_fill DM_fill.[pid]

set cmd "layout filemerge -infile \{ -name $feol_fill_gds -suffix \"_DM_feol_fill\" \} -out $tmp_feol"
eval $cmd
set cmd "layout filemerge -infile \{ -name $beol_fill_gds -suffix \"_DM_beol_fill\" \} -out $tmp_beol"
eval $cmd
layout filemerge -createtop $topcell -out $tmp_fill -in $tmp_feol -in $tmp_beol
layout filemerge -in $tmp_fill -in $design_gds -out $out_gds

The merge is non-destructive — the original shapes are preserved and fill shapes are appended as new cells instantiated at the top level. The output is written as a compressed GDS (.gds.gz). Process-ID-based temp file names ([pid]) prevent collisions when multiple jobs run in parallel.

🧠 Knowledge Check

1. What tool is used to run the GDS merge in this lab?

  • calibre -drc
  • calibredrv with a Tcl script
  • Calibre LVS engine
  • calibre -merge
Correct! calibredrv provides the GDS manipulation API used for merging.

2. What does layout filemerge -createtop do in the merge script?

  • It writes the final compressed GDS output
  • It combines the FEOL and BEOL temporary databases into a single fill database under a named top cell
  • It flattens both GDS files into a single hierarchy
  • It removes duplicate fill shapes
Correct! -createtop assembles the two fill temporaries (FEOL and BEOL) into one combined fill database with the original design's top cell name.

3. If the FEOL GDS path in the merge script points to the wrong file, what is the likely outcome?

  • calibredrv aborts with an error
  • The merge completes but FEOL fill shapes are absent from the output
  • The output GDS contains duplicate shapes
  • The output GDS is not created
Correct! Merging the wrong file may succeed silently but leave out the intended fill shapes.

4. What is the expected output filename after a correct merge?

  • aes_cipher_top.merged.gds.gz
  • aes_cipher_top.fill.gds.gz
  • aes_cipher_top_FEOL.gds
  • aes_cipher_top.drc.gds
Correct! The merged GDS is named aes_cipher_top.fill.gds.gz — used as input for DRC, antenna, and LVS.
