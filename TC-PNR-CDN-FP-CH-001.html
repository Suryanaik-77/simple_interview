Challenge Problem

INDEPENDENT WORK

You are given a floorplanning script for the iguana_soc RISC-V SoC — a full chip design containing multiple SRAM macros and hundreds of thousands of standard cells. The script (scripts/floorplan.tcl) contains a deliberate bug in the power plan source command: it references an incorrect path for the power plan script.

⚠ What goes wrong without the fix:
  • Bug — wrong power plan path: The source command references ../scripts/power_plan.tcl but the actual power plan file is located at ../inputs/power_plan.tcl. Innovus will report a TCL "cannot open file" error and the entire power distribution network will not be created.
  • Consequence: Without the power plan, the iguana_soc core has no M4–M9 VDD/VSS stripes. All standard cells and SRAM macros will be unconnected to the power supply. All four PG checks (check_drc, check_connectivity, check_power_vias, check_pg_shorts) will report failures.
  • Why the path matters: In this flow, the power plan TCL is a design input (pre-tuned for iguana_soc die dimensions and current budgets) rather than a user-editable script. It is stored in ../inputs/ alongside other input files like the floorplan DEF and initialized database.

Find the bug, correct the path, run the full floorplan flow, and save the floorplan.db database.

📝 Requirements and Deliverables

  • Fix the power plan path in the source command in scripts/floorplan.tcl — change ../scripts/power_plan.tcl to ../inputs/power_plan.tcl
  • The complete floorplan flow runs without errors in the Innovus log
  • ../reports/check_pin_assignment.rpt generated — no illegal pin placements
  • ../reports/check_endcaps.rpt generated — no endcap violations
  • ../reports/check_welltaps.rpt generated — no max_distance violations at 30 µm
  • ../reports/check_drc.rpt — zero DRC violations on power structures
  • ../reports/check_connectivity.rpt — VDD and VSS fully connected, no open nets
  • ../reports/check_power_vias.rpt — all via intersections present
  • ../reports/check_pg_shorts.rpt — zero VDD-to-VSS short circuits
  • ../outputs/floorplan.db written to disk with SDC constraints

⚙ Recommended Workflow

  1. Navigate: cd ~/pd/labs/PNR-CDN-FP/TC-PNR-CDN-FP-CH-001
  2. Open scripts/floorplan.tcl and inspect every source command carefully — note the path prefix used for the power plan
  3. Check what files exist in ../inputs/: ls ../inputs/
  4. Correct the source path so it points to ../inputs/power_plan.tcl
  5. Run make all to launch Innovus and execute the corrected script
  6. Verify the Innovus physical view shows M4–M9 VDD/VSS stripes across the die after the power plan runs
  7. Confirm all seven PG and physical cell check reports are generated in ../reports/
  8. Run make verify

💡 Hints

Hint 1 — Finding the bug
Look at the source command that invokes the power plan script. Compare the directory path it uses against where input files actually reside in this flow. The power plan is a pre-tuned design input, not a user-generated script — check whether it belongs in ../scripts/ or ../inputs/.
Hint 2 — Verifying the fix worked
After fixing the path and re-running the script, the Innovus physical view should show alternating VDD/VSS stripe pairs on M6–M9 across the full die area. If the view shows only standard cell rows with no metal stripes, the power plan script still did not execute. Also check the Innovus log for a TCL "cannot open file" error — that confirms the path bug is still present.
Hint 3 — Output database path
The write_db -sdc command at the end of the floorplan script saves to ../outputs/floorplan.db. Make sure this path exists — it was created by setup_lab.sh. The -sdc flag writes the active SDC timing constraints alongside the database so the placement stage can restore the full timing setup with a single read_db call.
Hint 4 — Why checkerboard well-tap placement matters
The iguana_soc core has multiple large SRAM macros. Dense macro regions restrict available standard cell row sites for well-tap insertion. If check_welltaps.rpt reports violations, the cause is almost always a narrow routing channel between two macros where no row sites are available for well-tap cells within 30 µm. The fix is usually to adjust macro placement to widen those channels.

📚 Knowledge Assessment Quiz

1. A "pad-limited die" is a common floorplan category. What defines it?

  • A die where the macro block area is larger than the standard cell area, forcing the die to expand
  • A die where the I/O ring width exceeds the minimum required, wasting silicon area
  • A die whose minimum size is determined by the number and physical size of I/O pads — even if the logic core could fit in a smaller area, the perimeter must accommodate all I/O pads at their required pitch
  • A die where the power pad count limits the maximum operating frequency due to IR drop constraints
Correct! A pad-limited (I/O-limited) die occurs when the required number of I/O pads at their minimum pitch exceeds what can fit around the perimeter of a die sized purely by logic area. Typical scenarios include designs with many GPIO pins, high-speed interfaces (PCIe, DDR), or mixed-signal designs with large pad pitch. Core utilization is typically low (10–30%) in pad-limited designs. The counterpart is a core-limited die where logic area dictates die size and I/O pads easily fit around the perimeter.

2. A key macro placement guideline states that hard macros should be placed near the core boundary rather than in the center. What is the primary reason?

  • Macros near the boundary are easier to connect to I/O pads, reducing signal routing length
  • Macros in the center fragment the standard cell region into disconnected islands, creating long detour paths for inter-region signals and severe routing congestion in narrow channels between macros
  • Boundary placement keeps macros away from the clock tree spine, reducing clock insertion delay
  • Tools run faster when macros are at the boundary because fewer standard cells need timing-driven placement near macro corners
Correct! When macros are placed in the center of the core, they physically divide the standard cell placement area into isolated sub-regions. Signals that need to cross from one region to another must route around or through narrow channels between macros, dramatically increasing wire length and congestion. Placing macros along the core periphery preserves a continuous central placement region for standard cells, maximizing routing resource efficiency and minimizing wire length for inter-block connections.

3. Three types of placement blockages are used in physical design: hard, soft, and partial. What type of cell is allowed inside a soft blockage?

  • No cells at all — a soft blockage is identical to a hard blockage but with lower enforcement priority
  • Only buffers (inserted during timing optimization steps) — no standard logic cells are placed during normal placement
  • Any standard cell up to a maximum density percentage — soft blockage is equivalent to partial blockage
  • Only tie cells and filler cells — functional cells are excluded from soft blockages
Correct! Soft blockages prohibit standard logic cell placement but permit buffer insertion during optimization. They are typically applied in macro channel regions — the space between adjacent macros where routing channels must remain clear. Normal placement cannot fill these channels, but if a critical timing path requires a buffer in that region during optimization, the tool is permitted to insert one. Hard blockages prohibit all cells unconditionally. Partial blockages allow cells up to a specified density percentage (e.g., 40% fill allowed).

4. The Flip Chip Ball Grid Array (FCBGA) package is preferred for high-performance SoCs over older DIP packages. What is its primary electrical advantage?

  • FCBGA uses through-hole mounting, which provides stronger mechanical attachment to the PCB than surface mount
  • FCBGA packages are made of ceramic instead of plastic, reducing package parasitics from moisture absorption
  • The flip-chip connection eliminates wire bonds — the die is flipped face-down and connected directly to the package substrate via solder bumps, providing the shortest possible signal path and the highest achievable pin density per unit area
  • FCBGA uses aluminium bond wires instead of gold wires, reducing parasitic inductance at each pin connection
Correct! In a conventional wire-bond package, long thin gold wires loop from die bond pads to the package lead frame, adding significant parasitic inductance (L) and resistance that limits high-speed signal integrity. The flip-chip attachment in FCBGA replaces these wires with short solder bumps directly under the die, reducing parasitic inductance by 10–100× per connection. Combined with a 2D grid of balls across the entire package base (BGA), FCBGA achieves far higher pin density than the perimeter-only pinout of DIP or QFP packages.
