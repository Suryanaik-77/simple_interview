📚 Background: Why Dummy Fill?

In sub-32nm technologies, chemical-mechanical planarization (CMP) is used to flatten each dielectric and metal layer. CMP polish rate is pattern-density dependent: sparse regions polish faster, leading to dishing in metal and erosion in oxide. The result is non-planar wafer topography that causes focus errors in subsequent lithography steps.

Foundries solve this by mandating a minimum pattern density in every layer. Dummy fill shapes (electrically floating geometries) are inserted into open areas to meet the density requirement without affecting circuit functionality.

FEOL dummy fill targets the transistor-level layers:

  • OD (Active / Diffusion) — sets the density of active silicon
  • PO (Poly / Gate) — sets the poly gate pattern density

TSMC 28nm HP requires FEOL fill to be inserted before BEOL metal fill so that any OD/PO density violations are resolved first.

⚙️ Calibre FEOL Fill Flow

Calibre runs fill as a special-mode DRC pass using the foundry-supplied dummy fill rule deck. The command is:

calibre -turbo 2 -hier -drc feol_runset.rule

The runset file controls all aspects of the fill run. The key statements are:

  • LAYOUT PATH — path to the input GDS/OASIS file
  • LAYOUT PRIMARY — top-level cell name in the GDS
  • LAYOUT SYSTEM — format (GDSII / OASIS)
  • DRC RESULTS DATABASE — output GDS with fill shapes appended
  • #DEFINE UserprBoundary — activates boundary layer recognition in the rule deck
  • INCLUDE — path to the foundry fill rule deck

A correctly configured FEOL runset for TSMC 28nm 1P9M looks like:

LAYOUT PATH "../inputs/aes_cipher_top.merged.gds.gz"
LAYOUT PRIMARY "aes_cipher_top"
LAYOUT SYSTEM GDSII

DRC SUMMARY REPORT "aes_cipher_top_FEOL.summary"
DRC MAXIMUM RESULTS ALL
DRC RESULTS DATABASE "../outputs/aes_cipher_top_FEOL.gds" GDSII _FEOL_fill

#DEFINE UserprBoundary

INCLUDE "/efs/semicon_labs_pd/pdk/.../Dummy_OD_PO_Calibre_28nm_HP.13a"

⚠️ Common Mistakes

  • Wrong PRIMARY cell name — Calibre exits with "can't find cell". Check GDS with calibredrv -m celllist.tcl.
  • Wrong INCLUDE path — Using the BEOL rule deck for FEOL fill applies the wrong density rules; output GDS may look valid but OD/PO fill is absent.
  • Missing #DEFINE UserprBoundary — Fill extends outside the intended boundary region.
  • Gzip input without .gz extension — Some Calibre versions need the extension to auto-detect compression.

🧠 Knowledge Check

1. What CMP mechanism does FEOL dummy fill address?

  • Metal electromigration during current flow
  • Pattern density variation causing dishing and erosion
  • Stress-induced voiding in copper interconnects
  • Via chain resistance increase at low temperature
Correct! CMP polishes pattern-sparse areas faster; dummy shapes equalize density to prevent dishing/erosion.

2. Which Calibre runset statement specifies the top-level cell in the input GDS?

  • LAYOUT PATH
  • DRC RESULTS DATABASE
  • LAYOUT PRIMARY
  • INCLUDE
Correct! LAYOUT PRIMARY tells Calibre which cell to treat as the top of the hierarchy.

3. What does #DEFINE UserprBoundary enable in the TSMC fill rule deck?

  • Recognition of a user-supplied boundary layer to constrain fill insertion area
  • Faster parallel multi-core processing
  • Output of the fill GDS in compressed OASIS format
  • Automatic selection between FEOL and BEOL rule decks
Correct! Without this define, the rule deck ignores the boundary layer and fills the entire chip area.

4. In what order must FEOL and BEOL fill be run?

  • BEOL first, then FEOL
  • They can run in any order
  • FEOL first, then BEOL
  • Simultaneously in the same Calibre run
Correct! OD/PO density must be established before the metal stack fill is computed, so FEOL runs first.
