Problem Statement

GUIDED

You have 4 saved PrimeTime sessions from the STA lab (one per PVT corner) sitting in inputs/PT_SS/. Your task is to load all 4 into a single DMSA environment, query the worst slack across all corners, and generate unified signoff reports.

📝 Step-by-Step: Understanding the DMSA Script

  • Navigate and Launch

    cd ~/pd/labs/STA-SNPS-DMSA/testcase1
make run

    This launches pt_shell -multi_scenario with the DMSA script. Open scripts/sta_dmsa.tcl in a separate editor and follow along.

  • Set Working Directory and Number of Workers

    set multi_scenario_working_directory ./

set_host_options -num_processes 4
    • multi_scenario_working_directory — sets the base directory for all DMSA worker processes.
    • -num_processes 4 — tells the master to spawn 4 worker processes, one for each PVT corner.

  • Create Scenarios from Saved Sessions

    set STA_DATA_DIR ../inputs/PT_SS

create_scenario -name ss_0p81v_m40c_cworst  -image ${STA_DATA_DIR}/funceco_ss_0p81v_m40c_cworst
create_scenario -name ss_0p81v_125c_rcworst -image ${STA_DATA_DIR}/funceco_ss_0p81v_125c_rcworst
create_scenario -name ff_0p99v_m40c_cbest   -image ${STA_DATA_DIR}/funceco_ff_0p99v_m40c_cbest
create_scenario -name ff_0p99v_125c_rcbest  -image ${STA_DATA_DIR}/funceco_ff_0p99v_125c_rcbest
    • create_scenario — registers a PVT corner with the DMSA master. The -name is a label you choose; the -image points to the saved PT session directory from the STA lab.
    • Each saved session already contains the full design, libraries, SPEF parasitics, SDC constraints, and timing graph for that corner — so the worker can start analysis immediately without re-reading any inputs.
    • Two slow corners (SS) for setup analysis, two fast corners (FF) for hold analysis.

  • Start Workers and Activate All Scenarios

    start_hosts

current_session -all
current_scenario -all
    • start_hosts — spawns all 4 worker processes. Each worker loads its saved session into memory. This takes a few minutes depending on design size.
    • current_session -all — tells the master to target all worker sessions when dispatching commands.
    • current_scenario -all — activates all 4 scenarios so every command runs across all corners simultaneously.

  • Apply Cell Restrictions on All Workers

    remote_execute {
    set_dont_use [get_lib_cells {*/*CK* */*D24* */*D26* */*D32*}]
}
    • remote_execute — sends the enclosed command to every active worker. The command runs inside each worker's PrimeTime session.
    • This blocks clock-tree cells and oversized drive-strength cells from being used in any ECO fixes applied later. The restriction is applied identically across all 4 corners.

  • Generate Unified Multi-Corner Reports

    file mkdir ../reports/dmsa

report_timing -pba_mode exhaustive -delay max -max_paths 50 -nosplit \
    -path full_clock_expanded -nets -transition_time -input_pins \
    > ../reports/dmsa/timing-max-all-corners

report_timing -pba_mode exhaustive -delay min -max_paths 50 -nosplit \
    -path full_clock_expanded -nets -transition_time -input_pins \
    > ../reports/dmsa/timing-min-all-corners

report_constraint -all_violators -nosplit > ../reports/dmsa/constraints-all-corners

report_qor -significant_digits 3 > ../reports/dmsa/qor-all-corners

report_global_timing -delay_type max > ../reports/dmsa/global-timing-max
report_global_timing -delay_type min > ../reports/dmsa/global-timing-min
    • In DMSA mode, every report command automatically queries all active workers and returns the worst-case result across all corners.
    • timing-max-all-corners — the 50 worst setup paths across all 4 corners. Each path shows which corner is the bottleneck.
    • timing-min-all-corners — the 50 worst hold paths across all 4 corners.
    • constraints-all-corners — every timing and DRC violation from every corner in one file.
    • qor-all-corners — unified WNS, TNS, and violating path count across all scenarios.
    • global-timing — per-clock-group timing summary for max (setup) and min (hold).

✅ Success Criteria

  • reports/dmsa/qor-all-corners — unified QoR report
  • reports/dmsa/timing-max-all-corners — worst setup paths across all corners
  • reports/dmsa/timing-min-all-corners — worst hold paths across all corners
  • reports/dmsa/constraints-all-corners — all violations across all corners

✅ Validation & Verification

After the DMSA session completes:

make verify

🧠 Knowledge Assessment

1. What does create_scenario -image load into the worker?

  • Only the gate-level netlist.
  • A complete saved PrimeTime session containing the design, libraries, SPEF, constraints, and timing graph for that corner.
  • Just the SDC constraints file.
  • The floorplan DEF from place-and-route.
Correct! The saved session is a complete snapshot of a single-corner PT run. The worker loads it and is immediately ready for timing queries without re-reading any inputs.

2. What does remote_execute do?

  • It runs the command only on the master session.
  • It sends the enclosed command to every active worker, so the command runs inside each worker's PrimeTime session simultaneously.
  • It saves the current session to disk.
  • It restarts all worker processes.
Correct! remote_execute dispatches the command block to all active workers in parallel. This is how you apply changes (like dont_use) consistently across all corners.

3. In DMSA, when you run report_timing -delay max, what do you get?

  • Timing from only the first corner that was loaded.
  • Separate reports from each corner that you have to compare manually.
  • A single unified report showing the worst slack across all active corners, with each path annotated with its limiting corner.
  • An error, because report_timing only works in single-scenario mode.
Correct! The master queries all workers, collects their results, and presents the worst-case across all scenarios in one report. This is the key advantage of DMSA over running corners individually.

4. Why are 4 workers needed for this design?

  • Each worker handles a different clock domain.
  • PrimeTime requires exactly 4 workers to run.
  • There are 4 PVT corners (2 slow for setup, 2 fast for hold), each with its own libraries, SPEF, and timing data. One worker per corner.
  • 4 workers are needed for ECO fixes only.
Correct! Each PVT corner has different libraries and parasitics, so each needs its own PrimeTime instance. DMSA coordinates all 4 through the master.
