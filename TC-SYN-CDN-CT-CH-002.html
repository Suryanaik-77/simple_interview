During synthesis, the check_timing_intent command reports multiple timing intent warnings. These warnings indicate that several parts of the design are missing required timing constraints.

Your Challenge: Analyze the Check timing intent report, determine which constraints are missing, update the SDC file appropriately, and ensure the design has a clean timing intent report.

🧠 Knowledge Check

Question 1: Which command helps you understand the detailed cause of each warning reported by check_timing_intent?

  • check_timing_intent -verbose
  • report_timing -verbose
  • report_clocks
  • check_design

Correct! The -verbose option provides detailed explanations for each timing intent warning.

Question 2: If an input port does not have an input delay constraint, which CTI warning will appear?

  • Generated clocks without clock waveform
  • Inputs without clocked external delays
  • Outputs without external load
  • Sequential data pins driven by a clock signal

Correct! This warning indicates that the synthesis tool cannot determine when external data arrives relative to the clock.

Question 3: Which SDC command should be used to constrain the arrival time of an external input signal relative to a clock?

  • set_input_delay -clock clk <delay> [get_ports data]
  • set_output_delay -clock clk <delay> [get_ports data]
  • create_clock -period <period> [get_ports data]
  • set_load <capacitance> [get_ports data]

Correct! set_input_delay defines the timing relationship between external inputs and the clock.

Question 4: Why must output ports have set_output_delay constraints defined?

  • To define clock frequency
  • To specify when the output data must be valid relative to a clock
  • To create generated clocks
  • To reduce logic delay inside the design

Correct! set_output_delay tells the tool when external logic expects valid output data.

Question 5: After adding missing constraints to the SDC file, which command should be run to verify that all timing intent warnings are resolved?

  • report_timing
  • check_timing_intent
  • report_area
  • report_qor

Correct! Running check_timing_intent again confirms that all timing constraints are properly defined.
