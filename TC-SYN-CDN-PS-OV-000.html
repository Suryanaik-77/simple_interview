📖 Theory and Background

What is Physical-Aware Synthesis?

In a traditional synthesis flow, the tool converts RTL to a gate-level netlist using only logical timing models — it has no knowledge of where cells will be physically placed on silicon. Wire delays are estimated using simple statistical models (wire-load models), which become increasingly inaccurate as designs grow larger and technology nodes shrink.

Physical-aware synthesis (also called Genus iSpatial or GPS) solves this problem by incorporating real physical information — cell placement, floorplan boundaries, and routing congestion — directly into the synthesis optimization loop. The tool reads LEF files (cell physical abstracts) and a floorplan DEF, then performs actual trial placement during synthesis to compute realistic wire delays.

The result is a gate-level netlist that is already placement-aware, leading to much better correlation between synthesis timing and place-and-route timing. This reduces the number of ECO iterations and shortens the overall design closure timeline.

Standard Synthesis vs. Physical-Aware Synthesis

Aspect Standard Synthesis Physical-Aware Synthesis (iSpatial)
Wire delay model Statistical wire-load models Real placement-based wire delays
Physical inputs None (timing libraries only) LEF files + floorplan DEF
Timing correlation Low — estimates diverge from P&R High — placement-aware optimization
Congestion awareness No Yes — considers routing congestion
Output handoff Netlist + SDC Netlist + SDC + placed DEF + Innovus database

Why LEF and DEF?

Standard synthesis only needs timing libraries (.lib) to know how fast cells are. Physical-aware synthesis also needs to know how big cells are, where their pins are, and where they will be placed on silicon:

  • LEF (Library Exchange Format) — describes the physical dimensions, pin shapes, and routing obstructions of every standard cell and macro. The technology LEF (.tlef) describes metal layers and via rules.
  • DEF (Design Exchange Format) — describes the floorplan: die area boundaries, placement rows, fixed macro positions, and I/O port locations. The placer uses this to determine where standard cells can be placed.

MMMC: Multi-Mode Multi-Corner

Physical-aware synthesis uses MMMC to analyze the design under multiple operating conditions simultaneously. Instead of loading a single timing library, MMMC defines:

  • Library Sets — groups of .lib files for a specific PVT corner (e.g., slow 0.81V −40°C)
  • RC Corners — parasitic extraction conditions (e.g., cworst, rcworst, cbest, rcbest)
  • Delay Corners — combine a library set with an RC corner to model a complete timing scenario
  • Constraint Modes — SDC files defining clock periods and I/O delays for a given operating mode
  • Analysis Views — combine a delay corner with a constraint mode; separate views for setup (slow corners) and hold (fast corners) analysis

Setup timing is hardest to meet when cells are slow (low voltage, extreme temperature), while hold timing is hardest when cells are fast (high voltage). Separate analysis views ensure both are checked under their respective worst-case conditions.

Useful Skew and Congestion Awareness

Two key optimizations available in physical-aware synthesis that are not possible in standard synthesis:

  • Useful skew optimization — intentionally skews clock arrival times at different flip-flops. Slack is borrowed from timing-rich paths and donated to timing-critical paths. This is only meaningful when actual wire delays from placement are known.
  • Congestion awareness — the placer detects areas where too many cells are packed together, which would cause routing failures during P&R. It redistributes cells to avoid congestion hotspots, improving routability of the final design.

🧠 Knowledge Assessment

1. What is the primary advantage of physical-aware synthesis over standard synthesis?

  • A. It runs faster because it skips the optimization phase.
  • B. It uses real placement-based wire delays instead of statistical wire-load models, improving timing correlation with place-and-route.
  • C. It eliminates the need for place-and-route entirely.
  • D. It only supports single-corner timing analysis.
Correct! Physical-aware synthesis performs trial placement during synthesis to compute realistic wire delays. This dramatically improves the correlation between synthesis timing results and final place-and-route timing, reducing ECO iterations.

2. Which additional physical input files does Genus iSpatial require beyond what standard synthesis needs?

  • A. Only the technology library (.lib) files.
  • B. The final routed GDSII file.
  • C. LEF files (cell physical abstracts) and a floorplan DEF file.
  • D. A Verilog testbench for simulation.
Correct! Genus iSpatial reads LEF files to know the physical dimensions of standard cells and macros, and a floorplan DEF to know the die area, placement rows, and macro locations. These enable placement-based wire delay estimation.

3. Why does physical-aware synthesis use MMMC instead of a single timing library?

  • A. MMMC is required because iSpatial cannot read .lib files directly.
  • B. MMMC is only needed for designs with more than one clock domain.
  • C. The placement engine needs to evaluate timing under multiple PVT and RC corners simultaneously to make placement decisions that are robust across all operating conditions.
  • D. Standard synthesis does not support timing analysis at all.
Correct! Physical-aware synthesis uses actual cell placement to compute wire delays, and different PVT/RC corners can result in different critical paths. MMMC ensures the placer optimizes for all corners simultaneously rather than a single worst case.

4. What does useful skew optimization do?

  • A. It eliminates all clock skew in the design.
  • B. It inserts clock buffers to balance the clock tree.
  • C. It intentionally skews clock arrival times at different flip-flops, borrowing slack from timing-rich paths to help timing-critical paths.
  • D. It disables clock gating to reduce skew sources.
Correct! Useful skew optimization intentionally adjusts clock arrival times so that timing-critical paths receive the clock later (for setup) or earlier (for hold), effectively borrowing slack from paths that have margin to spare.
