Challenge Problem

INDEPENDENT WORK

You are given an Innovus init_design for the iguana_soc design — a larger design with different SRAM macros than the tile design from the guided.

Your task: run the script, observe the failures, identify bugs, fix them, and verify that the corrected flow produces a valid ../outputs/init_design.db database.

⚠ What goes wrong without fixes:
  • Bug 1 — time_design redirect: The time_design -pre_place command redirects output to ../reports (a directory) instead of using -report_dir. The command silently fails to create a valid report.
  • Bug 2 — wrong output database name: The database is saved as ../outputs/init.db instead of ../outputs/init_design.db. The subsequent floorplan stage reads init_design.db and will fail to find the file.

📝 Requirements and Deliverables

  • Fix correct the time_design -pre_place command to use -report_dir with a proper file path
  • Fix change the output database filename from init.db to init_design.db
  • The complete init flow must run without errors from read_mmmc through write_db
  • ../outputs/init_design.db must exist and be a valid Innovus database
  • ../reports/check_timing_library_consistency.rpt must be generated
  • ../reports/report_timing.rpt must be generated

⚙ Recommended Workflow

  1. Navigate to Challenge: cd ~/pd/labs/PNR-CDN-DI/TC-PNR-CDN-DI-CH-001
  2. Open scripts/init_design.tcl in an editor and read through the script carefully
  3. Run make all and then source ../scripts/init_design.tcl to observe the failures
  4. Identify the two bugs from the error messages and script inspection
  5. Fix both bugs in the script
  6. Re-run the corrected script and verify all outputs are generated
  7. Run exit

📚 Knowledge Assessment Quiz

1. In MMMC setup analysis, which PVT corner is typically used and why?

  • FF (fast-fast) at low temperature and high voltage, because fast transistors create the tightest setup windows
  • TT (typical-typical) at 25°C and nominal voltage, because it represents average silicon behavior
  • SS (slow-slow) at high temperature (125°C) and low voltage (0.81 V), because slow transistors with degraded supply produce the maximum cell delays
  • SF (slow-fast) at low temperature, because the mismatch between PMOS and NMOS causes worst-case setup paths
Correct! Setup analysis uses the worst-case slow corner — SS process (slow NMOS + slow PMOS), high temperature (125°C), and low voltage (0.81 V for 28nm). Under these conditions, transistors drive current least effectively, producing maximum combinational delays. Any path that meets setup at this corner will meet it under all other operating conditions.

2. CPPR (Clock Path Pessimism Removal) is applied during timing analysis. What specific problem does it solve?

  • It removes pessimism caused by using the wrong RC corner for clock net extraction
  • It corrects the launch clock latency when the clock source is located outside the design boundary
  • When launch and capture paths share a common clock segment, timing tools apply OCV (on-chip variation) derating to that segment twice — once for launch and once for capture. CPPR removes this double-counted pessimism from the shared portion
  • It removes the pessimism introduced by using ideal clock assumptions during placement optimization
Correct! In MMMC timing analysis with OCV derating, the common clock path between launch and capture flip-flops is pessimistically derated in both directions simultaneously. Since the same physical wire cannot be both slower and faster at the same instant, this creates unrealistic pessimism. CPPR identifies the common clock path and credits back the double-counted derating, producing a more realistic timing result.

3. The ITF generates three types of parasitic model files used in PnR. Which of the following is the correct set?

  • SPEF, GDSII, and DEF — standard exchange formats for parasitic data
  • LIB, LEF, and VERILOG — the three file types needed for design initialization
  • TLUPLUS (Synopsys/ICC2), QRCTECH (Cadence/Innovus), and NXTGRD (Mentor) — tool-specific parasitic lookup table formats generated from the ITF
  • RC_corner, PVT_corner, and Mode_corner — the three corners in an MMMC analysis view
Correct! The ITF (Interconnect Technology File) is a process-layer description file provided by the foundry. It is processed by field-solver-calibrated tools to generate parasitic lookup tables in tool-specific formats: TLUPLUS for Synopsys ICC2, QRCTECH for Cadence Innovus, and NXTGRD for Mentor tools. These lookup tables are loaded as RC corners in MMMC and used during design optimization to estimate wire delays at ±3% accuracy.

4. In ICC2 (Synopsys), a Design Library is the top-level container for the physical design. What does it hold?

  • Only the gate-level Verilog netlist and SDC constraints
  • Only the technology files and PDK libraries — the design netlist is stored separately in a .db file
  • The technology file (process rules), all reference NDM (Node Design Model) cells from the PDK, and the design block being implemented — everything needed to run the full PnR flow
  • Only the MMMC configuration — library sets, constraint modes, and analysis views
Correct! In ICC2's design flow, a Design Library (create_lib) is a single on-disk container that bundles the technology file (layer rules, design rules) and all reference NDM cell libraries from the PDK. The design block is then opened within this library. Having technology + cells + design in one library ensures consistent rule checking and avoids mismatches between the design and its reference cells.
