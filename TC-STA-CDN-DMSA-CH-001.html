💡 Hints

Hint 1 — Optimization Sequence

The order of optimization phases matters significantly. Setup optimization must run first because it establishes the baseline timing. Hold optimization comes next since hold fixes must not violate setup constraints. DRV optimization runs last to clean up any remaining design rule violations. Each phase uses opt_signoff with the appropriate flag (-setup, -hold, or -drv) and should include -update_timing to refresh the timing graph after each pass.

Hint 2 — Path Group Configuration

After sourcing path_group.tcl, the variable $selected_groups contains the list of all defined path groups. Use set_db opt_signoff_include_setup_path_groups and set_db opt_signoff_include_hold_path_groups to tell the optimizer which path groups to target. Before each optimization phase, configure opt_signoff_eco_file_prefix and opt_signoff_write_eco_opt_db to control where intermediate ECO files and databases are written.

🧠 Knowledge Assessment

1. Why must setup optimization be performed before hold optimization in a DMSA ECO flow?

  • A. Setup optimization runs faster and should always go first for efficiency.
  • B. Hold optimization requires the SETUP_eco.db file as direct input.
  • C. Hold fixes (buffer insertions) can degrade setup timing, so setup must be closed first to establish a stable baseline before hold corrections are applied.
  • D. The Tempus tool enforces this order and will error out if hold is run first.
Correct! Setup optimization establishes the timing baseline. Hold fixes typically insert buffers or delay cells that add delay on paths, which can worsen setup slack. By closing setup first, the optimizer ensures that subsequent hold fixes do not create new setup violations.

2. What is the purpose of the -update_timing flag in the opt_signoff command?

  • A. It forces the tool to rewrite the timing database to disk after optimization.
  • B. It incrementally updates the timing graph after ECO changes so subsequent optimization phases work with accurate timing data.
  • C. It updates the SDC constraints file with the latest clock definitions.
  • D. It triggers a full timing signoff analysis and generates a timing report automatically.
Correct! The -update_timing flag ensures the in-memory timing graph is refreshed after each optimization pass. Without it, subsequent phases would optimize based on stale timing data, potentially making incorrect or suboptimal ECO decisions.

3. What does set_db opt_signoff_allow_multiple_incremental true enable in the DMSA ECO flow?

  • A. It allows multiple Tempus instances to run in parallel on different corners.
  • B. It permits the tool to read multiple timing databases simultaneously.
  • C. It enables the tool to generate multiple ECO scripts for different PVT corners.
  • D. It allows running multiple successive incremental optimization passes (setup, hold, DRV) within the same session without resetting the ECO state.
Correct! By default, Tempus may restrict incremental optimization to a single pass. Setting this attribute to true allows the flow to chain setup, hold, and DRV optimizations sequentially in one session, with each pass building on the ECO changes from the previous one.

4. Why is the ECO output written in Innovus format using write_eco -format innovus?

  • A. Innovus format is the only format Tempus supports for ECO export.
  • B. Innovus format produces smaller file sizes compared to other ECO formats.
  • C. The ECO changes must be applied back in the physical implementation tool (Innovus) to update the placed-and-routed design with the timing fixes.
  • D. Innovus format includes detailed timing reports alongside the ECO commands.
Correct! Tempus performs timing analysis and determines what logic changes (cell swaps, buffer insertions) are needed, but the physical implementation of those changes happens in Innovus. The ECO script in Innovus format contains commands that Innovus can directly execute to modify the placed-and-routed netlist.
