  • Set PrimeTime Analysis Variables

    set enable_recovery_removal_arcs true
set_app_var timing_remove_clock_reconvergence_pessimism true
set_app_var timing_update_status_level high
set_app_var report_default_significant_digits 3
set_app_var timing_enable_max_capacitance_set_case_analysis true
    • enable_recovery_removal_arcs — enables checking of recovery and removal timing arcs (async reset/set timing).
    • timing_remove_clock_reconvergence_pessimism — removes extra pessimism when the same clock reaches both launch and capture flip-flops through different paths (CRPR).
    • timing_update_status_level high — provides detailed progress messages during timing updates.
    • report_default_significant_digits 3 — sets report precision to 3 decimal places.
    • timing_enable_max_capacitance_set_case_analysis — enables max capacitance DRC checks even on pins with case analysis constants.

  • Read the Post-P&R Netlist

    read_verilog ../inputs/tile_pnr.v
current_design tile
link_design
    • read_verilog — reads the gate-level netlist produced by place-and-route.
    • current_design tile — sets the top-level design to tile.
    • link_design — resolves all cell references against the loaded libraries. If any cell is missing from link_library, this will report errors.

  • Enable Signal Integrity Analysis and Read SPEF

    set_app_var si_enable_analysis true
set_app_var read_parasitics_load_locations true
read_parasitics -format spef -keep_capacitive_coupling ../inputs/spef.spef.ss_0p81v_m40c_cworst
    • si_enable_analysis true — enables signal integrity (crosstalk) analysis. PrimeTime will compute crosstalk-induced delay changes on victim nets.
    • read_parasitics_load_locations true — reads X/Y coordinate data from the SPEF for more accurate analysis.
    • read_parasitics -format spef -keep_capacitive_coupling — loads the SPEF file for this corner. The -keep_capacitive_coupling flag preserves coupling capacitances between nets, which is needed for SI analysis. The SPEF file spef.spef.ss_0p81v_m40c_cworst contains parasitics extracted at the cworst (capacitance worst) condition.

    • set_operating_conditions -analysis_type on_chip_variation — enables OCV (On-Chip Variation) analysis. PrimeTime will apply different derating to launch and capture paths to model within-die variations.
    • source ../inputs/tile.sdc — loads the timing constraints (clock definitions, I/O delays, false paths, etc.).

    Triggers a full timing update. PrimeTime computes arrival times, required times, and slack for every timing path using the loaded libraries, SPEF parasitics, and SDC constraints.

    These variables build the report directory path: reports/sta/funceco_cworst/ss_0p81v_m40c/. All reports for this corner are saved under this directory.

  • Generate Check Timing and Annotated Parasitics Reports

    report_annotated_parasitics -check -constant_arcs -list_not_annotated -max_nets 200 \
  > ../reports/sta/${mse_str}/${pvt_str}/annotated

check_timing -verbose > ../reports/sta/${mse_str}/${pvt_str}/checktiming
    • report_annotated_parasitics — verifies that the SPEF was correctly annotated onto the design. Lists any nets that were not annotated (missing from SPEF).
    • check_timing -verbose — checks for missing timing constraints, unconstrained endpoints, and other timing intent issues. This should be clean if the SDC is complete.

  • Generate Timing Reports

    report_timing -group [get_path_groups *] -pba_mode exhaustive \
  -inp -net -trans -cap -nos -derate -crosstalk_delta \
  -delay max -max_paths 100 \
  > ../reports/sta/${mse_str}/${pvt_str}/timing-max

report_timing -group [get_path_groups *] -pba_mode exhaustive \
  -inp -net -trans -cap -nos -derate -crosstalk_delta \
  -delay min -max_paths 100 \
  > ../reports/sta/${mse_str}/${pvt_str}/timing-min
    • -pba_mode exhaustive — uses path-based analysis for most accurate results (considers path-specific derating instead of graph-based).
    • -delay max — reports setup (max delay) paths. -delay min reports hold (min delay) paths.
    • -crosstalk_delta — includes crosstalk-induced delay changes in the report.
    • -max_paths 100 — reports the top 100 worst paths per path group.

  • Generate QoR, Clock, and SI Reports

    report_constraint -all_violators > ../reports/sta/${mse_str}/${pvt_str}/constraints
report_bottleneck -max_cells 40 -max_paths 100 > ../reports/sta/${mse_str}/${pvt_str}/bottleneck_timing
report_qor -significant_digits 3 > ../reports/sta/${mse_str}/${pvt_str}/qor

report_clocks -attributes -skew > ../reports/sta/${mse_str}/${pvt_str}/clocks
report_clock_timing -type latency -verbose > ../reports/sta/${mse_str}/${pvt_str}/clock_latency
report_clock_timing -type skew -verbose > ../reports/sta/${mse_str}/${pvt_str}/clock_skew

report_si_bottleneck -cost_type delta_delay > ../reports/sta/${mse_str}/${pvt_str}/si_bottleneck_delta_delay
    • report_constraint -all_violators — lists all timing and DRC violations.
    • report_bottleneck — identifies cells that appear on the most critical paths.
    • report_qor — top-level summary: WNS, TNS, violating paths count.
    • report_clock_timing — clock latency, skew, and transition reports.
    • report_si_bottleneck — identifies nets with the largest crosstalk-induced delay impact.

📌 What Changes Across Sessions

Each PT session targets a specific PVT corner. The script structure (read netlist, annotate parasitics, source SDC, update timing, generate reports) stays the same. What changes between sessions is the matching pair of inputs:

  • Timing libraries (.db) — must match the PVT condition. Slow corners use SSG libraries (slow transistors, low voltage). Fast corners use FFG libraries (fast transistors, high voltage). The temperature in the library name must match the corner temperature.
  • SPEF file — must match the RC extraction condition. Slow corners use cworst/rcworst extraction (pessimistic parasitics that maximize delay). Fast corners use cbest/rcbest extraction (optimistic parasitics that minimize delay).

Using mismatched libraries and SPEFs (e.g., fast libraries with worst-case SPEF) produces physically meaningless results. Always verify the library PVT matches the SPEF extraction corner.

🧠 Knowledge Assessment

1. Why does each PVT corner use a different SPEF file?

  • The SPEF file contains the gate-level netlist which changes per corner.
  • Parasitic R and C values change with temperature and extraction methodology (cworst, rcworst, cbest, rcbest), so each corner needs its own extracted parasitics.
  • PrimeTime requires a separate SPEF for licensing reasons.
  • The SPEF file contains the SDC constraints which differ per corner.
Correct! Interconnect parasitics vary with temperature and extraction conditions. Using the wrong SPEF for a corner would give inaccurate wire delays.

2. What does -pba_mode exhaustive do in report_timing?

  • It disables timing analysis to save runtime.
  • It uses path-based analysis which considers path-specific derating for each timing path, giving more accurate results than graph-based analysis.
  • It limits the report to only 1 path per group.
  • It enables functional simulation mode.
Correct! Path-based analysis (PBA) exhaustive mode recomputes derating for each individual path rather than using a single worst-case derate, giving tighter and more accurate slack values.

3. Why is si_enable_analysis set to true?

  • It enables scan insertion for DFT.
  • It allows PrimeTime to read SystemVerilog files.
  • It enables signal integrity (crosstalk) analysis so PrimeTime can compute delay changes caused by coupling capacitance between adjacent wires.
  • It is required to read SPEF files.
Correct! With SI analysis enabled, PrimeTime uses the coupling capacitances from the SPEF to compute crosstalk-induced delay bumps on victim nets, which can cause additional timing violations.

4. What does timing_remove_clock_reconvergence_pessimism do?

  • It removes all clock constraints from the design.
  • It removes extra pessimism when the same clock reaches both launch and capture flip-flops through different paths (Clock Reconvergence Pessimism Removal).
  • It disables clock gating analysis.
  • It forces all clocks to have zero skew.
Correct! CRPR removes the artificial pessimism that occurs when OCV derating is applied differently to the common clock path segment shared by launch and capture. Without CRPR, slack would be overly pessimistic.
