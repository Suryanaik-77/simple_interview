INDEPENDENT WORK

You have an empty synthesis script at scripts/dc_syn.tcl. Your task is to write all the DC Shell commands needed to synthesize the iguana_soc open-source SoC design, then run it using make run.

Apply everything you learned in Testcase 1. The overall flow is the same — configure search paths, load libraries, read RTL, elaborate, apply constraints, compile, write outputs. However, this design is larger, uses SystemVerilog, and has six asynchronous clock domains. A few commands will have small differences that you will need to figure out.

No step-by-step instructions are provided. Use the design information, library paths, and hints on this page together with your Testcase 1 script as a reference.

📖 Design Information

iguana_soc is an open-source RISC-V SoC integrating a CVA6 application processor core, JTAG debug, USB, HyperBus, and serial-link interfaces. Unlike the tile design from Testcase 1, iguana_soc:

  • Is written in SystemVerilog (not plain Verilog)
  • Has six independent asynchronous clock domains
  • Contains three PSRAM macro instances with their own timing models

Input files provided:

  • inputs/iguana_soc_rtl.fl — Tcl filelist that sets $ver_files to the RTL source paths
  • inputs/iguana.sdc — timing constraints for all six clock domains

Clock domains defined in iguana.sdc:

Clock name Port Period Domain
clk_sysclk_i11.0 nsCore, peripherals
clk_jtgjtag_tck_i40.0 nsJTAG debug
clk_rtcrtc_i50.0 nsReal-time clock
clk_slislink_rcv_clk_i44.0 nsSerial link PHY
clk_usbusb_clk_i~20.8 nsUSB PHY
clk_hyp_rwdsihyper_rwds_i11.0 nsHyperBus RWDS
Note on asynchronous clocks: The SDC uses set_clock_groups -asynchronous to tell DC Shell not to analyze timing paths crossing between these domains. Those paths are handled by CDC synchronizers in RTL. Without this command DC Shell would try to meet impossible inter-domain timing and generate misleading violations.

💡 Hints

Hint 1: Reading the RTL for iguana_soc

The filelist inputs/iguana_soc_rtl.fl is a Tcl script that sets the variable $ver_files to the RTL source paths. Source it first, then pass that variable to analyze.

iguana_soc uses SystemVerilog constructs (interfaces, packages, logic, always_ff). Check the analyze command documentation for the format flag that enables SystemVerilog parsing — it was not needed in Testcase 1 where the design was plain Verilog.

Hint 2: Clock gating cell and set_dont_use

Apply the same set_dont_use strategy as Testcase 1 to block LVT cells and clock-tree cells. Use the same remove_from_collection pattern to re-enable CKLNQD8BWP40P140LVT for ICG insertion: 

set_dont_use [remove_from_collection [get_lib_cells {*/*CK* */*LVT*}] [get_lib_cells */CKLNQD8BWP40P140LVT]]

The set_clock_gating_style command and the CKLNQD8BWP40P140LVT ICG cell remain the same as Testcase 1 — the gating strategy does not change between designs.

Hint 3: Asynchronous clock domains

iguana_soc has six independent clock domains. The SDC file already contains set_clock_groups -asynchronous to prevent DC Shell from analyzing paths crossing between them. You do not need to add this yourself — just source ../inputs/iguana.sdc as you did with tile.sdc in Testcase 1.

After elaboration and before running compile_ultra, run check_timing to confirm all clock domains are recognized and constrained correctly.

🧠 Knowledge Assessment

1. iguana_soc uses set_clock_groups -asynchronous in its SDC. What does this tell DC Shell?

  • It disables timing analysis for all clocks in the design.
  • It sets the clock uncertainty to zero for asynchronous paths.
  • It tells DC Shell not to analyze timing paths that cross between the listed clock groups, since those paths are handled by CDC synchronizers in RTL.
  • It marks all clocks as generated clocks derived from a single master clock.
Correct! Paths crossing asynchronous clock boundaries are handled by dedicated CDC synchronizers in RTL. Without set_clock_groups -asynchronous, DC Shell would try to meet timing on those paths and generate misleading violations.

2. The analyze command for iguana_soc requires a different format flag than Testcase 1. What is it and why?

  • -format vhdl, because iguana_soc uses mixed Verilog/VHDL sources.
  • -format sverilog, because iguana_soc is written in SystemVerilog which has constructs (interfaces, packages, logic, always_ff) that the standard Verilog parser does not support.
  • -format db, because iguana_soc RTL is pre-compiled into a binary format.
  • -format verilog works for SystemVerilog too; no flag change is needed.
Correct! iguana_soc is written in SystemVerilog. Passing -format sverilog to analyze enables the SystemVerilog parser so constructs like interface, package, logic, and always_ff are recognized correctly.

3. Why are PSRAM macro .db files added to set_link_library but NOT to set_target_library?

  • DC Shell cannot read PSRAM .db files; they must be specified separately.
  • PSRAM macros are automatically included when set_search_path directories are configured.
  • set_target_library contains only cells DC Shell can map logic onto. PSRAM macros are fixed black boxes — DC Shell uses their timing models for analysis but cannot place logic inside them.
  • PSRAM macros are only needed for place-and-route, not synthesis timing analysis.
Correct! set_target_library is for cells DC Shell selects during technology mapping. PSRAM macros are hard macros — their internal logic is fixed. They only appear in set_link_library so DC Shell can check timing at their ports.

4. After compile_ultra -gate_clock finishes, what should you check first in the reports?

  • report_design, to confirm the correct top-level module was synthesized.
  • report_power, to verify clock gating reduced dynamic power.
  • report_qor, which shows worst negative slack (WNS), total negative slack (TNS), and number of violating paths — the primary indicators of timing closure.
  • check_design, to confirm there are no unconnected ports before checking timing.
Correct! report_qor is always the first report to check after compilation. WNS and TNS immediately tell you whether the design closed timing. If WNS is negative, you have violations to investigate in report_timing.
