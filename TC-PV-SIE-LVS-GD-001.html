🧠 Knowledge Assessment

1. Why must v2lvs use aes_cipher_top.fill.pg.vg instead of aes_cipher_top.pg.vg for this LVS flow?

  • The fill Verilog has better timing annotation
  • The fill Verilog includes DCAP and filler cell instances that are present in the layout GDS; without them the CDL is missing those cells and LVS reports thousands of unmatched transistors
  • v2lvs cannot parse the pre-fill Verilog format
  • The pre-fill Verilog does not include power/ground connections
Correct! DCAP/filler cells are inserted during chip finishing and appear in the GDS. Using the post-fill Verilog ensures the CDL includes those instances so LVS can match both sides.

2. Why is the PDK SPICE file (-s flag) needed in v2lvs?

  • To compile the rule deck
  • It provides SPICE subcircuit definitions for standard cells referenced in the Verilog
  • To set the technology node
  • v2lvs does not need the SPICE file
Correct! v2lvs needs the SPICE models to map Verilog module references to CDL subcircuits.

3. In the LVS runset, what is the difference between LAYOUT and SOURCE?

  • LAYOUT is the schematic; SOURCE is the GDS
  • LAYOUT is the GDS; SOURCE is the CDL/SPICE schematic
  • Both refer to the same GDS file
  • LAYOUT is the rule deck; SOURCE is the netlist
Correct! In Calibre LVS, LAYOUT is always the physical database (GDS) and SOURCE is always the schematic (CDL/SPICE).

4. What does VARIABLE POWER_NAME / VARIABLE GROUND_NAME specify in the LVS runset?

  • Power domains for multi-voltage designs
  • Net name aliases that the PDK rule deck uses to identify power and ground rails during layout extraction
  • IR drop constraints
  • Calibre license server power management
Correct! VARIABLE POWER_NAME and VARIABLE GROUND_NAME feed net name lists into the PDK rule deck so Calibre correctly identifies VDD/VSS supply rails including both upper- and lower-case variants.
