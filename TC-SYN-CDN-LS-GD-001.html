Problem Statement

GUIDED

You have an empty synthesis script at scripts/genus_syn.tcl. Your task is to fill it with all the Genus commands needed to synthesize the tile design from the OpenPiton processor, then run it inside Genus.

Follow each step below. Add the command(s) shown to genus_syn.tcl, read the explanation, and move to the next step. When all commands are written, source the script inside Genus and run make verify.

⚙ Synthesis Flow Overview

Genus synthesis runs in three broad stages. Every command in your script belongs to one of these:

  • Setup — load libraries, read RTL, enable clock gating, elaborate the design.
  • Constraints — source the SDC, apply set_dont_use restrictions, run design checks.
  • Synthesis & Outputs — syn_generic → syn_map → syn_opt, generate reports, write netlist and SDC.

    set_db library tells Genus which cell libraries to use for mapping. All paths go inside one Tcl list ({ }). This command loads two groups:

    • Standard cell libraries (TSMC 28 nm HPHP, SSG corner, −40°C) — three Vt flavors:
      • HVT (hvtssg…) — high threshold voltage, slower switching, very low leakage. Good default choice.
      • LVT (lvtssg…) — low threshold voltage, faster, but leaks more. Loaded here but disabled later with set_dont_use.
      • SVT (ssg…) — standard threshold voltage, the general-purpose cells Genus will primarily use.
    Corner chosen (SSG, −40°C): The slow-slow-ground, cold-temperature corner represents the worst-case setup timing scenario — cells are slowest and voltage is lowest. If synthesis closes timing here, it will close at all other operating conditions.

  • Read the Design

    set_db init_hdl_search_path {/efs/semicon_labs_pd/designs/tile/piton/design/include/}
source /efs/semicon_labs_pd/designs/tile/Filelist.tcl
read_hdl $RTL_SOURCE_FILES
    • set_db init_hdl_search_path — tells Genus where to look for Verilog header files (.h / .tmp.h). Several OpenPiton source files use `include directives that reference headers in this directory.
    • source /efs/semicon_labs_pd/designs/tile/Filelist.tcl — executes the Tcl filelist, which sets the variable $RTL_SOURCE_FILES to the full list of Verilog source paths.
    • read_hdl $RTL_SOURCE_FILES — reads and parses every Verilog file. Watch the log for parse errors. An error here means a file is missing or has a syntax problem that must be fixed before elaboration.

  • Enable Clock Gating

    set_db lp_insert_clock_gating true

    This attribute tells Genus to automatically insert Integrated Clock Gating (ICG) cells during synthesis. ICG cells block the clock from toggling flip-flops that are not changing state, which directly reduces dynamic power.

    Why before elaborate? Genus identifies gating candidates by analysing the design structure during elaboration. The attribute must be set before that step so the analysis is performed; setting it afterwards has no effect.

  • Elaborate the Design

    elaborate $design_name
write_db ../outputs/elaborate.db
report_qor > ../reports/report_qor_elab.rpt
    • elaborate $design_name — the top-level module name is stored in $design_name (set to tile at the top of the script). Genus connects all instantiated modules together, resolves parameter values, and builds the complete design hierarchy in memory. If any instantiated module is missing from the files you read, you will see an unresolved reference error here.
    • write_db ../outputs/elaborate.db — saves a checkpoint of the post-elaboration state. If synthesis fails later, you can reload this database with read_db and restart from elaboration rather than re-reading all RTL.
    • report_qor > ../reports/report_qor_elab.rpt — saves a pre-synthesis quality-of-results baseline. You can compare it with the post-synthesis QoR to measure how much the tool improved the design.

  • Run Design Checks

    set_db use_scan_seqs_for_non_dft false
check_design > ../reports/check_design.rpt
    • set_db use_scan_seqs_for_non_dft false — prevents Genus from treating non-DFT flip-flops as scan chain elements. Without this, Genus might try to insert scan test logic into registers that are not intended for testing.
    • check_design — scans for structural problems such as unconnected ports, combinational feedback loops, and multi-driven nets. Review the report file before proceeding.

  • Apply Timing Constraints and Restrict Cell Usage

    source ../inputs/tile.sdc
set_dont_use [get_lib_cells *LVT]
set_dont_use [get_lib_cells {*CKBD* *CKND* *CKMUX* *CKAN* *DEL *D18 *D20 *D24 *D32}]
set_db timing_report_time_unit ns
    • source ../inputs/tile.sdc — loads the timing constraints for the tile design. Key constraints defined here:
      • Clock period: 1.7 ns (about 588 MHz) on port clk
      • Input/output delays as fractions of the clock period
      • Max transition, max fanout, and load constraints
      • Path groups (r2r, i2o, i2r, r2o) to organise timing reports
    • set_dont_use [get_lib_cells *LVT] — blocks all LVT cells from being used during logic synthesis. LVT cells switch faster but have significantly higher leakage current. Excluding them keeps static power low. If a critical path cannot meet timing with HVT/SVT cells alone, only those specific gates would be allowed to use LVT.
    • set_dont_use [get_lib_cells {*CKBD* *CKND* *CKMUX* *CKAN* …}] — blocks clock buffer, clock inverter, clock multiplexer, and high drive-strength cells. These are reserved for the clock tree that will be built during place-and-route. Using them in the logic fabric would cause problems during clock tree synthesis.
    • set_db timing_report_time_unit ns — sets the unit for timing report values to nanoseconds, which matches the SDC constraint values and makes reports easier to read.

  • Run Synthesis

    check_timing_intent > ../reports/check_timing_intent_before_compile.rpt
syn_generic
syn_map

group_path -name reg2reg -from [all_registers -clock_pins] -to [all_registers -data_pins]
group_path -name in2out  -from [all_inputs]                -to [all_outputs]
group_path -name in2reg  -from [all_inputs]                -to [all_registers -data_pins]
group_path -name reg2out -from [all_registers -clock_pins] -to [all_outputs]
group_path -name mem2reg -from [get_pins -filter "is_clock_pin" -of_objects [get_cells -hierarchical -filter "is_hard_macro == true"]] -to [all_registers -data_pins]
group_path -name reg2mem -from [all_registers -clock_pins] -to [get_pins -filter "is_clock_pin == false" -of_objects [get_cells -hierarchical -filter "is_hard_macro == true"]]

syn_opt
check_timing_intent > ../reports/check_timing_intent_after_compile.rpt
    • syn_generic — converts the RTL into a technology-independent logic network using simple Boolean gates. No library cells are chosen yet. Clock gating cells are also identified and added to the netlist during this step.
    • syn_map — maps each generic gate to an actual standard cell from the loaded libraries, picking cells that best meet the timing constraints and area goals. This is the step where your design becomes a real gate-level netlist.
    • group_path commands — define named timing path groups (reg2reg, in2out, in2reg, reg2out, mem2reg, reg2mem) after syn_map but before syn_opt. This placement is intentional: the groups must be defined on the mapped netlist so Genus can use them to prioritize timing fixes during optimization.
    • syn_opt — performs incremental timing-driven optimization: swapping cells for faster or stronger variants, inserting buffers on long nets, and restructuring logic to fix any remaining setup violations.
    • check_timing_intent — re-runs the timing intent check after optimization to confirm all paths are still properly constrained and no new unconstrained paths were introduced.
    Runtime note: Synthesizing the tile design takes several hours. You will see progress messages in the log for each phase (syn_generic, syn_map, syn_opt). Monitor the log file at logs/genus_synthesis.log.

    📋 Expected check_timing_intent Output (after syn_opt)

    After syn_opt completes, the 8 unconstrained clock pin warnings should be gone. Eight warnings remain: 5 timing exceptions with no effect and 3 exceptions with invalid timing start-/endpoints.

    Why did the 8 sequential clock pin warnings disappear? The 8 sequential clock pins belonged to control latches whose outputs were not consumed by any downstream logic path. During syn_generic and syn_opt, Genus identifies sequential elements with no load on their data outputs and removes them as dead logic. Once those latches are eliminated from the netlist, their unconstrained clock pins no longer exist and the warnings are automatically cleared. This is the expected and correct behaviour — synthesis cleaned up unreachable state elements that the RTL carried but the synthesized circuit does not need.

  • Path Groups — What They Do

    The six group_path commands shown in the synthesis step above organise all timing paths into named categories. They are placed between syn_map and syn_opt so Genus can use them to prioritise fixing the most critical group during optimization.

    • reg2reg — register output to register input (the most common and usually most critical path type)
    • in2out — input port directly to output port (pure combinational paths)
    • in2reg — input port to a register data input
    • reg2out — register output to an output port
    • mem2reg — SRAM macro clock pin to register data pin (memory read paths)
    • reg2mem — register clock pin to SRAM macro data input (memory write paths)

  • Generate Reports

    report_qor                  > ../reports/report_qor.rpt
report_timing               > ../reports/report_timing.rpt
report_gates                > ../reports/report_gates.rpt
report_area                 > ../reports/report_area.rpt
report_timing_summary       > ../reports/report_timing_summary.rpt
report_clock_gating         > ../reports/report_clock_gating.rpt
    • report_qor — top-level summary: worst negative slack (WNS), total negative slack (TNS), number of violating paths, total area, and estimated power. This is the first report to check after synthesis.
    • report_timing — detailed timing paths. For each violating path, the report shows every gate, its delay contribution, and the required/arrival time at each pin. Use this to understand what is causing a violation.
    • report_gates — list of every standard cell instance and its drive strength. Useful for understanding which cells are used most.
    • report_area — area breakdown by module hierarchy. Identifies which blocks in the design consume the most silicon area.
    • report_timing_summary — a condensed per-path-group timing summary showing WNS and TNS for each group (reg2reg, in2reg, etc.).
    • report_clock_gating — shows how many ICG cells were inserted, which register groups they protect, and the estimated dynamic power savings.

  • Write Outputs and Exit

    write_db ../outputs/synthesis.db
write_hdl > ../outputs/$design_name.v

    • write_db ../outputs/synthesis.db — saves the complete Genus session (design, libraries, constraints, synthesis results) to a binary database. You can reload it later with read_db for re-reporting or further optimization without re-running synthesis.
    • write_hdl > ../outputs/$design_name.v — writes the gate-level netlist in Verilog (resolves to tile.v). This is the primary output of synthesis and the input handed off to place-and-route.
    • write_sdc > ../outputs/$design_name.sdc — writes the post-synthesis timing constraints (resolves to tile.sdc). Use this file (not inputs/tile.sdc) for place-and-route.     • exit — closes the Genus session and returns to the Linux shell.

🧠 Knowledge Assessment

1. What is the correct order of the three Genus synthesis commands?

  • syn_map → syn_generic → syn_opt
  • syn_generic → syn_map → syn_opt
  • syn_opt → syn_generic → syn_map
  • syn_generic → syn_opt → syn_map
Correct! syn_generic creates a technology-independent logic network; syn_map maps it to real library cells; syn_opt fixes remaining timing violations. The order is fixed and cannot be changed.

2. Why must set_db lp_insert_clock_gating true be set before elaborate?

  • Elaboration reads the library files which need clock gating enabled first.
  • Genus identifies clock gating opportunities during elaboration, so the setting must be active before that step.
  • Clock gating cells are inserted during read_hdl, before elaborate runs.
  • The setting has no effect if applied after the libraries are loaded.
Correct! Genus analyses the design for clock gating candidates during elaboration. Setting this attribute beforehand ensures those opportunities are captured when syn_map inserts ICG cells.

3. Why are LVT cells excluded with set_dont_use?

  • LVT cells are not available in the TSMC 28 nm library used here.
  • LVT cells are slower than HVT cells and hurt timing.
  • LVT cells have higher leakage current; excluding them reduces static power while the design still meets timing using HVT and SVT cells.
  • LVT cells can only be used during place-and-route, not synthesis.
Correct! LVT cells switch faster but leak significantly more power. Blocking them with set_dont_use keeps static power low. If a critical path cannot close timing without them, only those specific instances would be selectively allowed.

4. Why should outputs/$design_name.sdc be used for place-and-route instead of inputs/tile.sdc?

  • The original SDC is deleted by Genus after synthesis completes.
  • The output SDC is in a different format that place-and-route tools require.
  • Synthesis inserts clock gating cells with derived clocks not present in the original SDC; write_sdc captures these new clocks.
  • The output SDC is smaller and loads faster in Innovus.
Correct! When clock gating cells are inserted, Genus creates derived clocks for them. write_sdc exports an updated SDC that includes these new clocks, giving place-and-route the complete and accurate timing picture.
